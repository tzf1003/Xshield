# 真实 Jev 的录制

`quick.jsonl` 是快速模式的真实 Jev 录制。`lab --jev record` 把每次应答按请求摘要写进去，`lab --jev replay` 只从它答复。录制入库后，没有密钥的人也能重放同一批判定并核对报告。

**这个文件目前不存在，本目录只有这份说明。** 录制要用真实 Jev 和用户提供的密钥，并且要等判定路径上的在途改动都合入之后再做：指令文本和模型名都在摘要里，判定路径上任何一个改动都会让摘要变掉，现在录下的文件合入后就对不上了。在它存在之前，`--jev replay` 以退出码 2 退出并说明没有录制文件，`test_jev_relay.py` 里依赖它的用例跳过。

## 每行的格式

```json
{"digest": "<64 位小写十六进制>", "status": 200, "body": "<真实 Jev 的应答原文>"}
```

同一摘要出现多行时按录制的先后顺序返回，所以同一批请求在回放中得到同样的应答。文件里没有请求头、没有密钥，也没有请求体，只有摘要、状态码和应答。只有 2xx 的应答会写入：限流、鉴权失败和服务错误都计为失败、不写入，录制因此不完整，运行以退出码 2 结束。

## 摘要

摘要是请求体（规范化 JSON，键排序，无空白）的 SHA-256，去掉 `state.session.age_seconds`。那是挂钟时间，任何两次运行都不同，指令也不读它。请求体里有问题文本，所以判定指令一改，摘要就变；模型名也在摘要里。两者任何一个变了，旧录制就对不上，要重新录制，不要放宽未命中。

回放时摘要不在文件里的调用收到 UNKNOWN（两问都答不上来），计入“回放未命中率”。同一批请求的回放未命中率应为 0。不为 0 说明请求体里还有随时间变化的字段，要先找出来，再录制。

一次判定如果因为请求太大被分批（见 `docs/07` 7.5.1），每一批是一次调用，有自己的摘要，分别录制和回放。

## 录制步骤

谁来录：持有密钥的线程，在它自己的环境里执行。密钥只从环境变量读取，不写进命令行参数、文件、提交或聊天。验收线程的环境里没有这个变量，也不去抄它。

录制要带 PostgreSQL，这样“学到的”一列也在录制里。输出目录放到 `/mnt/project-files/acceptance/batch9/`，里面有录制文件和报告，都不含密钥。

```sh
export XSHIELD_JEV_ENDPOINT=<真实 Jev 的地址>
export XSHIELD_JEV_API_KEY=<密钥>
python3 scripts/measure_effectiveness.py lab --jev record --out /mnt/project-files/acceptance/batch9
```

- 退出码 2：录制不完整，有调用没得到 2xx 应答，或应答里带密钥。这次的录制不能入库，先查原因。
- 退出码 0 或 1：录制完整，门槛结果以报告为准。

一次完整的录制大约是 3500 次真实模型调用。每次重录都要用户知情，因为它花真实调用。

验收线程做回放和核对：

```sh
python3 scripts/measure_effectiveness.py lab --jev replay --out <另一个输出目录>
```

回放未命中率应为 0。报告的指标、门槛、计数、失败清单和置信度扫描都与录制时一致。两者一致后，把 `jev-recording.jsonl` 复制为 `quick.jsonl`，用一个单独的小 PR 入库，入库前过 `scripts/check_secrets.py`。

## 录制过期

回放未命中率本身是一个读数：网关发给模型的内容变了多少。不为了消掉未命中而放宽摘要。需要新的对照时重新录制。

## 为什么入库

录制是对真实模型的一次性记录，之后每次度量都不再需要密钥或流量，结果可以复现。文件里只有应答，不含密钥。摘要字段名不含 key、secret、token 或 password，`scripts/check_secrets.py` 不会把它当成密钥；提交前仍要跑一遍这个检查。
