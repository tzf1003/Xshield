# PR 交付清单

## 变更目标
关联的需求或问题，以及改动落在哪一块：判定路径（docs/01）、Jev 调用（docs/02）、站点配置和判定日志（docs/03）、控制台（docs/06、docs/07），还是文档和脚本。

## 实现边界
写明没有改变的部分：判定步骤、发给 Jev 的内容、站点配置字段是否变化。新增配置项、环境变量、表、crate 或依赖时，说明现有机制为什么不够用（AGENTS.md"做减法"），依赖还要说明原因和许可证。

## 安全与日志
会话凭证和口令不写入日志，也不发给 Jev（docs/02 第 2.4 节）。Jev 超时或答不上来时不默认放行。判定日志只用于排查，不作为授权依据。生产输入路径没有新增 unwrap、expect 或 panic。

## 测试与证据
列出实际执行的命令和结果，例如 cargo fmt --check、cargo clippy、cargo test、scripts/validate_library.py。没有执行的写明原因，例如缺少 PostgreSQL 或真实 Jev 密钥。格式检查通过不代表业务验证通过。

## 发布与回滚
数据库迁移是否向前兼容；站点配置变更是否先在观察模式运行（docs/04 第 4.2 节）；回滚方式，例如把站点配置还原到上一版本（docs/03 第 3.2 节）。
