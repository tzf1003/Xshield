# 23 剩余风险与待验证决策

## 23.1 不能靠调整措辞消除的边界

流程自洽不等于业务 ACL 正确；已认可的页面错误暴露管理动作时需要显式高危映射约束。完整凭证可复制，双 Cookie 绑定不是设备证明。前端被冻结，不能保证心跳永续。看不到的源站撤权不能立即推断。源站副作用与 WAF 日志不构成跨系统原子事务。

这些边界不否定用户选择的严格流程规则；它们必须作为 coverage/assurance 单独显示，避免销售和后台把 FLOW_ALLOWED 写成 BUSINESS_AUTHZ_PROVEN。

## 23.2 待验证列表

| 决策 | 首版方向 | 完成条件 |
|---|---|---|
| Pingora 请求/响应等待点 | Rust 数据面首选 | 验证无提前转发、取消和缓冲限制；不满足则替换适配层 |
| 基础规则引擎 | 复用既有受测引擎 | 许可证、性能、检测覆盖和故障策略确认 |
| TLS 后端 | 受支持且测试通过的构建 | 不将实验性选项当默认稳定能力 |
| Jev/OpenJev | 可替换，先影子测试 | 任务级误放、误拒、延迟和成本可接受 |
| UI 动态状态 | 编译映射 + 受验证响应 | 仅客户端可控状态不升级成可信证据 |
| 全量原文保留 | 加密库、秘密排除、24h 初始值 | 站点明确范围、体积、访问与期限 |
| 高危审计耐久 | 可要求 remote_durable | 故障域与延迟预算通过测试 |
| 热资格缓存 | 首版使用事务状态 | 撤销语义明确后再引入缓存 |
| 多区域 | 首版不强制 | 主权威区/分区/恢复方案与实测 |
| HTTP3/业务流式 | 后续独立适配 | 每消息/字节释放前检查的覆盖定义 |

## 23.3 不用的捷径

不以模型高分替代绑定；不全局关闭 CSP；不让无效封包回退明文；不以 source response=200 自动授予权限；不把日志原文直接喂给可操作生产的 Agent；不把实时 stdout 当耐久证据；不声称 hash chain 无条件防删；不把 JSON 语法校验当上线验收。

## 23.4 决策更新

待验证事项由 owner、实验记录、ADR、通过标准和结论管理。产品名、Rust 主语言、无业务 SDK、无来源拒绝是已确定约束，不反复提为待选。变更这些约束需明确新的产品决定。
# 已确定决策

Agent 允许直接应用，但必须拥有明确 tenant/site scope 与 `site.config.apply_direct`；直接应用写入绑定修订与配置摘要的 `direct_apply` 审批记录并写终态审计，且不留下阻塞其他站点的过期审批标记。API Key 使用独立 Header、一次性明文展示和专用 HMAC 指纹密钥；不能扩大权限、读取秘密或绕过确定性校验。
