# 00 产品定位与核心规则

版本 4.0｜2026-11-01｜状态：设计基线。本组文档（00–07）取代 v3 的 00–32 号文档；代码已按本组文档实现，v3 机制的去留见 [05 删减清单](05-v3-removal.md)。

## 0.1 一句话

Xshield 是部署在源站前面的反向代理 WAF。它记住每个登录会话"正常走过的路"：从哪个入口进来，源站给它看过哪些数据。请求里一旦出现这条路上没出现过的东西，网关就把会话上下文和这次请求一起交给 Jev 模型判断，这是正常操作，还是越权访问或攻击。Jev 判为不正常，请求就在到达源站之前被拦截。

## 0.2 要解决的两类问题

1. **越权访问（IDOR）**。后端没做对象级鉴权时，改一下 URL 或参数里的 ID 就能读写别人的数据。
2. **注入类攻击**（SQL 注入、命令执行、路径穿越等）。规则型 WAF 依赖特征和正则，换一种编码或写法就可能绕过。Xshield 不维护规则库，把请求内容交给模型判断。

两类问题走同一条判定路径，用同一次 Jev 调用。

## 0.3 核心规则：只接受正常访问路径

例子：医生 A 能看患者 A、B、C，医生 B 只能看患者 D。

- 医生 A 登录，从首页进入"我的患者"列表，源站返回了 A、B、C。随后他打开患者 B 的详情。B 在这个会话里出现过，放行。
- 医生 A 把地址里的患者改成 D。D 从未在他的会话里出现过，交给 Jev，Jev 判为越权，拦截。后端有没有做鉴权不影响结果。
- 医生 A 换一个浏览器登录，**直接**输入患者 B 的详情地址。他在源站确实有这个权限，但新会话里没见过 B，同样拦截。

Xshield 判断的不是"这个账号在源站有没有权限"，而是"这次访问有没有一条正常的路径"。这比源站权限更严：有权限但没有走正常路径，也会被拒绝。这是有意的产品选择，换来的是不需要知道源站的权限模型。

同一条规则也适用于功能。站点可以在功能表里把某些接口标为管理功能（`tier: admin`，可靠性高）。非管理员会话调用它时，即使请求的对象是它见过的，也算尝试越权：这些接口不在普通用户的正常路径上，交给 Jev 判定，并要求 Jev 拒绝。判断会话是不是管理员，要求站点声明角色身份位置。没有声明的站点上，所有会话都不是管理员，管理档条目会拦住包括真正管理员在内的所有人，所以要先声明角色身份位置，再标管理档。站点还可以打开“未知功能送 Jev 判定”，让功能表里没有的接口也经过判定，判断的依据是接口名和路径本身。

## 0.4 入口

上下文需要起点。管理员在后台把一部分接口登记为**入口**，访问入口不要求会话里事先有上下文：

- 登录、首页、"我的患者"这类起始列表。
- 分享和邀请的兑换接口。医生 A 分享患者 A 的数据，源站生成一个分享码；接收者打开 `/share/{code}`，源站校验分享码后返回患者 A 的数据。这些数据随即进入接收者的会话上下文，他之后查看患者 A 的详情就是正常访问。

分享码由源站自己生成和校验，Xshield 不签发、不保存分享凭证，只把兑换接口当作入口。入口上的请求同样要经过攻击判定，也不能借入口去指定别人的对象（例如在"我的患者"接口上加 `?doctor=B`），见 [01.4](01-request-flow.md#14-判定步骤)。

## 0.5 设计原则

- **做减法**。判定只依赖"会话上下文 + 当前请求 + Jev"。不再逐个接口配置资源字段，不再维护资格账本和界面动作映射，不再需要浏览器探针。
- **单管理员**。一个管理员就能修改配置并立即生效，不设第二审批人。
- **配置最少**。一个站点只填源站地址、会话凭证的位置和入口列表，其余都有默认值，见 [03.2](03-admin-config-audit.md#32-站点配置)。
- **先观察后拦截**。新站点默认是观察模式：照常判定和记录，但不拦截。管理员看过判定日志、确认误判可以接受之后，再切到拦截模式。

## 0.6 不承诺的事

- Jev 是模型，会误判。观察模式和判定日志用来发现、压低误判，不能消除误判。
- 源站在正常界面里把不该给的数据给了用户，这些数据会进入上下文，之后的访问会被放行。站点标注了档位（[07.4.7](07-console-architecture.md#747-档位在判定中的使用)）后，只由公共搜索展示过的对象，在不接受公共来源的写操作上不再放行，交 Jev 判越权。Xshield 拦的是"跳转"出来的访问，不修复源站自身的授权错误。
- 偷到完整会话凭证的人，拿到的是这个会话的上下文。Xshield 不解决凭证盗用。
- 每个需要判定的请求多一次模型调用，延迟和费用是主要代价，见 [02.5](02-jev.md#25-延迟费用与限流)。
- 发给 Jev 的请求值可能包含业务数据。医疗等受监管行业上线前要确认合规，必要时改用私有部署的模型，见 [02.6](02-jev.md#26-数据外发)。
- 功能级的判断依赖站点标注。没有标为管理功能的管理接口，只能靠“未知功能送 Jev 判定”兜底，而模型对名字普通的管理接口可能认不出来。
- 功能级的判断需要角色身份位置（见 [07.9.18](07-console-architecture.md#7918-功能表) 的已知局限）。没有声明角色的站点上，所有会话都不是管理员，管理档条目会拦住真正的管理员；先声明角色身份位置，再标管理档。
