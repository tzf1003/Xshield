# 30 控制台重构方案与实施记录

本章记录 2026-10 对 `web/console` 的整体重构：为什么重构、目标、信息架构、技术选型、安全不变量的落点、分阶段交付和仍未完成的部分。页面行为的细节以 [15](15-console-and-api.md) 和 `web/console/README.md` 为准，接口契约以 [29](29-api-endpoint-catalog.md) 为准；本章只保存决策和验收口径，不复述它们。

## 30.1 起因与诊断

重构前的控制台能完成每个后端闭环，但操作者很难用，原因是结构而不是配色：

- 页面按 API 端点拆分，每个页面以“粘贴一个 `req_…`/`mdl_…`/`grant_…` UUIDv7”开始，无法浏览“最近一小时被拒绝的请求”。
- 写操作把后端机制交给用户：幂等键是表单字段，重试要勾选“恢复原访问申请”，多数页面常驻 2–4 段机制说明。
- 导航有 17 个一级入口，“模型调用列表/详情”“资格/身份绑定”各占一项，API Key 页面存在但没有入口。
- 约 1,800 行手写 CSS、103 个硬编码颜色、重复的 sidebar/topbar 规则；antd 6 已安装却没有任何页面使用。
- `App.tsx` 1,391 行、37 个 `useState`，11 个请求通道靠手工计数防晚到响应；移动端有大块空白和横向溢出。

值得保留的是 `api.ts` 中严格的响应解码器、范围校验、晚到响应隔离和“结果未知只能原样重试”的语义，它们被整体迁入新数据层。

## 30.2 目标场景

| 场景 | 重构前 | 目标 |
|---|---|---|
| 定位一条被拒请求的原因 | 选菜单、从别处取得 ID、粘贴、查询、切页签 | 打开请求流，筛选“拒绝”，点一行；不需要 ID |
| 接入新站点到 observe 生效 | 10 个分类页分别填写，没有引导和汇总校验 | 向导：基本信息 → 上游与监听 → 入口与模式 → 首批路由 → 校验与保存 |
| 申请并下载证据原文 | 在 3 个页面间手抄 case/artifact/access ID，自己填写幂等键 | 在案件或请求详情里申请；审批人在审批中心处理；框架生成幂等键并在需要时就地 step-up |
| 状态表达 | 每个页面各写一套，常只有文字或英文枚举 | 判定、应用状态、健康、索引完整性各有固定的颜色、图标和中文文案 |
| 视觉与适配 | 只有浅色，移动端溢出 | 浅色/深色/跟随系统与紧凑密度；1280px 与 390px 都没有横向页面滚动；axe 无 critical/serious |

## 30.3 信息架构（已实现）

侧栏按任务分组，按服务端会话角色隐藏无权入口（隐藏不替代授权，每个接口仍由服务端独立校验）：

| 分组 | 入口 |
|---|---|
| 工作台 | 概览 |
| 站点 | 受保护站点（列表、新建向导、站点工作区）；非 SystemAdmin 的 Observer 与 PolicyAuthor/PolicyApprover/ReleaseOperator 另有当前会话站点的“站点状态/站点发布” |
| 流量与调查 | 请求调查（请求流与请求详情）、结构化检索、身份与资格（资格与身份绑定合并为一页两个页签）、模型调用、Agent 运行 |
| 案件与审批 | 案件工作台（证据、访问申请、保留锁、导出、分析任务都在案件详情内）、审批中心（证据原文、调查导出、策略修订三类待办合并） |
| 运维与治理 | 运行状态（任务）、审计发布状态、校准报告、API Key、权限中心 |

顶栏常驻：⌘K/Ctrl+K 跳转（按前缀识别 `req_`/`mdl_`/`agt_`/`grant_`/`auth_`/`calr_`/`case_`/`access_`/`export_`/`job_`/`artifact_`/`ev_` 与 32 位 trace，也可搜页面）、范围徽章、step-up 状态与剩余时间、待确认操作托盘、主题与用户菜单。原 URL 全部保留或重定向（例如 `/evidence/access|holds|exports` 进入案件/审批中心，`/investigation/bindings` 与 `/investigation/models/lookup` 进入合并后的页面）。

## 30.4 技术选型

| 领域 | 选择 | 理由 |
|---|---|---|
| 组件 | antd 6 + 一层领域组件（判定徽标、原因码、ID 芯片、时间范围选择器、完整性提示、状态药丸） | 已是依赖（MIT）；中文本地化、CSP nonce、深色算法、虚拟滚动表格现成 |
| 主题 | 单一 token 源同时生成 antd 主题和 CSS 变量文件；浅色/深色/系统与紧凑密度；`style.css` 不再含硬编码颜色 | 消除层叠覆盖，深色靠切换算法 |
| 路由 | TanStack Router 代码式路由树，按路由拆包 | 类型化参数、嵌套布局、旧路径可重定向 |
| 数据 | TanStack Query + 受保护的数据层 | 晚到响应隔离从“每处手写”变成“框架保证” |
| 写操作 | `useGuardedMutation` + 内存中的 `PendingOperationStore` | 幂等键对用户不可见，结果未知统一进托盘 |
| 质量 | Biome（lint + format），不依赖 TypeScript 编译器 API | 避开 TypeScript 7 与 typescript-eslint 的兼容风险 |
| 字体 | `@fontsource/ibm-plex-sans`、`@fontsource/jetbrains-mono`（OFL-1.1，自托管） | 控制台 CSP 不允许外部字体主机 |

新增依赖与许可证：`@tanstack/react-router`、`@tanstack/react-query`（MIT）、`@biomejs/biome`（MIT/Apache-2.0）、`@axe-core/playwright`（MPL-2.0，仅开发）。版本锁定到小版本，每季度统一升级并跑全量回归。

## 30.5 安全不变量的落点

这些是产品要求，新架构中由框架层而不是各页面保证，并有回归测试：

| 不变量 | 落点 |
|---|---|
| 会话与敏感数据只在内存；401、15 分钟闲置、离页或退出时清空 | `SessionProvider`：会话代际（epoch）递增、查询缓存与待确认登记一并清空；只有主题/密度偏好使用 localStorage |
| 每个响应校验 tenant/site，晚到响应不能回填 | 受保护查询把 epoch 放入 query key、透传 AbortSignal、逐响应核对范围，不符则全局断开 |
| 写操作冻结路径、幂等键和正文；结果未知只能原样重试 | `useGuardedMutation` + `PendingOperationStore`；重试被 step-up 拒绝时仍保持“未知”并保留离页警告 |
| 读取都会写管理审计，不自动轮询 | Query 默认 `retry: 0`、关闭窗口聚焦/重连刷新；工作台只在打开页面和显式刷新时读取 |
| 原文读取与导出下载需要两分钟内的 MFA step-up 且仍需独立审批 | 服务端要求 step-up 时就地完成再认证，再续跑同一份冻结请求 |
| 错误只显示安全文案、稳定码和管理请求 ID | 统一错误状态组件；各稳定码有中文解释和下一步建议，扫描后端源码的测试保证新码不会漏映射 |

## 30.8 已知缺口与风险

- 浏览器测试里的控制 API mock 用 25 毫秒的中止窗口区分 StrictMode 的重复读取和真实读取；窗口放长会让“真实刷新紧接着被下一次点击中止”的用例失败，放短在慢速共享机器上偶尔漏判。没有一个对两边都成立的值，所以 CI 允许一次重试（重试通过会被报告为 flaky），根治需要让这类用例不依赖时间窗口。
- API Key 列表接口不返回 scopes，只有本会话新建的 Key 能显示自己的范围，轮换时需要重新选择；创建在服务端不是幂等的，未知结果后重试可能签发第二把 Key（页面如实说明，由操作者核对列表）。
- 工作台与任务页没有“本会话启动的任务”列表（案件工作区不保存它）；任务只能按 ID 查询。

- 站点列表需要 SystemAdmin，因此只有 PolicyApprover 角色的用户在审批中心看不到策略来源；`reauth/start` 需要 Reader，仅有 Approver 角色的用户无法发起 step-up。
- 列表响应不含申请理由；理由在选中行后才读取。导出详情没有 `as_of`。
- 控制台里有两套并行的判定/ID/时间组件（站点侧与调查侧），原因码字典在 14 个码上重叠，需要在后续合并。
- 冻结的写请求只存在内存，刷新后消失（页面会如实说明）。
- step-up 在独立弹窗里完成 OIDC 再认证，弹窗以空白页打开（为了在点击事件内同步打开，避免被拦截）后再导航到身份提供方，因此保留 `window.opener`；一个被攻破的身份提供方页面理论上可以导航控制台标签页。弹窗只通过同源 BroadcastChannel 回传一条不含数据的提示，打开者会重新读取服务端会话作为唯一证明，所以它不能伪造再认证；若部署启用 `Cross-Origin-Opener-Policy: same-origin`，弹窗与打开者的句柄会被切断，需要改用“我已完成，重新检查”。
- 构建在 CSP 下依赖部署模板为 `xshield-csp-nonce` 注入 nonce 并允许 antd 的运行时样式，这一点在重构前就存在，已写入控制台 README。
- 本机无法拉取 Docker 镜像，Keycloak/OIDC 真登录、ClickHouse 集成和容器构建没有在本章的验证中执行。
