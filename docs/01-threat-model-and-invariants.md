# 01 威胁模型与安全不变量

## 1.1 信任边界

客户端可操纵 JS、DOM、Cookie、自有 JWT、代理重放、用户生成内容和调用栈。源站是业务内容来源，但源站可能存在越权、错误页面暴露、回显与解析缺陷；“来源于源站”不等于“业务权限正确”。模型输入包含攻击者文本，输出存在误差。控制台操作者也按最小权限分离，不允许普通调查员读取所有原始凭证或发布规则。

可信根限定为：批准的站点配置、经验证的业务认证关系、经批准的入口与操作映射、网关实际观察的报文字节，以及持久提交的资格状态。将内容来源、业务权威性与密码学完整性作为三个不同字段保存。

## 1.2 威胁与控制

| 威胁 | 主要控制 | 残余边界 |
|---|---|---|
| A 的 WAF Cookie + B 的业务凭证 | 每请求认证组合绑定 | 整套 A 凭证复制不是串用 |
| 看评论得到 ID 后调用高权限接口 | 页面动作 + operation + target + fields 精确资格 | 正常认可流程错误提供该动作需额外策略 |
| 修改列表主体，污染资格账本 | 先验证资格来源请求及范围，再提取指定响应字段 | 不能信任任意 200 |
| 提交良性明文镜像、转发恶意密文 | 以实际接管封包得到的冻结参数重建源站请求 | 不可适配则显式不可见 |
| 诱导加密回退 | 站点服务端模式、异常类别分离 | 兼容路径仍有声明的覆盖缺口 |
| 修改 UI 遥测/提示注入 | 遥测不直接发行资格；固定候选和规则 | 语义识别本身必须评估 |
| 日志中的 XSS、SQL 注入、Agent 越权 | 日志按数据渲染；参数化查询；只读调查工具 | 证据系统成为高价值目标 |
| 删除、替换或漏记证据 | 持久日志、签名段、独立锚点、完整性清单 | 被控制的生产者在记录前伪造无法仅靠哈希识别 |
| 请求洪峰耗尽 GPU/磁盘 | 有界队列、预算、配额、严格故障策略 | 完整审计与可用性存在成本取舍 |

## 1.3 MUST 不变量

INV-01：Cookie 新建只产生匿名空账本，不自动产生认证或业务资格。

INV-02：每次请求用源站实际生效的认证方式匹配绑定。冲突的认证组合不能由不同层各自挑选。

INV-03：只有认可的认证转换能换绑。账号、租户或权限上下文变化不得继承旧操作资格。

INV-04：资格至少限定认证绑定、代际、资源类型、资源引用、operation、字段/视图、范围、来源、有效期。

INV-05：缺少认可 UI 操作来源时，强制端点拒绝；未发现不等于已证明恶意。

INV-06：观察到 ID、JS 公共包中的按钮、用户生成内容、任意成功响应不能直接发行资格。

INV-07：根入口必须显式批准；资格发行链不能从一次被拒绝或不受认可的访问开始。

INV-08：安全判定使用的业务参数与向源站重建的参数一致，后续插件不能替换目标。

INV-09：请求和响应可见性分别标注，截断、未解密、未验证不得标记 complete。

INV-10：Jev 只能在服务端构造的有限候选中提供信号，不直接写账本或覆盖硬拒绝。

INV-11：资格提交使用原请求身份快照；旧响应不能污染新账号，也不能复活已撤销资格。

INV-12：分享/登录/公开入口不是全路径免检，后续数据仍有视图与操作边界。

INV-13：日志和证据记录与业务准入分离；普通日志故障不静默跳过认证，严格审计故障不静默丢记录后继续高危执行。

INV-14：硬规则 confidence=null；没有执行的阶段记录 skipped/cancelled，而非伪造通过与置信度。

INV-15：安全审计事件不受 tracing 采样影响；证据缺失、删除和不可用均有显式状态。

INV-16：保密、脱敏、完整性和耐久性是不同维度，不能用“加密了”替代访问控制与完整性验证。

INV-17：调查、导出、解密、回放、策略发布本身必须被审计。

INV-18：回放默认无网络和业务副作用；源站执行结果未知时不自动重试非幂等操作。

INV-19：第三方库、AI 产出和插件不因写成 Rust 就自动可信；解析差异、依赖漏洞与逻辑缺陷仍须测试。

INV-20：所有性能数值、配额、阈值均为设计起点；通过真实负载与攻击矩阵后方能作为产品承诺。

## 1.4 安全评审方法

每次新端点、新来源、新插件同时回答：输入来自哪里、攻击者能修改什么、谁发资格、拒绝发生在哪个副作用之前、如何退回安全状态、日志是否能证明当时的依据。测试将信任边界当作断言，而非仅验证 HTTP 成功码。[S01][S02][S09]
