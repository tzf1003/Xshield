# 01 请求判定流程

## 1.1 组件

| 组件 | 职责 |
|---|---|
| 网关（`xshield-gateway`） | 反向代理；识别会话，维护会话上下文，调用 Jev，执行放行或拦截 |
| Jev | 外部模型判定服务，经 Vercel AI Gateway 调用，见 [02](02-jev.md) |
| 控制台（`xshield-control` + `web/console`） | 管理员修改站点配置，按请求 ID 追溯判定过程和 Jev 上下文，见 [06](06-console-ui.md)、[07](07-console-architecture.md) |
| PostgreSQL | 站点配置、配置历史、判定日志 |

网关直接看得到源站的每个响应，所以不需要浏览器探针来告诉它用户看到了什么。网关从 PostgreSQL 读取站点配置，配置变更后自动重新加载，不再需要控制面向网关推送签名快照。

## 1.2 会话与上下文

**会话**由源站自己的登录凭证确定。站点配置写明凭证在哪个 Cookie 或请求头里（例如 `SESSIONID` 或 `Authorization`）。网关用密钥对凭证值做哈希，作为会话键，不保存凭证原文。凭证变了（重新登录、换账号）就是一个新会话，上下文从空开始。会话键同时带上站点名：同一个凭证在两个站点上是两个会话，各自学习，一个站点学到的值不影响另一个站点。没有凭证的入口请求，其上下文同样按站点和客户端地址区分。

网关只为源站认过的凭证保存会话：源站对带这个凭证的请求答了 2xx，登录响应下发了它（下面的登录跳转和 JSON 登录），或者带它的请求被转发后源站作了应答并且请求里有值需要记住。在此之前，带这个凭证的请求按“空会话”判定（没有已见值，也没有放行缓存），不在网关里留下任何记录，需要问 Jev 时占用的是来源 IP 的额度（[02](02-jev.md) 2.5）。这样随手编造的凭证不能把真实会话挤出上限为 2 万的会话表，也不能各自拿到一份 Jev 额度。

每个会话的**上下文**包含三部分：

- **已见值**。源站返回给这个会话的成功响应里出现过的值。网关解析响应，取出其中所有字符串和数字标量（患者 ID、订单号等），用密钥哈希后保存，并记下每个值出现时的字段名和来源请求（例如"`id`，来自 `GET /api/patients`"）。不需要配置哪个字段是 ID。网关还记下每个请求自己发出、且此前未见过的值；源站之后在响应里回显这些值时，它们不计为已见。JSON 凭证站点的登录响应值，在会话建立时按 [1.7](#17-网关对请求和响应的处理边界) 的登录规则记入。
- **近期访问记录**。最近若干次请求的方法、路径和状态码，不含请求值。
- **经过的入口**。会话访问过哪些入口，以及第一次访问的时间。
- **身份**（可选）。站点在对象表里把某个响应位置标为身份（`user`、`org` 或 `role`，即“本会话的用户、机构、角色”）时，网关从该位置的成功响应里记下会话的用户和机构（只存键控哈希）与角色（标签）。每次身份响应都会更新它。判定记录的 `trace.session.identity` 带上这些标签，供学习按用户统计；身份暂不参与放行与拦截。没有身份位置的站点不记身份，判定与日志与之前相同（[07.9.15](07-console-architecture.md#7915-对象表的身份位置w1)）。身份还用于属性越权告警：响应里有不属于本会话的用户类对象，同时带手机号、邮箱或身份证号时，只在 `trace.response.exposure` 记一条告警，不影响放行与拦截（[07.9.17](07-console-architecture.md#7917-属性越权告警w6)）。

响应解析范围：JSON 响应（`application/json` 以及 `application/vnd.api+json` 这类 `application/…+json` 类型，请求体同此）取全部标量；HTML 响应取链接（`href`、`src`、`action`）里的路径段和查询参数值，以及表单字段的值。其他类型（二进制、应用层加密报文）不解析，相关的后续请求都会交给 Jev。单个响应超过 1 MiB 时不解析，判定日志里注明。

默认上限（固定在代码里，不进配置）：每个会话最多 5000 个已见值、每个值最多记 3 处来源、50 条访问记录；会话 24 小时无活动即过期；超出上限时淘汰最旧的记录。

首版上下文存放在网关进程内存里，适用于单实例部署。需要多实例时改为共享存储（PostgreSQL），读写接口不变。网关重启会丢失上下文，用户需要从入口重新进入，这与"只接受正常路径"的规则一致。

## 1.3 请求值

网关把一个请求拆成若干**请求值**：路径中的每一段、每个查询参数值、表单字段值和 JSON 请求体里的每个标量。同一个键重复出现时，每次出现的值各算一个请求值：源站可能取第一个，网关不能只看最后一个。会话凭证本身不算请求值。

每个请求值标注：

- 位置（例如"路径第 3 段"、"查询参数 `doctor`"、"JSON 字段 `patient.id`"）；
- **是否已见**，以及已见时的来源（字段名和来源请求）。

**快速放行的特异性要求**：值必须曾以类似标识的字段出现过才算已见：字段名是 `id`、`uuid`、`key`、`ref`、`link`，或以 `id`、`no`、`num`、`code`、`ref` 结尾。只以名称、文本或备注等字段出现过的值，不论多长都不算。较短的值（例如 `7`）还须由同一类对象的接口展示过，因为它很容易在别的字段里碰巧出现过（患者 8 和年龄 8）。只以 `age` 出现过的 `8` 不算，交给 Jev。

**类别**：较短的值还要看它被当作哪类对象（`/api/doctors/7/files/9` 里的 `9` 是文件，不是医生）。路径段取它前面最近的路由词；查询、表单或 JSON 的键有名字的，取键名（`?doctor=` 是医生）；没有名字的键（裸 `id`、`ids`，或顶层数组里的值）取路径末尾最近的路由词，即路径所指的对象。嵌套在具名对象里的裸 `id` 取对象名：`{"doc":{"id":5}}` 的 `doc.id` 装的是文档，与 `?doc=5` 一致。展示侧的裸 `id` 取父对象名，没有父对象的取返回它的接口路径末尾最近的路由词，即那个接口所指的对象；`search` 之类的动作词不算路由词，所以 `GET /rest/products/search` 返回的裸 `id` 是商品。字段类别可以用 `advanced.field_kinds` 覆盖（见 [07.6](07-console-architecture.md#76-站点级判定参数advanced)）。

**惰性值**：不可能是对象引用、本身也构不成注入载荷的值不触发判定，也不影响快速放行：
- 路径段和查询、表单、JSON 里的值，只由 1–40 个小写字母、`_`、`-` 组成并以字母开头，且所在字段名不像标识、也不含 `user`、`name`、`owner`、`account`、`email`、`doctor`、`patient`、`member`、`login`、`uid`（例如 `/api/patients` 里的 `api`、`patients`，`sort=asc`）；
- 路径里不是最后一段的段，只由 1–32 个字母（大小写都算）、`_`、`-` 组成、以字母开头的，是路由名（`/api/BasketItems/7` 里的 `api`、`BasketItems`）。最后一段可能是对象名（`/users/Alice`），仍按上一条，只有小写的才算；
- 分页字段（`page`、`pagesize`、`size`、`limit`、`offset`、`perpage`、`count`、`skip`、`take`、`index`）下不超过 6 位的数字。

**已知缺口**：按用户名等纯小写字母标识访问的接口（`/users/alice`），如果字段名里没有上面的提示词，`alice` 会被当作惰性值，越权引用不会被发现。这类站点需要等"按站点学习路由词"的改进（路由词 = 在多个会话的同一路径位置反复出现的段），首版不做。

## 1.4 判定步骤

对每个请求依次执行：

1. **跳过**。路径命中站点的 `bypass` 列表（静态资源等）：直接转发，不判定，只写一条简记录（请求行、状态码、耗时、命中的模式），保证每个请求都能按请求 ID 查到。
2. **识别会话**。没有会话凭证的请求只能访问入口；访问其他路径直接返回 401。
3. **拆出请求值**，按 [1.3](#13-请求值) 标注。
4. **快速放行**。请求没有任何请求值，或者全部请求值都已见且满足上面的特异性要求：放行，不调用 Jev。这些值都是源站之前亲自交给这个会话的，既不是越权引用，也不是攻击者构造的文本。

   站点配置了档位（[07.4.7](07-console-architecture.md#747-档位在判定中的使用)）时，“已见”要按档位核验。搜索、列表这类公共档的响应，任何登录会话都会收到，它们给出的值不证明会话有权操作对应的对象。收紧条件同时满足时，这类值被判为**尝试越权**：请求位置不接受公共来源（`accepts_public: false`，可靠性高），并且值的每个来源都是可靠性高的公共档响应。尝试越权的请求不快速放行，交 Jev，并在 `state` 里带上 `"attempt": "over_privilege"`，指令要求 Jev 对这个值答 DENY。自身档的来源不单独核验，只用来排除收紧；管理档的来源只对管理员会话算正证（依赖会话身份）。没有档位的站点按上面的规则判，与之前一致。
5. **查缓存**。同一会话、同样的方法、路径和请求值，且会话是否为管理员不变，在缓存时长内（默认 10 分钟，站点可用 `advanced.allow_cache_minutes` 调整，0 表示不缓存）被 Jev 判为放行过：直接放行，判定日志记下复用的是哪次 Jev 放行。只缓存放行结论，因为会话的证明只会增加，放行结论不会因此失效；管理员角色变化是例外，它会让管理档的证明失效，所以缓存按管理员身份分开。拒绝结论可能在用户浏览列表之后变成放行，所以不缓存。尝试越权的请求同样不查缓存，它每次都交给 Jev。 请求值没有读全的请求（超过值数或深度上限、请求体读不懂）不查缓存，放行结果也不写入缓存：缓存键只覆盖读到的值，没读到的部分每次都要交给 Jev。
6. **调用 Jev**。其余请求连同上下文交给 Jev，一次调用回答两个问题：这次访问有没有正常路径依据，请求内容是不是攻击。请求是否命中入口作为事实一并告诉 Jev。入口请求里的未见值，如果是入口本身需要的输入（登录表单、分享码、搜索关键字），不构成越权；如果是在指定别人的对象（例如在"我的患者"接口上带 `?doctor=B`），仍判为越权。详见 [02](02-jev.md)。请求值太多、一份 `state` 放不下时，值分成几批并行调用，任一批判拒即拒绝（[02.5](02-jev.md#25-延迟费用与限流)）。
7. **执行**。两个问题都通过：转发源站。任一判为拒绝：返回 403，不转发。超出调用限额的请求返回 429（`rate_limited`），不转发，不论 `on_jev_unavailable` 如何设置。分批后仍有单个值放不进 8 KiB，或没核验的非输入值装不进 16 批的请求（正常不会出现）返回 403，不转发，同样不论 `on_jev_unavailable`。超过 16 批的请求只送前 16 批，没送出的值记入判定记录的 `left_out`，结论照常定；全部放行则放行，但这次放行不写进放行缓存（[02](02-jev.md#25-延迟费用与限流)）。Jev 超时、出错或答不上来（UNKNOWN）：按站点的 `on_jev_unavailable` 处理，默认拒绝。超时和调用限额可按站点调整（[07.6](07-console-architecture.md#76-站点级判定参数advanced)）。观察模式下只记录"本应拦截"，照常转发。
8. **记录上下文**。源站返回 2xx 响应后，把响应中的值加入已见值，追加一条访问记录；命中入口的请求同时记入"经过的入口"。
9. **写判定日志**。见 [03.4](03-admin-config-audit.md#34-判定日志)，字段和追溯链路见 [07.4](07-console-architecture.md#74-判定记录decisionrecord-v2)。

## 1.5 写操作和新建对象

写操作（POST、PUT、PATCH、DELETE）走同样的步骤。删除患者 D，D 未见，交给 Jev，判越权。新建患者时，请求体里是姓名等新输入，不是在指定已有对象，Jev 只做攻击判定；源站返回的新患者 ID 进入上下文，之后打开详情走快速放行。

写操作的目标如果只在公共搜索里出现过，而站点标明这个请求位置不接受公共来源，就是尝试越权（第 4 步）：删除搜到的患者交给 Jev，Jev 判 DENY，源站不会收到请求。同一个患者在备注这类接受公共来源的子路径上写入，不受影响，见 [07.4.7](07-console-architecture.md#747-档位在判定中的使用)。

在请求值的类别上，请求体（JSON 或表单）里键名为 `name` 的值是 `input`，不是对象引用，所以新建患者的姓名不会被当作引用送给 Jev。查询和路径里的 `name` 仍是引用，因为 `?name=` 可以按名字查找对象；`username`、`patient_name` 这类键同样仍是引用。

## 1.6 首版范围

首版只处理 HTTP 请求和响应。业务 WebSocket、应用层加密报文、HTTP/3 不做判定，站点如果依赖这些通道传业务数据，需要单独评估。

## 1.7 网关对请求和响应的处理边界

- **请求体**：需要判定的请求，网关先读完请求体再转发。请求体超过 48 KiB 或没有明确的 `Content-Length`（分块传输）时，网关直接返回 413，不转发，只写一条简记录。需要上传大文件的接口登记到 `bypass`（该接口因此不经判定，包括越权判定）。
- **响应压缩**：网关转发时去掉请求里的 `Accept-Encoding`，让源站返回未压缩内容，这样才能读出响应里的值。`bypass` 路径不受影响，静态资源仍可压缩。
- **响应观察范围**：只读取 2xx、`Content-Type` 为 JSON 或 HTML、未压缩且不超过 1 MiB 的响应。其他响应不进入上下文。
- **登录跳转**：登录接口返回 302 并下发会话 Cookie 时，网关用这个 Cookie 建立新会话。只支持 Cookie 或响应头里的会话凭证；凭证只出现在响应 JSON 里的源站（下称 JSON 凭证站点），登录后第一次请求须落在入口上。JSON 凭证站点的登录响应值按下面的规则记入会话：
  - **暂存**：登录请求没有会话，网关把 2xx、JSON 的登录响应里的所有标量暂存为“待绑定登录”。暂存只保存键控哈希、字段名和响应中的位置，不保存原文；对象表里标为身份的位置也一样，只保存键控哈希和角色标签。长度不少于 16 个字符的标量作为凭证候选；没有候选的响应不暂存。暂存有效 5 分钟，最多 1000 份，所有暂存合计最多 20000 个值，超出时都淘汰最旧的；网关重启即丢失，与 [1.2](#12-会话与上下文) 的规则一致。暂存属于它所在的站点。
  - **绑定**：只有入口请求会开始会话并参与绑定。凭证第一次出现在其他路径的请求上时不绑定；源站应答之后它才有会话，这个会话不带登录值，也不记判定原因，之后的入口请求同样不再绑定（会话已存在）。入口请求上的凭证绑定不上时，判定记录写明原因，会话同样要等源站对它答了 2xx 才建立。请求带来的凭证（Cookie 原样比较；`Authorization` 头比较前去掉 `Bearer ` 等认证方案前缀，方案名按 HTTP 令牌字符判断，可含数字；其他请求头原样比较）的键控哈希，与同一站点一份待绑定登录的某个候选标量相同，且只对上这一份时，网关用该凭证建立会话，把这份登录响应的标量（凭证本身除外）记入该会话的已见值，来源记为“登录响应”；登录响应里对象表标为身份的位置（用户、机构、角色）的值，按同样的回声规则记为该会话的身份，然后删除这份暂存。绑定只看凭证值，不看客户端地址或登录先后；同一地址的其他用户或并发登录的值不会进入这个会话。会话已存在时不再绑定。
  - **不绑定**：凭证对上多份未过期的暂存、对上的暂存已过期或没有对上时，都不记入任何会话。会话按没有登录值处理，与现在相同。判定日志注明原因：`login_ambiguous`、`login_expired`、`login_unmatched`。
  - **判定日志**：登录请求记 `trace.response.pending_values`（暂存的标量数）；绑定那次请求所在的会话记 `trace.session.login_request_id`，指向这次登录（见 [7.4](07-console-architecture.md#74-判定记录decisionrecord-v2)）。
- **转发头**：网关追加 `X-Forwarded-For`（客户端地址）和 `X-Xshield-Request-Id`，`Host` 原样透传。
