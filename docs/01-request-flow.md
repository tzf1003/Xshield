# 01 请求判定流程

## 1.1 组件

| 组件 | 职责 |
|---|---|
| 网关（`xshield-gateway`） | 反向代理；识别会话，维护会话上下文，调用 Jev，执行放行或拦截 |
| Jev | 外部模型判定服务，经 Vercel AI Gateway 调用，见 [02](02-jev.md) |
| 控制台（`xshield-control` + `web/console`） | 管理员修改站点配置，查看判定日志 |
| PostgreSQL | 站点配置、配置历史、判定日志 |

网关直接看得到源站的每个响应，所以不需要浏览器探针来告诉它用户看到了什么。网关从 PostgreSQL 读取站点配置，配置变更后自动重新加载，不再需要控制面向网关推送签名快照。

## 1.2 会话与上下文

**会话**由源站自己的登录凭证确定。站点配置写明凭证在哪个 Cookie 或请求头里（例如 `SESSIONID` 或 `Authorization`）。网关用密钥对凭证值做哈希，作为会话键，不保存凭证原文。凭证变了（重新登录、换账号）就是一个新会话，上下文从空开始。

每个会话的**上下文**包含三部分：

- **已见值**。源站返回给这个会话的成功响应里出现过的值。网关解析响应，取出其中所有字符串和数字标量（患者 ID、订单号等），用密钥哈希后保存，并记下每个值出现时的字段名和来源请求（例如"`id`，来自 `GET /api/patients`"）。不需要配置哪个字段是 ID。
- **近期访问记录**。最近若干次请求的方法、路径和状态码，不含请求值。
- **经过的入口**。会话访问过哪些入口，以及第一次访问的时间。

响应解析范围：JSON 响应取全部标量；HTML 响应取链接（`href`、`src`、`action`）里的路径段和查询参数值，以及表单字段的值。其他类型（二进制、应用层加密报文）不解析，相关的后续请求都会交给 Jev。单个响应超过 1 MiB 时不解析，判定日志里注明。

默认上限（固定在代码里，不进配置）：每个会话最多 5000 个已见值、每个值最多记 3 处来源、50 条访问记录；会话 24 小时无活动即过期；超出上限时淘汰最旧的记录。

首版上下文存放在网关进程内存里，适用于单实例部署。需要多实例时改为共享存储（PostgreSQL），读写接口不变。网关重启会丢失上下文，用户需要从入口重新进入，这与"只接受正常路径"的规则一致。

## 1.3 请求值

网关把一个请求拆成若干**请求值**：路径中的每一段、每个查询参数值、表单字段值和 JSON 请求体里的每个标量。会话凭证本身不算请求值。

每个请求值标注：

- 位置（例如"路径第 3 段"、"查询参数 `doctor`"、"JSON 字段 `patient.id`"）；
- **是否已见**，以及已见时的来源（字段名和来源请求）。

只有长度不少于 8 个字符的值才能单凭"已见"走快速放行。短值（例如 `7`、`asc`）很容易在别的字段里碰巧出现过（患者 8 和年龄 8），不能仅凭出现过就认定是同一个对象，需要交给 Jev 结合来源判断。

## 1.4 判定步骤

对每个请求依次执行：

1. **跳过**。路径命中站点的 `bypass` 列表（静态资源等）：直接转发，不判定，不记录。
2. **识别会话**。没有会话凭证的请求只能访问入口；访问其他路径直接返回 401。
3. **拆出请求值**，按 [1.3](#13-请求值) 标注。
4. **快速放行**。请求没有任何请求值，或者全部请求值都是已见的长值：放行，不调用 Jev。这些值都是源站之前亲自交给这个会话的，既不是越权引用，也不是攻击者构造的文本。
5. **查缓存**。同一会话、同样的方法、路径和请求值，在 10 分钟内被 Jev 判为放行过：直接放行。只缓存放行结论，因为上下文只会增长，放行结论不会因此失效；拒绝结论可能在用户浏览列表之后变成放行，所以不缓存。
6. **调用 Jev**。其余请求连同上下文交给 Jev，一次调用回答两个问题：这次访问有没有正常路径依据，请求内容是不是攻击。请求是否命中入口作为事实一并告诉 Jev。入口请求里的未见值，如果是入口本身需要的输入（登录表单、分享码、搜索关键字），不构成越权；如果是在指定别人的对象（例如在"我的患者"接口上带 `?doctor=B`），仍判为越权。详见 [02](02-jev.md)。
7. **执行**。两个问题都通过：转发源站。任一判为拒绝：返回 403，不转发。Jev 超时、出错、超出调用限额或答不上来（UNKNOWN）：按站点的 `on_jev_unavailable` 处理，默认拒绝。观察模式下只记录"本应拦截"，照常转发。
8. **记录上下文**。源站返回 2xx 响应后，把响应中的值加入已见值，追加一条访问记录；命中入口的请求同时记入"经过的入口"。
9. **写判定日志**。见 [03.4](03-admin-config-audit.md#34-判定日志)。

## 1.5 写操作和新建对象

写操作（POST、PUT、PATCH、DELETE）走同样的步骤。删除患者 D，D 未见，交给 Jev，判越权。新建患者时，请求体里是姓名等新输入，不是在指定已有对象，Jev 只做攻击判定；源站返回的新患者 ID 进入上下文，之后打开详情走快速放行。

## 1.6 首版范围

首版只处理 HTTP 请求和响应。业务 WebSocket、应用层加密报文、HTTP/3 不做判定，站点如果依赖这些通道传业务数据，需要单独评估。
