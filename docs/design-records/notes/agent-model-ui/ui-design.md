# 控制台界面设计：学习代理与模型配置

2026-11-03 · 设计稿，尚未实现 · 接 [console-design-objects-routes.md](../console-design-objects-routes.md)（对象表）和 docs/06

范围：两块。

1. **学习代理**（代码名 `agent`）：学习设置里的开关和每日上限，学习任务与代理的运行状态，代理给出的结论怎么看、怎么处理。
2. **模型配置**：控制台“系统”页新增“模型”标签，管理 Jev 判定模型和学习代理模型的地址、模型名、密钥和超时，取代现在只能用环境变量配置的做法。

对象表的另外四块（冷启动候选、自动收紧和自动暂停的提示、暂停状态、路径 id 确认）由「补完对象学习的未实现部分」另出设计稿（`notes/object-learning-ui/ui-design.md`），这里不重复。

写法沿用 docs/06：ASCII 线框、控件与校验表、文案集中在 `lib/vocab.ts`。原则沿用 06.1.2：结论先行，用业务话，代码名悬停可查，记录里的内容（包括模型输出）一律按不可信文本只渲染文本节点。

## 2. 系统 · 模型

### 2.1 布局

系统页的标签变为：网关、日志存储、运行参数、**模型**、导入。模型排在导入之前，因为它比导入常用。

```text
├──────────────────────────────────────────────────────────────────────────────────────────┤

│ 提供方    Vercel AI Gateway（OpenAI 兼容）                                                 │
│ 地址      https://ai-gateway.vercel.sh/v1                                                 │
```

- 两张卡片上下排列，各自独立编辑、保存、测试。卡片标题右侧是一句话状态：
  - Jev：`● N/N 个网关已加载第 M 版`；有实例没跟上时 `▲ edge-2 仍在用第 4 版：密钥无法解密`；没有在线网关时 `– 没有在线的网关`（灰字）。
  - 学习代理：`● 最近一次成功`、`▲ 最近 5 次失败：401 未授权`、`– 未配置`、`– 已配置，还没有调用过`。
- “来源”一行回答“现在用的是哪份配置”：
  - `控制台第 N 版`：控制台里有配置，环境变量即使设置了也不再使用。被覆盖的环境变量列出名字（不列值），提示用户可以从 compose 里删掉。
  - `环境变量`：控制台里还没有配置，网关仍读环境变量（兼容现在的部署）。这时卡片显示网关上报的线路、主机名和模型（来自心跳，与网关标签一致），密钥一行写“来自环境变量 AI_GATEWAY_API_KEY”。主按钮改为“改由控制台管理…”，打开编辑表单，地址和模型预填网关上报的值，密钥要重新填写（控制台读不到环境变量里的密钥）。
  - 学习代理模型没有环境变量来源，未配置时卡片只有一句说明和“配置…”按钮：

```text
┌ 学习代理模型 ──────────────────────────────────────────────────────────────────── – 未配置 ┐
│ 学习代理在规则判不了某个位置的类别时，用这个模型给出提议。                                 │
│ 没有配置时，各站点的学习代理开关保持关闭，学习照常按规则进行。                             │
│                                                                              配置…        │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- “最近 1 小时”和“今天”两行是给人判断“改完有没有坏”的：Jev 的数字来自判定日志（与 Jev 调用页同源，点击跳过去）；学习代理的数字来自学习任务的运行记录。“各站点用量”展开一张小表：站点、今天已用 / 上限、失败、上次调用，站点名点进该站点的对象表。

### 2.3 密钥

密钥只写不读：控制台接口从不返回密钥本身，只返回“是否设置、末 4 位、更新时间、来源”。

```text
 密钥   已设置 · 末 4 位 …a91f · 11-03 10:12 更新    替换…
                                    ↓ 点“替换…”
 密钥   [ ●●●●●●●●●●●●●●●●●●●●            ] 👁   取消替换
        保存后旧密钥立即作废。只会显示末 4 位。
```

- 输入框 `type=password`、`autocomplete="off"`、`spellcheck=false`，眼睛按钮只在按住时显示明文。粘贴时去掉首尾空白；含换行或空格时报错“密钥里不能有空白”。
- 密钥不写进 `sessionStorage` 草稿，也不进 URL、日志或错误上报；离开页面时表单里的密钥丢弃。
- 不提供“清除密钥”。要回到环境变量，用卡片的“改回环境变量…”（只在环境变量里有对应密钥时出现，确认后删除控制台里这一组配置）。
- 末 4 位由后端在保存时算好另存，不从密文解出来显示。

### 2.4 测试连接

“测试连接”用**表单里当前的值**（密钥没替换时用已保存的）发一次最小调用，不需要先保存：

- Jev：发一份固定的、不含任何真实数据的 `state`（一次登录后查看自己资料的请求），检查回答是否能按 docs/02 解析出两个问题的概率。
- 学习代理：发一份固定的位置上下文（一个只有一个候选类别的玩具站点），检查输出是否符合结构约束。

结果显示在表单底部，保留到下次测试或离开页面：

| 结果 | 写法 |
|---|---|
| 成功 | `✓ 11:02:31 成功 · 812 ms · 模型返回了合法的回答` |
| 能连上但回答不对 | `! 能连上，但回答不能解析：缺少 attack 问题的概率`（Jev）/ `输出不符合结构约束`（代理）。说明“多半是模型名填错了，换成了一个不是 Jev 的模型” |
| 失败 | `✕ 失败：401 未授权，密钥不对或已过期`；`✕ 失败：超时（2,000 ms）`；`✕ 失败：451，这个地区不能直连`；`✕ 连不上：域名解析失败`。失败码沿用 6.6.4 的 Jev 失败码文案，多出来的（解析失败、TLS 错误）加到词表 |
| 模型返回的错误正文 | 最多 300 字符，按不可信文本显示在结果下方，可展开 |

- 测试从**控制台进程**发出。控制台和网关不在同一网络时，结果可能不同，结果下方固定一行灰字：“测试从控制台发出。保存后以网关的加载状态为准。”
- 测试每 10 秒最多一次（按钮倒计时），计入模型用量，但不写判定日志，也不算进学习代理的每日上限。

### 2.5 保存

“保存…”打开确认对话框（与站点的保存对话框同一个外观，但不产生站点版本）：

```text
┌ 保存 Jev 判定模型（第 6 版）────────────────────────────────────────────────────────────┐
│ 改动                                                                                    │
│   模型   typesafe-ai/jev → typesafe-ai/jev-2                                            │
│   密钥   已替换（…a91f → …7c02）                                                         │
│ 影响                                                                                    │
│   全部 6 个站点的 Jev 调用改用新配置。网关约 5 秒内加载；加载失败的网关继续用第 5 版。    │
│   ▲ 2 个站点处于拦截模式，Jev 失败时拒绝请求：emr、juice                                  │
│ 测试   ✓ 11:02:31 用这份配置测试成功                                                     │
│ 备注   [ 换成新版 Jev                                         ]                          │
│                                                               取消      保存第 6 版     │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

- 改动逐项列出，密钥只写“已替换”和前后末 4 位。
- **测试门槛**：这份配置（与表单逐字段比较）没有测试成功过时，“测试”一行写 `! 这份配置还没有测试成功`，并出现复选框“我知道没有测试成功，仍然保存”，勾选后才能保存。有站点处于拦截模式并且 `on_jev_unavailable: deny` 时，复选框旁加一句“保存后如果 Jev 调用失败，这些站点会拒绝请求”。
- 保存带上读取时的版本号；别人（另一个浏览器标签）先保存过时返回冲突，对话框提示“配置已被改为第 6 版”，并给出“重新载入”。
- 保存成功后对话框关闭，卡片标题的状态变为 `○ 等待网关加载第 6 版…`，5 秒一刷新，直到所有在线网关都上报第 6 版（`● 3/3 个网关已加载第 6 版`）或有网关报错（`▲ edge-2 加载第 6 版失败：……，仍在用第 5 版`）。这与站点保存后的“生效状态”是同一套展示。
- 学习代理的保存对话框没有“拦截模式”这一行，影响写“开启了学习代理的 3 个站点下一次学习起改用新配置”。

### 2.6 变更记录

“变更记录”在卡片下方展开一张表，最近 20 版：版本、时间、改了什么（字段名和新旧值，密钥只写“已替换”）、备注、测试结果（保存时是否测试成功）。每行有“恢复到这一版…”，打开保存对话框，改动预填为恢复后的差异；**密钥不随版本恢复**（旧密钥已作废），对话框里写“密钥保持当前的 …7c02”。

### 2.7 网关标签的配合

“网关”标签展开实例后的“Jev 线路”一节保持只读，多一行“配置来源”：`控制台第 6 版` 或 `环境变量`。实例上报的版本落后于模型标签时，这一行加 `▲ 未加载第 6 版：{原因}`，并链接到模型标签。

## 3. 学习代理

### 3.1 学习设置里的开关

学习设置抽屉里“学习代理”一行按状态显示四种样子：

```text
 学习代理  [   关 ]  规则判不了的位置交给学习代理。
            – 系统里还没有配置学习代理模型 · 去配置 →                         （开关置灰）

 学习代理  [   关 ]  规则判不了的位置交给学习代理。
            ▲ 学习代理模型最近 5 次调用失败：401 未授权 · 查看模型配置 →     （开关可用）

 学习代理  [   关 ]  规则判不了的位置交给学习代理。
            现在有 12 个位置在等学习代理。发给它的只有位置、结构和统计，不含值 · 看一个例子

 学习代理  [ 开   ]  规则判不了的位置交给学习代理。
            每日上限 [ 200 ] 次    今天已用 37 次 · 下次学习 15:00
```

- “去配置 →”和“查看模型配置 →”跳到 `/system?tab=models`。
- “看一个例子”打开一个只读弹层，显示本站点一个真实等待位置的代理输入（结构见 object-map-design 第 4 节：位置、响应结构、流向、候选类别卡片），标题写“发给学习代理的内容（不含任何值）”。这是让管理员放心打开开关的关键一步。
- 每日上限：0 到 100000（与现有校验一致），0 表示开着但不调用（只排队）。旁边灰字：“按位置调用，不按请求调用。首轮大约每个接口 1 次，之后只在接口变化时调用。”
- 打开开关、改上限都走站点的保存对话框、产生版本（与现在一致）。保存对话框的影响一节写：“学习代理每天最多调用 200 次；现在有 12 个位置在等它，下一次学习（15:00）开始处理。学习代理只产生提议，放宽仍要人确认。”
- 模型未配置时网关和控制台都拒绝保存 `agent.enabled: true`，错误文案“学习代理模型还没有配置”。已开启的站点之后模型被改坏，不自动关开关，靠 3.2 的状态条和总览提示。

`AGENT_SAVE_READY` 在学习代理上线时改为真，`agent_configured` 改为“学习代理模型已配置（地址、模型、密钥齐全）”。另加 `agent_health`（`ok`、`failing`、`unknown`）驱动上面第二种样子。

```text
│ 类别 12 │ 已确认 86 │ 待确认 7 │ 有歧义 3 │ 已暂停 1 │ 学习中 41          ⌕ 搜索类别、字段、路径 │
│ 学习任务 上次 14:00 · 用时 12 秒 · 新提议 3 · 自动收紧 2   下次 15:00     运行记录   立即运行    │
│ 学习代理 今天 37 / 200 · 等待 12 个位置 · 失败 2                                               │
```

- 第一行永远显示；从没跑过时写“学习任务 还没有运行过 · 下次 15:00”；自动学习关闭时写“自动学习已关闭，只用手工声明”，没有“立即运行”。
- 第二行只在学习代理开启时显示。上限用完时写 `今天 200 / 200 · 已到上限，剩下 9 个位置明天继续`；模型失败时 `▲ 最近 5 次失败：401 未授权 · 查看模型配置`。
- 数字可点：“新提议 3”筛选待确认里本次新增的位置；“等待 12 个位置”筛选 `agent=waiting`；“失败 2”筛选 `agent=failed`。
- **立即运行**：只跑本站点一次，和每小时的任务同一套逻辑（包括调用学习代理、受每日上限约束）。按下后按钮变为“正在运行…”，结束后状态条刷新，并用一行提示写结果（“新提议 1 个，学习代理回答 4 个”）。同一站点 5 分钟内只能运行一次，任务正在跑时按钮置灰并说明“学习任务正在运行”。

### 3.3 运行记录

“运行记录”打开右侧抽屉，最近 48 次（两天的整点任务加手动运行）：

```text
┌ 学习任务运行记录 · emr ──────────────────────────────────────────────────────────────────┐
│ 时间          触发   用时    新提议  自动收紧  自动暂停  学习代理（问 / 答 / 失败 / 跳过）│
│ 11-03 14:00   定时   12 秒      3        2         0      6 / 5 / 1 / 0                 │
│ 11-03 13:41   手动    9 秒      1        0         0      4 / 4 / 0 / 0                 │
│ 11-03 13:00   定时   11 秒      0        0         0      0 / 0 / 0 / 0                 │
│ 11-03 12:00   定时    —         —        —         —      ✕ 失败：读取判定日志超时        │
│ ……                                                                                     │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

- 单击一行展开明细：本次新提议、自动收紧、自动暂停的位置列表（点进位置抽屉），学习代理每次调用的位置、结果（选了什么 / 失败原因）和耗时。“跳过”是因为每日上限用完没有问的位置数。
- 整次失败的运行只显示原因，原因是服务端文案，不含堆栈。

### 3.4 位置抽屉里的“学习代理结论”

现有的“agent 结论”一节改名“学习代理结论”，按状态显示。只在这个位置问过、或正在等学习代理时出现。

**已回答，与规则一致或规则没有结论**（现有样子加两行）：

```text
 学习代理结论                                              11-03 14:00 · anthropic/claude-…
   选择     医生 doctor
   置信度   86%
   依据     f1 · 响应结构                       （点击高亮对应的流向行或结构行）
   理由     （模型输出，按文本显示）预约列表里 doc_id 的值之后 87% 用在医生详情……
   看它收到的输入 ▸                     重新询问
```

**与规则不一致**（记为有歧义，等人处理）：

```text
 学习代理结论                                                                  ▲ 与规则不一致
   规则         医生 doctor（流向 87%）
   学习代理     文档 document（置信度 71%）
   所以这个位置记为“有歧义”，暂时交给 Jev。你可以选一边确认，或保持有歧义。
                                         按规则确认…   按学习代理确认…   保持有歧义
```

**提议新类别**：

```text
 学习代理结论
   选择     新类别：处方 prescription
   说明     （模型输出）医生开具的处方单，值在处方列表和处方详情之间流动。
                                                          新建类别并确认…
```

“新建类别并确认…”打开声明字段归类对话框（对象表设计 3.3），类别一栏预填“＋ 新类别”和代理给的 id、名称、说明，全部可改；id 先按类别 id 的规则校验（小写字母、数字、`_`），不合规时预填清洗后的值并提示。

**排队中 / 失败 / 预算用尽**：

```text
 学习代理结论   排队中 · 下次学习 15:00 处理
 学习代理结论   ✕ 14:00 失败：超时（30 秒），第 2 次 · 下次学习重试，连续 3 次失败后不再自动重试   重新询问
 学习代理结论   – 今天的上限已用完，明天继续
```

- **看它收到的输入**：展开显示这次调用发出的上下文 JSON（不含值，结构同 3.1 的例子），等宽字体，可复制。用来判断代理“为什么这么选”。
- **重新询问**：再问一次，计入今天的上限；上限用完或学习代理关闭时置灰并说明原因。已确认的位置不显示这个按钮。重新询问是排队，不是同步等待：按下后这一节变为“排队中 · 立即运行或下次学习时处理”，旁边给“立即运行”。
- 代理的结论只产生提议。会放宽的提议进入待确认，与规则的提议一样；只会收紧的提议在自动收紧开启时自动生效，横幅和变更历史的作者写“学习任务（学习代理）”。
- 理由、说明、新类别名称都是模型输出，按不可信文本渲染，长度截断到 500 字符（可展开）。

### 3.5 位置表的来源筛选

工具栏在视图切换旁加“来源”下拉：全部 / 管理员声明 / 规则 / 学习代理。另加两个只在学习代理开启时出现的选项：等学习代理、学习代理失败。选择写入 URL `source`、`agent`。位置表的“来源”列对学习代理写“学习代理”，依据列写“学习代理 86%”或“与规则不一致”。

### 3.6 总览的需要处理

| 事项 | 何时出现 | 写法 | 操作 |
|---|---|---|---|
| 模型配置未加载 | 有在线网关上报的 Jev 配置版本落后于控制台，超过 1 分钟 | `▲ edge-2 没有加载 Jev 模型配置第 6 版：密钥无法解密` | 查看模型配置 |
| 学习代理连续失败 | 学习代理模型最近 5 次调用全部失败 | `▲ 学习代理最近 5 次调用失败：401 未授权，3 个站点的学习暂时只按规则进行` | 查看模型配置 |
| 学习代理上限连续用尽 | 某站点连续 3 天到达每日上限 | `emr 的学习代理连续 3 天用完 200 次上限，还有 140 个位置在等` | 调整上限（打开该站点的学习设置） |

## 5. 数据与接口

接口名和字段名可由后端线程调整，但下面这些信息界面都要用到。

### 5.1 模型配置（「把模型配置移到控制台后台」）

| 接口 | 用途 |
|---|---|
| `GET /api/system/models` | 两组配置的当前状态 |
| `PUT /api/system/models/{jev｜agent}` | 保存。正文是表单值加 `expected_version`、`note`；`key` 省略表示不换，字符串表示替换；`share_key_with_jev`（仅 agent）。返回新版本号；版本冲突 409 |
| `POST /api/system/models/{jev｜agent}/test` | 用正文里的值测试（`key` 省略时用已保存的）。返回 `ok`、`latency_ms`、`status`、`failure`（失败码）、`detail`（模型返回的错误正文，最多 300 字符）、`answer_valid`。每 10 秒一次，多了返回 429 |
| `DELETE /api/system/models/jev` | 改回环境变量（只在环境变量里有密钥时允许） |
| `GET /api/system/models/{jev｜agent}/history` | 最近 20 版 |
| `GET /api/system` | 每个网关实例的 `jev` 多两个字段：`config_source`（`console`、`env`）、`config_version`，加载失败时 `config_error` |

`GET /api/system/models` 每组的形状（示意）：

```json
{
  "configured": true,
  "source": "console",
  "version": 5,
  "updated_at": "2026-11-03T02:12:00Z",
  "route": "gateway",
  "endpoint": "https://ai-gateway.vercel.sh/typesafe/v1/systemone",
  "model": "typesafe-ai/jev",
  "timeout_ms": 2000,
  "key": { "set": true, "last4": "a91f", "updated_at": "2026-11-03T02:12:00Z", "shared_with_jev": false },
  "env_overridden": ["AI_GATEWAY_API_KEY"],
  "env_available": true,
  "loaded": [{ "edge": "edge-1", "version": 5, "error": null }],
  "usage": { "window": "1h", "calls": 4812, "failed": 19, "p95_ms": 910 },
  "last_call": { "at": "2026-11-03T02:59:58Z", "ok": true, "failure": null }
}
```

后端约定（界面依赖这些行为）：

- 控制台有配置时优先，没有时网关继续读环境变量。
- 网关加载新版本失败时继续用旧版本，并在心跳里上报失败原因；不能因为新配置坏了就没有 Jev。
- 密钥加密保存，接口从不返回密钥，审计和日志里只出现末 4 位。
- 学习代理模型由控制台进程使用（学习任务在控制台里跑），不需要网关加载。

### 5.2 学习代理（「实现对象学习代理」）

| 接口 | 用途 |
|---|---|
| `GET /api/sites/{name}/objects` | 现有字段外加 `agent_configured`（改为真实值）、`agent_health`，以及 `learning_run`：`{ last: { at, trigger, duration_ms, proposals, tightened, paused, agent: { asked, answered, failed, skipped }, error } ｜ null, next_at, running, agent_today: { used, limit }, agent_waiting, agent_failed }` |
| `GET /api/sites/{name}/objects/runs?limit=48` | 运行记录；单条的明细（位置列表、每次调用）用 `GET …/runs/{id}` |
| `POST /api/sites/{name}/objects/run` | 立即运行。202；5 分钟内重复或正在运行返回 429 / 409，带原因 |
| `POST /api/sites/{name}/objects/slots/{id}/ask` | 重新询问学习代理（排队）。上限用完、未开启返回 409，带原因 |
| `GET /api/sites/{name}/objects/agent-sample` | 3.1 的“看一个例子”：一个等待位置的代理输入 |
| `GET /api/sites/{name}/objects/slots/{id}` | `agent` 扩为下面的形状 |

位置详情里的 `agent`：

```json
{
  "status": "answered",
  "asked_at": "2026-11-03T06:00:03Z",
  "model": "anthropic/claude-…",
  "attempts": 1,
  "choice": "doctor",
  "new_class": null,
  "confidence": 0.86,
  "cites": ["f1", "endpoint_shape"],
  "reason": "……",
  "rule_choice": "doctor",
  "failure": null,
  "input": { "slot": {}, "endpoint_shape": [], "flows_in": [], "candidates": [] }
}
```

`status` 取 `queued`、`answered`、`failed`、`skipped_budget`；`choice` 为 `new` 时 `new_class` 是 `{ id, name, description }`；`rule_choice` 为规则的结论或 null，两者不同时界面按“与规则不一致”显示。

## 7. 新增词汇

| 代码名 | 名称 | 说明 |
|---|---|---|
| `agent` | 学习代理 | 规则判不了时给出类别提议的模型。列宽不够时写“代理” |
| `models` | 模型 | 系统页标签 |
| `config_source: console / env` | 控制台第 N 版 / 环境变量 | 当前生效配置的来源 |
| `route: gateway / direct / custom` | Vercel AI Gateway / TypeSafe 直连 / 自定义地址 | Jev 线路（沿用现有 `ROUTE_LABEL`） |
| `queued` / `answered` / `failed` / `skipped_budget` | 排队中 / 已回答 / 失败 / 上限已用完 | 学习代理对一个位置的状态 |
| `disagree` | 与规则不一致 | 规则和学习代理结论不同，位置记为有歧义 |
| `trigger: schedule / manual` | 定时 / 手动 | 学习任务的触发方式 |
| `answer_invalid` | 回答不能解析 | 测试或调用时模型回答不符合格式 |
| `dns` / `tls` | 域名解析失败 / TLS 错误 | 测试连接的新增失败原因 |

## 8. 空状态、错误与可访问性

- 模型标签读不到数据时用 6.7.3 的错误条；两张卡片分别加载，一张失败不影响另一张。
- 测试中按钮显示“正在测试…”，最长等到超时加 2 秒，期间可以取消。
- 密钥输入框的眼睛按钮有 `aria-label="按住显示密钥"`；测试结果区域 `role="status"`，读屏会读出结果。
- 卡片标题的状态不只靠颜色：● ▲ – 加文字，符合 6.5.3。

## 9. 分工与顺序

| 线程 | 界面部分 |
|---|---|
| 「把模型配置移到控制台后台」 | 第 2 节全部、3.6 的“模型配置未加载”、5.1 |
| 「实现对象学习代理」 | 第 3 节（3.6 的后两项）、5.2；3.1 的“去配置”只依赖 `agent_configured`、`agent_health`，可以先按假数据做 |

两边唯一的交点是“学习代理模型”卡片：配置的存取和测试接口由模型配置线程做，学习代理线程按 5.1 的形状读取配置、上报 `usage` 和 `last_call`。建议两边先对一下 `GET /api/system/models` 里 `agent` 这一组的字段，再各自开工。
