## 2. 配置 · 接口名规则

```text
┌ 接口名规则 ─────────────────────────────────────────────────────────── 1 条 · 24 小时 9,812 次 ┐
│ 默认用 URL 路径作为接口名。只有接口名放在请求头、查询参数或正文里的路径才需要规则。             │
│                                                                                               │
│ 路径  /weixin/wx/mp/wx361163d21a65f679/gateway                                9,812 次         │
│  接口名 第 1 段  [请求头 ▾] [ X-Service-Id     ]   ＋ 源站也认的位置                              │
│         第 2 段  [请求头 ▾] [ X-Service-Method ]   ＋ 源站也认的位置                              │
│         ＋ 添加一段                                                                            │
│  示例   …/gateway/bus.buriedPointService/saveBuriedPointList        （最近一条匹配的请求）      │
│  取不到 24 小时 3 次，按"未知接口"处理 · 查看                                                    │
│  ! 每一段只写了一个位置。如果源站在别处也接受接口名，请一并写上，否则网关和源站可能认成两个接口。 │
│ ＋ 添加规则                                                                                    │
├───────────────────────────────────────────────────────────────────────────────────────────────┤
│ 规则测试  粘贴一个完整的 HTTP 请求。只在浏览器里解析，不会上传，也不会存进草稿。                  │
│ [ POST /weixin/wx/mp/wx361163d21a65f679/gateway HTTP/1.1 …                                   ]  │
│ 结果  接口名  bus.buriedPointService/saveBuriedPointList（第 1 段、第 2 段来自请求头）            │
│       逻辑路径 /weixin/…/gateway/bus.buriedPointService/saveBuriedPointList                    │
│       命中绕过 /weixin/…/gateway/bus.buriedPointService/*                                       │
│       已隐藏 Cookie、X-Access-Token 等 3 个凭证值                                               │
└───────────────────────────────────────────────────────────────────────────────────────────────┘
```

| 项 | 控件 | 本地校验与提示 |
|---|---|---|
| 路径 | 文本框，规则同入口（`PathPattern`） | 与其他规则的路径重叠时报错"与第 2 条规则的路径重叠"；与入口、绕过规则写法相同时提示下面的"入口不再命中" |
| 来源 | 下拉：请求头 / 查询参数 / 正文字段 | 正文字段只支持 JSON 和表单，说明"正文是其他格式或加密时取不到，按未知接口处理" |
| 名称 | 文本框 | 请求头按头名字符集；查询参数按参数名；正文字段写 `a.b.c`，不支持数组下标；最长 64 个字符 |
| 源站也认的位置 | 同一段内追加一个位置 | 位置不能重复；悬停说明"这些位置都出现时，值必须一致，不一致按未知接口处理" |
| 段数 | ＋ 添加一段 | 1 到 4 段 |

提示与警告：

- **单位置提示**（`!`，中性符号）：每一段都只写了一个位置时显示上面的提示，可以点"我确认源站只认这里"关掉，记在草稿里。
- **入口不再命中**：规则生效后，这条路径下的请求按逻辑路径匹配入口和绕过。现有的 `/weixin/…/gateway` 这类精确入口不会再命中任何请求，提示"改写为逻辑路径"，并给出按接口名补全的候选（来自最近的记录）。
- **预估的局限**：过去的判定记录没有保存请求头，来源是请求头的规则无法按历史预估接口拆分，提示"保存后开始按接口统计"；来源是查询参数或正文字段的规则可以按历史预估。

入口和绕过的编辑器（`PatternListEditor`）在有规则的路径下输入时，按最近记录补全逻辑路径，例如输入 `/weixin/…/gateway/` 后列出 `bus.buriedPointService/saveBuriedPointList · 24 小时 8,016 次`。规则测试器（`PatternTester`）同时接受单个路径和完整请求：只有路径时用 URL 路径，粘贴完整请求时先算逻辑路径再匹配。

- 顶部横幅只放需要人处理的事：自动暂停（▲，警告色）、自动收紧（中性，可撤销）。没有时不显示。
- 计数标签互斥，选中写入 URL `state`，与搜索框同时生效。
- **按类别**：左侧类别列表（名称、id、位置数、24 小时使用次数），右侧类别卡片和它的位置表。类别 id 创建后不变，改名只改名称。
- **按位置**：一张表，列为位置（一侧图标 + 逻辑路径 + 位置）、类别与状态、来源（管理员声明 / 规则 / agent）、依据摘要、最近出现。单击行在右侧打开位置抽屉（3.2），`j`/`k` 逐条浏览，与请求追溯的预览面板一致。

### 3.2 位置抽屉

```text
┌ 响应 GET /api/appointments  [].doc_id ───────────────────────────────── 待确认 · 规则 ┐
│ 提议：医生 doctor                                                                      │
│ 依据  这个位置的值之后用在：                                                            │
│   GET /doctor/{id} path[1]          87%   140 次   23 个会话   Jev 通过 140 · 拒绝 0     │
│   GET /api/schedule query.doc       11%    18 次    6 个会话   Jev 通过 18 · 拒绝 0      │
│   示例请求 …77354552 · …e3a1b2c4 · …0c41d2e9                                            │
│ 响应结构（不含值）  [].id:number  [].doc_id:number  [].doc_name:string  [].slot:string   │
│ 影响  过去 7 天 158 次 Jev 调用会变成快速放行；14 次快速放行会改回 Jev（/docs/{id}）        │
│       改回 Jev 的这些请求原本把医生编号当成了文档编号 · 查看                              │
│ 范围  仅 /api/appointments*（证据里的接口） · 放宽…                                      │
│ 历史  10-31 规则提议 · 11-01 证据更新                                                    │
│                                         标为有歧义   改为其他类别…   忽略   确认…        │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

- 依据一节按位置的一侧显示"之后用在"（响应位置）或"之前出现在"（请求位置），每行可点，跳到按这个组合筛选的请求追溯。
- 响应结构只显示字段路径和类型，从不显示值。
- agent 给出的提议多一节"agent 结论"：选择、置信度、引用的依据（`f1`、响应结构，点击高亮对应的行）、理由。理由是模型输出，按不可信文本只渲染文本节点。
- **复合值**（位置带格式时）多一节"格式"：

```text
│ 格式  按 # 拆成 3 段（98% 的值符合）                                                     │
│   第 1 段  字母 2–20 位        输入：姓名                                                │
│   第 2 段  数字 11 位          输入：手机号（按身份信息查找）                             │
│   第 3 段  数字 1–6 位         患者 patient  · 流向 92% · 已确认                          │
│   不符合格式的 2% 整体交给 Jev · 查看                                                     │
```

- **按条件取类别**（位置带条件时）多一节"条件"：`由 query.by 决定：id 为患者；phone、name 为输入（按身份信息查找）`；按形状判断的写成 `按值的形状：短数字为患者，11 位数字为手机号`，形状重叠的部分标"有歧义，交给 Jev"。
- 操作：
  - **确认…**：打开保存对话框（06.4.9），改动写成"对象表 ＋ 响应 GET /api/appointments [].doc_id 归为医生（仅 /api/appointments*）"，影响按第 6 节列出。站点处于拦截模式、并且会新增快速放行时，必须勾选"我已查看示例请求"才能保存。
  - **改为其他类别…**：选择已有类别或新建，同样走保存对话框。
  - **标为有歧义**：这个位置永久交给 Jev，学习不再提议。
  - **忽略**：记在服务端，学习任务不再提议同一结论；证据发生明显变化后重新提议。与调优建议的"忽略"不同，后者只存在浏览器里。

### 3.3 声明字段归类

"＋ 声明字段归类"和请求详情里的"把这个字段归类…"打开同一个对话框：

```text
┌ 声明字段归类 ────────────────────────────────────────────────────────────────────────────┐
│ 字段   [ doc_id ]        忽略大小写和 _、-：doc_id、docId、DocID 是同一个                   │
│ 类别   [ 医生 doctor ▾ ]  或 ＋ 新类别                                                      │
│ 范围   ● 仅这些接口  [ /api/appointments* ] ＋                                              │
│        ○ 全站（站点里同名字段指两种东西时会错放行）                                          │
│ 会匹配 响应 GET /api/appointments [].doc_id · 请求 GET /api/schedule query.doc_id            │
│        另有 GET /api/records/{id} attachments[].doc_id 不在范围内（之后用在 /docs/{id}）      │
│                                                         取消      预估影响并加入草稿         │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

- 从请求详情发起时，范围默认填这次请求的接口；"会匹配"一栏按最近的记录列出命中和不命中的位置，不命中的同名字段用来提醒范围的意义。
- 选"全站"时，如果最近记录里同名字段流向两类以上的目标，选项旁显示警告，并列出这些目标。

### 3.4 从同义词改写

高级判定参数的同义词旁、以及对象表工具栏的"从同义词改写…"：对每组同义词按最近记录列出它实际影响的位置，逐个选择"归为哪一类、限定在哪些接口"，生成字段归类声明，并删除这组同义词。同义词里的词也出现在站点路径里（例如 `/api/docs`）时，组标题旁显示"会让路径里的 docs 也算成 doctor"。

### 3.5 学习设置

"学习设置 ⚙"打开抽屉，设置属于站点配置，改动走保存对话框、产生版本：

| 项 | 控件 | 说明 |
|---|---|---|
| 自动学习 | 开 / 关 | 关闭后只用手工声明，已确认的位置照常生效 |
| 自动收紧 | 开（推荐）/ 关 | 只会让快速放行变少的改动是否自动生效；关闭后也进入待确认 |
| agent | 开 / 关 + 每日调用上限 | 规则判不了的位置是否交给 agent；没有配置模型时置灰并说明 |
| 学习门槛 | 至少 N 次使用、M 个会话（默认 20、5） | 调低会更快学到，也更容易被少数会话影响 |
| 自动暂停 | 开（推荐）/ 关 | 已确认位置出现异常时自动暂停 |

## 4. 请求追溯与请求详情

### 4.1 请求追溯

- 路径列显示逻辑路径；由规则得到的部分用 `›` 分隔并用次要文字色，例如 `/weixin/…/gateway › bus.buriedPointService/saveBuriedPointList`，悬停说明"接口名来自请求头 X-Service-Id、X-Service-Method"。未知接口写 `/weixin/…/gateway › 未知接口`。
- 条件语法新增：

| 条件 | 例子 | 说明 |
|---|---|---|
| `path:` | `path:/weixin/*` | 改为匹配逻辑路径。没有规则的站点与现在相同；逻辑路径以真实路径开头，前缀筛选照常可用 |
| `api:` | `api:saveBuriedPointList`、`api:unknown` | 接口名部分；`unknown` 查取不到接口名的请求 |
| `object:` | `object:doctor` | 请求值里有这一类对象的请求 |

### 4.2 请求详情

- **头部**：请求行下面多一行"接口 bus.buriedPointService/saveBuriedPointList · 来自请求头"；取不到时写原因，例如"未知接口：X-Service-Method 出现了 2 次，按未知接口处理（不算入口、不走绕过）"。
- **判定过程**：在"站点"之后加一步"接口名"：`✓ 接口名  规则 /weixin/…/gateway → bus.buriedPointService/saveBuriedPointList（请求头）`；没有规则时 `– 接口名  没有规则，用 URL 路径`，灰字；取不到时用 `!` 和原因。
- **请求值表**新增"类别"一列，并调整来源标签：

```text
 位置          字段     值   类别                      已见  已核验  来源
 path[1]       —        5    医生 doctor（对象表）       见过  未核验  attachments.doc_id · GET /api/records/7 · 文档
                                                                    ! 类别不同：文档 ≠ 医生
 body.who      who      …    复合值 · 按 # 拆成 3 段     —     —
   body.who#0           Alice 输入：姓名                 —     —
   body.who#2           42   患者 patient（对象表）     见过  已核验  id · GET /api/patients · 患者
 query.q       q        42   患者（由 query.by=id 决定） 见过  已核验  …
```

  - 类别后面注明来自哪里：对象表（已确认）、对象表提议（未生效，只作为提示交给 Jev）、名字推断（灰字）。
  - 来源标签末尾加上来源位置的类别；两边类别不同时在下一行用 `!` 写"类别不同：文档 ≠ 医生"，这正是 Jev 判越权的依据。
  - 用作接口名的值显示为"接口名"，不参与核验，归入折叠的惰性值一行。
- **Jev 上下文**结构化视图里，值和来源都显示 `object`；判读提示加一条"值只以文档出现过，现在用作医生"。
- **相关栏**新增操作：把这个字段归类…（值未核验且来源字段名与路径的类别不同）、为这条路径写接口名规则…（路径是某条规则的前缀，或命中"可能是统一网关"的建议）。

## 5. 调优建议与变更历史

新增建议类型：

| 代码名 | 名称 | 卡片内容 | 操作 |
|---|---|---|---|
| `object_proposals` | 对象表待确认 | "对象表有 7 条待确认，确认后预计每天少调用 Jev 1,240 次"，列出影响最大的 3 条 | 前往对象表；单条可直接"确认…" |
| `route_rule_candidate` | 可能是统一网关 | "/weixin/…/gateway 占本站点 92% 的请求，正文字段 `method` 有 37 种取值"（来源是请求头时需要网关记录请求头名，见第 7 节） | 写接口名规则…（预填路径和来源） |

## 6. 保存对话框的新影响类型

| 影响 | 写法 | 可否从历史预估 |
|---|---|---|
| 按接口拆分 | "这条路径下 9,812 个请求将按 37 个接口分别判定" | 来源是查询参数、正文字段时可以；请求头不行，写"保存后开始统计" |
| 入口、绕过不再命中 | "入口 /weixin/…/gateway 将不再命中任何请求（N 个原本放行的无会话请求将需要会话）" | 可以 |
| 新增快速放行 | "158 次 Jev 调用会变成快速放行" + 示例 | 可以，按记录里的来源近似估算 |
| 改回 Jev | "14 次快速放行会改回调用 Jev" + 示例，说明"这些请求原本靠名字把医生编号当成了文档编号" | 可以 |
| 缓存按接口区分 | "同一会话里参数相同的不同接口不再共用放行结论" | 只提示，不计数 |

统计不完整时沿用"按前 N 条记录计算"。近似估算的影响旁注明"来源只记录了前 3 个，结果是近似值"。

## 7. 数据与接口

| 接口 | 用途 |
|---|---|
| `GET/PUT /api/sites/{name}`、`POST /api/sites/validate`、影响预估 | 站点配置新增 `routes`、`objects`（含学习设置），沿用现有保存、校验、版本流程 |
| `GET /api/sites/{name}/objects` | 类别、位置列表和计数；参数 `state`、`class`、`q` |
| `GET /api/sites/{name}/objects/slots/{id}` | 位置抽屉：流向、示例请求、响应结构、格式、条件、agent 结论、历史 |
| `POST /api/sites/{name}/objects/slots/{id}/dismiss`、`/ambiguous` | 忽略提议、标为有歧义（学习状态，不进站点版本） |
| `GET /api/sites/{name}/objects/bootstrap` | 冷启动的候选类别 |
| 请求列表、详情 | 记录新增 `logical_path`、`api`（名字和来源，或取不到的原因）、每个值和来源的 `object`；筛选参数新增 `api`、`object` |

- 逻辑路径的计算放在 `lib/logical-path.ts`，与 Rust 实现共用测试用例（同 `lib/site-validate.ts` 的做法）。规则测试器在浏览器里调用它，所以粘贴的请求不需要上传。
- 粘贴的请求先在本地隐藏 `Cookie`、`Authorization`、名字含 token 的头的值，再显示和解析；不写入 `sessionStorage` 草稿。
- "可能是统一网关"的建议如果要覆盖请求头来源，需要网关在判定记录里记下请求头的**名字**（不记值，有数量上限）。不做这一步时，建议只覆盖查询参数和正文字段来源。

## 9. 新增词汇

| 代码名 | 名称 | 说明 |
|---|---|---|
| `logical_path` | 逻辑路径 | 真实路径加上按规则取到的接口名，判定、入口、绕过、缓存都按它 |
| `api` | 接口名 | 接口名规则取到的名字 |
| `unknown_api` | 未知接口 | 有规则但取不到接口名，不算入口、不走绕过、交给 Jev |
| `object` | 类别 | 值指向的对象类别，例如医生、文档 |
| `slot` | 位置 | 值所在的地方：某个接口的某个字段，或某个路由的某个参数 |
| `pending` / `proposed` / `confirmed` / `ambiguous` / `suspended` / `retired` | 学习中 / 待确认 / 已确认 / 有歧义 / 已暂停 / 已过期 | 位置的状态 |
| `admin` / `rule` / `agent` | 管理员声明 / 规则 / agent | 类别从哪里来 |
| `composite` | 复合值 | 一个值里装了几段，按格式拆开分别核验 |
| `identity_lookup` | 按身份信息查找 | 按手机号、姓名等查对象，不要求展示过，由 Jev 判断是否合理 |

一句话解释（`explain.ts`）的调整：`fast_allow` 在用到对象表时写"{N} 个需核验的值都已核验（按对象表：医生），没有调用 Jev。"；`jev_deny` 的越权原因在类别不同时写"{位置}里的 {值} 在这个会话里只以{文档}出现过，现在用作{医生}。"。

## 10. 分期

与后端分期对齐，每期都能单独上线：

1. **接口名规则**：配置分组、规则测试、入口与绕过的逻辑路径补全、请求列表和详情的接口名、`api:` 条件、对应的影响预估。
2. **对象表骨架**：对象表标签（类别卡片、手工声明、从同义词改写）、请求值表的类别列、Jev 上下文的类别、`object:` 条件。
3. **学习**：待确认队列、位置抽屉的证据、冷启动、学习设置、自动收紧和自动暂停的横幅与历史、调优建议的两个新类型。
4. **复合值与按条件取类别**：位置抽屉的格式、条件两节，请求值表的子行。

原型：可以按这份设计在 `design/console-v4` 里补上这些画面，再开始实现。
