# 对象学习：控制台界面设计（冷启动、自动变更、暂停、路径参数确认）

2026-11-03 · 设计稿，尚未实现 · 依据仓库 HEAD `4c13997` · 接 [console-design-objects-routes.md](../console-design-objects-routes.md)

范围：[object-learning-status.md](../../answers/object-learning-status.md) 第 3 节第 1、2、3、6 条。学习代理、模型配置不在本稿。

沿用现有控制台的写法和组件：`Card`、`Notice`、`ErrorBar`、`Loading`、`Kv`、`.banner` / `.banner.warn`、`.obj-foot`、`StateTag`、`RequestLink`；文案集中在 `lib/vocab.ts` 的 `OBJECT_TEXT`；任何会改配置的操作都通过 `onApply` 进保存对话框（`SaveDialog`，含影响预估、示例请求、拦截模式下"我已查看示例请求"）。记录里的文字（位置键、原因里的路径）一律用 `SafeText` 按文本渲染。

## 0. 共同约定

**收紧与放宽**（object-map 设计 3.4、5.6）：

| 方向 | 定义 | 例子 | 谁能做 |
|---|---|---|---|
| 收紧 | 只会让快速放行变少 | 把 `doc` 拆成文档与医生；位置改到更窄的类别；暂停一个位置 | 学习任务可自动执行（开关开时），管理员也可 |
| 放宽 | 会新增快速放行 | 确认提议、重新确认暂停的位置、撤销一次自动收紧 | 只能管理员，走保存对话框 |

**确认写到哪里**（第 4 节的依据）：

| 位置 | 例子 | 写入 | 范围 |
|---|---|---|---|
| 有字段名的位置 | `GET /api/appointments [].doc_id`、`query.doc` | `advanced.field_kinds` 一条 `{field, kind, in}`（现状不变） | 默认证据里的接口 |
| 路径参数 | `GET /doctor/{id} path[1]` | `objects.slots` 一条 `{key, class, source}`，类别不存在时同时加进 `objects.classes` | 只这个方法和路由模板，精确匹配 |

`objects.slots` 网关已经能解析，判定器在 `engine.rs:407` 按位置键查类别，所以路径参数的确认只差控制台写入和影响预估，不需要新的判定语义。

新增词汇（加进 `vocab.ts`）：

| 代码名 | 名称 | 说明 |
|---|---|---|
| `auto_tighten` | 自动收紧 | 学习任务自动执行的收紧，作者显示"学习任务" |
| `auto_pause` | 自动暂停 | 学习任务自动停用一个已确认的位置 |
| `anomaly` | 检测到异常 | 自动暂停关闭时，只提示、不停用 |
| `evidence_drift` | 证据转向 | 位置的值改为主要来自（或用在）另一类别的位置 |
| `origin_4xx_rise` | 403/404 升高 | 按这个位置快速放行后，源站 403、404 比例升高 |
| `jev_deny_rise` | Jev 拒绝增多 | 同一位置 Jev 拒绝次数明显增加 |
| `name_inference` | 名字推断 | 没有对象表时的判定方式：字段名、父对象名、接口名、路由词 |
| `keep_paused` | 保持暂停 | 知悉暂停，不改配置，从横幅里移除 |

## 1. 冷启动候选（接入向导第 5 步）

### 1.1 入口

- 向导现有 4 步（基本信息、会话凭证、接口名入口与绕过、确认），第 4 步"创建站点"后站点才存在，候选接口才能按站点查。新增第 5 步"对象表起点（可选）"，地址 `/sites/new?step=5&site={name}`（`search-schema.ts` 的 `step` 上限改为 5，加 `site`）。
- 第 4 步现有的勾选"创建后打开对象表"改为"创建后确认对象表起点（可跳过）"，默认勾选。不勾选时照旧直接进入站点详情。
- 第 5 步时步骤条前 4 步显示 ✓ 且不可点（站点已创建，配置在站点详情里改）。刷新页面时按 `site` 参数恢复；站点不存在时跳回 `/sites`。
- 同一个列表组件也用于对象表为空时的冷启动面板（现有 `ColdStartPanel`），两处行为一致，只有底部按钮不同。

### 1.3 组件

| 组件 | 说明 |
|---|---|
| `BootstrapList`（新，从 `ColdStartPanel` 拆出） | 分组列表、全选、筛选、汇总行；`ColdStartPanel` 和向导第 5 步共用 |
| 分组头 | 按候选类别分组；复选框三态（☑ 全选、◩ 部分、☐ 未选）；可折叠 |
| 候选行 | 复选框、一侧（请求 → / 响应 ←）、位置键（`obj-code`）、类别下拉、来源说明、`uses · sessions`、提示行 |
| 类别下拉 | 原生 `select`，与 `DeclareKindDialog` 同款：本列表里的候选类别 + 站点已有类别 + "＋ 新类别…"（展开 id 和名称两个输入框，id 校验同现有 `kindHint`） |
| `WizardObjectsStep`（新） | 第 5 步外壳：标题、窗口说明、底部按钮、跳转 |

### 1.4 状态

| 状态 | 显示 | 按钮 |
|---|---|---|
| 加载中 | `Loading height=160` | "跳过，进入站点"可用 |
| 出错 | `ErrorBar`："取不到候选：{错误}" + 重试；下一行灰字"跳过不影响站点，之后可以在对象表里确认同一份列表。" | 跳过可用 |
| 没有流量（`records = 0`） | `Empty` 标题"还没有判定记录"，正文"站点刚创建，还没有经过网关的请求。开始接流量后，名字明确的位置会出现在对象表顶部，到时再确认。" | 只有主按钮"进入站点" |
| 有流量、没有候选 | 沿用 `coldStart.none`："最近的请求里没有名字明确的位置。有请求后再来看，或在对象表里手工声明。" | 主按钮"进入站点" |

| 保存对话框取消 | 留在第 5 步，勾选保留 | — |

### 1.5 文案

- 来源说明（按 `reason.code`，词取自后端）：`field_name` "字段名 {field}"；`parent_name` "裸 id，取父对象 {word}"；`endpoint_name` "裸 id，取接口名 {word}"；`route_word` "路由词 {word} 紧挨在前"。悬停说明"名字推断的规则，与判定时相同"。
- 路径参数行多一行灰字，写法同 4.1："路由 /doctor/{id} 的第 1 个路径参数"。
- 改过类别的行，下拉旁显示"已改"，悬停写"系统提议：{原类别}"。
- 汇总行："确认后：字段归类 ＋{a} 条 · 对象表位置 ＋{b} 条 · 新类别 {c} 个（{名称列表}）"。
- 确认按钮：`确认 {n} 个位置…`（现有文案按类别计数，改为按位置）。

### 1.6 交互

- 全选只勾可选的行；筛选后全选只作用于可见行，汇总行仍按全部已选计数。
- 改某一行的类别不移动它的分组（分组按系统提议），避免列表跳动。改成"新类别"时，同一新 id 在列表内共用名称。
- 确认：字段位置生成 `advanced.field_kinds`，路径位置生成 `objects.slots`（`source: rule`；类别被改过的写 `admin`），缺的类别加进 `objects.classes`，再 `onApply` 打开保存对话框，备注预填"接入时确认对象表起点"。
- 跳过不写任何东西，对象表为空时对象表标签仍显示同一列表。

## 2. 自动收紧与自动暂停

### 2.1 学习设置里的开关

在现有 `LearningSettings` 抽屉里只改文案和状态行，不改布局：

| 项 | 名称 | 说明（`obj-learning-help`） |
|---|---|---|
| 自动收紧 | 自动收紧（推荐） | 只会让快速放行变少的改动自动生效，例如把同时指医生和文档的 doc 拆成两个类别。每次都写成新版本，作者为"学习任务"，可以撤销。关闭后这类改动进入待确认。 |
| 自动暂停 | 自动暂停（推荐） | 已确认的位置出现异常时自动停用，判定退回名字推断。异常包括：证据转向别的类别、按它快速放行后源站 403/404 比例升高、同一位置 Jev 拒绝增多。恢复属于放宽，需要你确认。关闭后只提示，不停用。 |

- 两个开关下各一行状态（小字）："学习任务每小时执行一次，上次 14:00 · 近 7 天自动收紧 2 次"、"…自动暂停 1 次"。点次数打开 2.3 的列表。
- 后端还不执行时（`features.auto_tighten = false`），开关仍可保存，状态行改为灰字"开关会保存，执行要等网关升级后生效"。不隐藏开关，以免管理员以为功能不存在。
- 关闭自动暂停时，保存对话框的改动行写"自动暂停 开 → 关：已暂停的位置保持暂停，之后的异常只提示"。

### 2.2 对象表顶部横幅

替换现有 `ObjectsBanner` 的逐条显示，改为按类型各一行，只放未处理的事件：

```text
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│ ▲ 2 个位置已自动暂停，判定已退回名字推断：GET /doctor/{id} path[1] 源站 404 比例从 1% 升到 18% 等 · 查看 │
│ ▲ 1 个已确认的位置出现异常，自动暂停已关闭，仍在生效：GET /api/schedule query.doc Jev 拒绝增多 · 查看 │
│ 学习任务 14:00 自动收紧了 2 个位置：[].doc_id 从医生改为文档 等 · 查看 · 知道了                      │
└───────────────────────────────────────────────────────────────────────────────────────────┘
```

- 暂停、异常用 `.banner.warn` 和 ▲；收紧用中性 `.banner`。只有一个事件时直接写全，多个时写第一个加"等"。
- "查看"：打开 2.3 的列表并按该类型筛选；只有一个事件时直接打开该位置的抽屉。
- 收紧行的"知道了"把这批收紧标为已处理；暂停行没有"知道了"，必须逐个处理（保持暂停、重新确认、驳回或标为有歧义），因为它影响快速放行。
- 横幅不放"撤销"：撤销是放宽，要在列表里看清前后类别和影响后再做。

### 2.3 自动变更列表

从横幅、学习设置的状态行、变更历史里的自动版本进入。右侧抽屉（`Drawer size=560`），URL `objevents=open|all`。

```text
┌ 自动变更 ─────────────────────────────────────────────────── 近 30 天 · 未处理 3 ┐
│ ● 未处理  ○ 全部        类型 [全部 ▾]                                             │
├─────────────────────────────────────────────────────────────────────────────────┤
│ 11-03 14:00  自动收紧 · v18 · 学习任务                                             │
│   响应 GET /api/records/{id} attachments[].doc_id                                 │
│   医生 doctor  →  文档 document                                                   │
│   原因  证据转向：72% 的值之后用在 GET /docs/{id} path[1]（之前 95% 用在 /doctor/{id}） │
│   影响  过去 7 天 31 次快速放行改回 Jev · 示例 …77354552                            │
│                                             知道了   查看版本   撤销…              │
├─────────────────────────────────────────────────────────────────────────────────┤
│ 11-03 13:00  自动暂停 · v17 · 学习任务                                             │
│   请求 GET /doctor/{id} path[1]                                                   │
│   医生 doctor  →  已暂停（名字推断：doctor）                                        │
│   原因  快速放行后源站 404 比例从 1% 升到 18%（7 天 312 次中 56 次） · 示例 …e3a1b2c4 │
│                                         打开位置   保持暂停   重新确认…            │
```

每条的字段：时间、类型、版本（链接到变更历史的对比）、位置、前后类别（收紧时也写范围变化，例如"范围 全站 → 仅 /api/appointments*"）、原因、影响（沿用 `IMPACT_INFO` 的 `back_to_jev`、`new_fast_allow`）、示例请求、状态。

原因的写法（按 `reason.code`）：

| code | 文案 |
|---|---|
| `evidence_drift` | 证据转向：{now} 的值{来自/之后用在} {key}（之前 {before} {来自/用在} {key0}） |
| `origin_4xx_rise` | 快速放行后源站 {403/404} 比例从 {before} 升到 {after}（{days} 天 {total} 次中 {hits} 次） |
| `jev_deny_rise` | Jev 拒绝增多：{days} 天 {after} 次，之前 {before} 次 |
| `split` | {class} 同时指两类对象，拆成 {a} 与 {b} |

状态：未处理（默认）、已知悉（灰字"已知悉 · alice 11-03 15:02"）、已撤销 / 已重新确认（写出版本和人）、已被后续改动取代（"之后 v20 又改了这个位置"，不可撤销）。

### 2.4 撤销与恢复

| 操作 | 出现在 | 行为 |
|---|---|---|
| 撤销…（自动收紧） | 列表、变更历史的自动收紧版本 | 在草稿里把这次改动反过来（去掉 `after`，放回 `before`），`onApply` 打开保存对话框。属于放宽：影响按 `new_fast_allow` 列出并附示例请求，拦截模式下必须勾选"我已查看示例请求"。备注预填"撤销自动收紧 v18"。 |
| 重新确认…（自动暂停） | 列表、位置抽屉 | 把暂停前的条目放回配置，同上走保存对话框。备注预填"重新确认 GET /doctor/{id} path[1]（自动暂停 v17）"。 |
| 知道了 / 保持暂停 | 列表、横幅、抽屉 | 只标记事件已处理，不改配置，不产生版本 |
| 查看版本 | 列表 | 打开变更历史并对比该版本（`tab=history&diff=18`） |

- 撤销按钮禁用的情况，按钮旁小字写原因："这个位置之后又改过（v20），请在位置抽屉里处理"；"草稿里有未保存的改动涉及这个位置"。
- 撤销或重新确认保存成功后，事件变为"已撤销 · v19"，横幅里移除。学习任务不会马上再做同一次收紧或暂停（见第 6 节 C3）。
- 变更历史：版本类型"自动收紧"、"自动暂停"作者显示"学习任务"，摘要用上表的前后类别，操作里的"撤销…"与这里相同；其他版本仍是现有的回滚对话框。

## 3. 暂停的位置

### 3.1 对象表里

- 计数标签"已暂停 N"不变。异常但仍在生效的位置也计在"已暂停"里，行上多一个警告标记。
- 按位置视图的行：

```text
 位置                              类别与状态                 来源      依据                     最近
 请求 GET /doctor/{id} path[1]     ▲ 已暂停 · 医生 → 名字推断   规则      404 比例 1% → 18%         21:10
 请求 GET /api/schedule query.doc  ▲ 已暂停 · 医生 · 仍在生效   管理员    Jev 拒绝 0 → 12           20:44
```

- "类别与状态"列：已停用的写"医生 → 名字推断"；未停用的写"医生 · 仍在生效"并用警告色。"依据"列写暂停原因的短句（`origin_4xx_rise` "404 比例 1% → 18%"、`jev_deny_rise` "Jev 拒绝 0 → 12"、`evidence_drift` "证据转向文档 64%"）。
- 按类别视图：类别卡片的位置表同样显示；类别列表里有暂停位置的类别名旁加 ▲ 和个数。

| 情况 | 文案 |
|---|---|
| 已停用，名字推断得到同一类别 | 判定退回名字推断：{依据} 得到 {kind}。名字推断与暂停前相同，快速放行多半不变。想让它更严，可以标为有歧义。 |
| 已停用，名字推断得到别的类别 | 判定退回名字推断：{依据} 得到 {kind}。与暂停前不同，按 {kind} 核验。 |
| 已停用，名字推断得不到类别 | 判定退回名字推断：没有可用的名字，这个位置的值都交给 Jev。 |
| 仍在生效（自动暂停关闭，或后端尚未让暂停影响判定） | ▲ 仍在生效：判定照常按 {class} 核验。检测到异常后没有停用，因为自动暂停已关闭。（后端未就绪时改为"暂停尚未影响判定"） |

### 3.3 操作

| 按钮 | 已停用时 | 仍在生效时 |
|---|---|---|
| 重新确认为{类别}…（主按钮） | 放宽：配置放回原条目，走保存对话框，影响按 `new_fast_allow` | 不显示（已经在生效）；改为"保持生效"，只标记已处理 |
| 暂停使用…（主按钮） | 不显示 | 收紧：配置去掉该条目，走保存对话框，影响按 `back_to_jev` |
| 改为其他类别… | 保留现有按钮；证据指向另一类别时，下拉默认选它 | 同左 |
| 驳回 | 学习状态，立即生效：暂停前的类别是错的；学习不再提议同一结论，证据实质变化后可再提议 | 先打开保存对话框去掉条目，保存成功后再记驳回 |
| 标为有歧义 | 学习状态：永久交给 Jev | 同"驳回"，先去掉条目再记 |
| 保持暂停 | 只标记已处理，不改配置，不产生版本；从横幅移除，位置仍是"已暂停" | 不显示 |

**要不要"保持暂停"**：要，但做成轻操作。没有它，管理员只能在"重新确认"（放宽）和"驳回 / 有歧义"（改变学习结论）之间二选一，而常见情况是"异常原因还没查清，先这样"。它也是横幅消失的唯一不改配置的方式。仍在生效时不显示，避免文字与事实不符。

- 状态提示（`Notice tone=info`）：保持暂停后"已保持暂停。这个位置继续按名字推断判定，之后可以在这里重新确认。"；驳回后沿用 `drawer.dismissed`。
- 已暂停的位置没有"忽略"：现有"忽略"只对待确认的提议有意义，对已暂停的位置就是"驳回"。

## 4. 路径参数的确认

### 4.1 声明怎么显示

位置键 `GET /api/doctors/{id}/files/{id} path[4]` 在抽屉和冷启动列表里写成：

```text
│ 位置    路由 GET /api/doctors/{id}/files/{id} 的第 2 个路径参数（path[4]）            │
│         /api/doctors/{id}/files/［{id}］                                              │
│ 提议    文件 file                                                                     │
│ 确认后：对象表 ＋ 路由 GET /api/doctors/{id}/files/{id} 的第 2 个路径参数 = 文件        │
│         （只对这个方法和路由，精确匹配；路由改版后是新的位置）                             │
```

- "第 N 个路径参数"按路由模板里 `{…}` 出现的顺序从 1 数；`path[n]` 是从 0 数的段号，放在括号里给需要的人对照。`path[n]` 指向的不是 `{…}` 段时写"第 n 段（从 0 数）"。
- 第二行是路由模板，被指到的段用 `［ ］` 包起来并加底色（`obj-code` + 新类 `obj-seg-hl`）。
- 范围一行替换现有"仅 {scope}（证据里的接口）"：路径参数写"只对这个方法和路由，精确匹配"，没有"放宽…"。
- 改动列表和变更历史里的写法："对象表 ＋ 请求 GET /doctor/{id} 第 1 个路径参数 = 医生"。

### 4.2 按钮状态

确认按钮文案沿用"确认…"。禁用时按钮带 `title`，同时在操作行上方一行小字写原因（替换现有 `drawer.noField`）：

| 情况 | 按钮 | 原因文案 |
|---|---|---|
| 待确认，有提议类别 | 可用 | — |
| 没有提议类别 | 禁用 | 还没有提议的类别，先用"改为其他类别…"选一个。 |
| 草稿里已有这个位置 | 禁用，文案"已在草稿里" | 草稿里这个位置已归为{类别}，保存或撤销草稿后再改。 |
| 已确认 | 不显示 | 状态行已写"已确认" |
| 已暂停 | 换成"重新确认为{类别}…"（3.3） | — |
| 对象表位置已满（2,048）或类别已满（64） | 禁用 | 对象表最多 2,048 个位置 / 64 个类别。先清理已过期的位置。 |
| 位置键超长（256 字节）或格式不对 | 禁用 | 这个路由太长，不能写进对象表。可以驳回或标为有歧义。 |
| 后端不支持（`features.path_confirm = false`） | 禁用 | 路径参数的确认需要网关升级，暂不可用。现在可以驳回或标为有歧义。 |

- "改为其他类别…"对路径参数也可用：不再打开字段归类对话框（它需要字段名），改为在操作行上方展开一个类别下拉（同 1.3 的类别下拉）加"确认…"。
- 影响一节：确认路径参数的影响由后端按 `objects.slots` 计算，沿用 `new_fast_allow`、`back_to_jev`；取不到时写"无法预估"，保存对话框照常要求在拦截模式下勾选"我已查看示例请求"。

### 4.3 写入

确认时控制台在草稿里加 `objects.slots` 一条 `{key: "GET /doctor/{id} path[1]", class: "doctor", source: "rule"}`（agent 提议写 `agent`，改过类别写 `admin`），类别不在 `objects.classes` 里时加 `{id, name}`，名字取类别卡片或新类别输入。`objects.classes`、`objects.slots` 不再原样保留，控制台可以追加和删除条目，但不改动别的条目的顺序和内容。

## 6. 接口需要

前缀均为 `/api/sites/{name}`。所有响应不含值，只含位置键、类别、计数和请求 id。

**A. 站点配置（第 4 节、1.6）**

1. `objects.classes`、`objects.slots` 由控制台写入：网关已能解析和校验（`CLASSES_MAX` 64、`SLOTS_MAX` 2048、`KEY_MAX` 256、类别必须已声明）。需要 `POST /validate` 和保存失败时返回具体位置：`{error: "SITE_CONFIG_OBJECTS_INVALID", field: "objects.slots[3]", reason: "class_unknown" | "duplicate_key" | "key_invalid" | "too_many" | "class_id_invalid"}`。现在是笼统的 `ConfigError::Objects`。
2. 影响预估（`preview.rs`）覆盖 `objects.slots` 的增、删、改类别，输出 `new_fast_allow`、`back_to_jev`（count、sample、top），与 `field_kinds` 一致；位置抽屉的 `impact` 对路径参数也要填。
3. 保存请求体可选 `object_event: "<event id>"`：标明这次保存是撤销某次自动收紧或重新确认某次暂停。后端据此把事件标为 `undone`，变更历史里写"撤销自动收紧 v18"。

**B. `GET /objects/bootstrap`（第 1 节）** — 现在返回空数组，形状可以直接换：

```json
{ "window_hours": 24, "records": 1204,
  "candidates": [
    { "id": "c1", "key": "GET /doctor/{id} path[1]", "side": "request",
      "kind": "doctor", "name": "医生",
      "reason": { "code": "route_word", "word": "doctor", "field": null },
      "uses": 21, "sessions": 6,
      "note": null, "conflict": null } ] }
```

- `reason.code`：`field_name` | `parent_name` | `endpoint_name` | `route_word`，与判定时的名字推断同一套规则（`kind_words` 等）。
- `records`：窗口内这个站点的判定记录数，用来区分"没有流量"和"没有候选"。
- `note`：需要人看的原因（缩写等），有它时默认不勾选。`conflict`：已保存配置里这个位置（或这个字段在重叠范围内）已归为别的类别时写那个类别 id，界面禁用该行。
- 已在 `objects.slots`、`advanced.field_kinds` 里的位置不返回。
- 假设：候选只来自这个站点自己的判定记录，门槛由后端定（界面只显示 `uses`、`sessions`）。刚创建的站点通常 `records = 0`，界面按空状态处理。

**C. 自动收紧与自动暂停（第 2、3 节）**

1. 执行：开关打开时，学习任务把收紧、暂停写成新版本（作者"学习任务"，版本类型 `auto_tighten` / `auto_pause`），从 `objects.slots` 或 `advanced.field_kinds` 去掉或改窄对应条目，判定器因此不再使用它。开关关闭时不改配置：收紧进入待确认，暂停只把位置标为 `suspended` 并记一条 `anomaly` 事件（就是现在的行为）。
2. 事件：`GET /objects/events?status=open|all&kind=&days=30` 返回列表；`GET /objects` 的 `events` 只放未处理的。每条：

```json
{ "id": "e42", "kind": "auto_tighten" | "auto_pause" | "anomaly",
  "at": "2026-11-03T06:00:00Z", "version": 18,
  "slot_id": "…", "key": "GET /api/records/{id} attachments[].doc_id", "side": "response",
  "before": { "class": "doctor", "entry": { "field": "doc_id", "kind": "doctor", "in": ["/api/records/*"] } },
  "after":  { "class": "document", "entry": { "field": "doc_id", "kind": "document", "in": ["/api/records/*"] } },
  "reason": { "code": "evidence_drift" | "origin_4xx_rise" | "jev_deny_rise" | "split",
              "days": 7, "before": 0.95, "after": 0.72, "status": 404,
              "total": 312, "hits": 56, "key": "GET /docs/{id} path[1]", "key_before": "GET /doctor/{id} path[1]",
              "classes": ["doc", "doctor"] },
  "impact": [ { "kind": "back_to_jev", "count": 31, "sample": "…" } ],
  "examples": ["…"],
  "status": "open" | "acknowledged" | "undone" | "superseded",
  "handled": { "by": "alice", "at": "…", "version": 19 } | null }
```

   `before.entry`、`after.entry` 是配置里的原样条目（`field_kinds` 一项或 `objects.slots` 一项，暂停时 `after.entry` 为 null），控制台据此在草稿里撤销或重新确认。之后的版本又改了同一位置时 `status` 为 `superseded`。`reason` 里的字段按 `code` 取用，没有的为 null。
3. `POST /objects/events/{id}/ack`：知道了、保持暂停、保持生效。幂等；已 `undone` 的返回 409。
4. 撤销或重新确认之后，学习任务把被撤销的结论按驳回处理（复用现有 dismiss 的"证据实质变化才再提议"），重新确认的位置从保存时起重新计算自检基线，避免下一小时又做同一次收紧或暂停。
5. `GET /objects` 增加 `features: { auto_tighten: bool, auto_pause: bool, path_confirm: bool }`（后端是否已执行或支持）和 `learning_status: { last_pass_at, auto_tighten_7d, auto_pause_7d }`，供 2.1 的状态行。

**D. 暂停的位置（第 3 节）** — `ObjectSlotRow` 和抽屉增加：

```json
{ "in_effect": true,
  "suspension": { "at": "…", "auto": true, "version": 17, "event_id": "e41",
                  "reason": { "code": "origin_4xx_rise", "…": "同 C2" },
                  "previous": { "class": "doctor", "source": "rule", "confirmed_at": "…", "confirmed_by": "alice" },
                  "fallback": { "kind": "doctor", "basis": "route_word", "word": "doctor" },
                  "evidence_now": [ { "class": "document", "share": 0.64 }, { "class": "doctor", "share": 0.30 } ],
                  "acknowledged": false } }
```

- `in_effect`：已保存配置里是否还有这个位置的条目（判定器是否仍在用它）。`suspension` 只在 `state = suspended` 时出现。
- `fallback`：名字推断的结果，与 B 的 `reason.code` 同一套；得不到类别时 `kind` 为 null、`basis` 为 `none`。必须用判定器的同一份代码算。
- 现有 `dismiss`、`ambiguous` 接口要接受 `suspended` 状态的位置（现在界面只对 `proposed` 开放忽略）。
- 依赖：缺口第 4 条（暂停不影响判定）由 C1 的"自动暂停写新版本、去掉条目"解决；`in_effect = true` 时界面如实写"仍在生效"，不依赖判定器读学习状态。

**E. 路径参数（第 4 节）** — 除 A1、A2 外不需要新接口；`features.path_confirm` 在 A1、A2 上线后置为 true。
