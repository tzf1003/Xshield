# 14 按 ID 检索、证据分析与安全回放

## 14.1 统一调查入口

后台顶部全局搜索支持 req_/ev_/dec_/art_/mdl_/agt_/grant_/case_ 以及标准 trace_id。解析 ID 类型后先鉴权，再定位安全域与数据分区。不得凭 ID 中时间或租户字段相信客户端授权。

request_id 查询返回请求摘要、身份快照、阶段树、来源页面与资格链、解密转换图、模型/Agent 关联、最终动作、源站结果、证据可用性及索引水位。用户从一条模型调用或资格 ID 也能反向定位关联请求。

新事件尚未进入 ClickHouse 时，查询接口显示 pending + indexed_through，并可按权限从已持久 journal/manifest 读取最近证据；不把“索引还未到”误显示为“没有发生”。

## 14.2 查询能力

结构化过滤：时间、站点、operation、decision、reason_code、auth_binding_ref、grant_id、model_version、低置信区间、回退类型、证据完整性、源站结果、延迟范围。

请求排序分页使用稳定游标与唯一 ID，不使用无上限 OFFSET。限制每次时间窗、扫描字节、行数和执行时间；结果包含实际扫描量和截断标记。

结构化事件检索可按事件 envelope 的 32 个小写十六进制字符 `trace_id` 精确过滤；检索摘要回传已校验的 trace 引用，事件详情可据此预填同 Trace 检索，但仍由操作者提交有界 UTC 时间窗。trace 本身不携带可信事件时间或授权范围，查询固定 tenant/site、参数绑定并沿用 Investigator 预算和审计，不据 trace 推断主体、资格或跨作用域关联。

调查者也可按规范 `ShareGrantId` 定位已发布的分享签发记录；该条件只读取固定 `share.issued` 事件的顶层 `share_id`，结果仍为脱敏摘要，不返回 bearer 凭证或改变分享/业务授权。

当前结构化检索支持一个有界因果边：以规范 `ev_` ID 精确查找直接引用它为前驱的事件；事件详情也可沿已记录的 `cause_event_ids` 反向逐条查看前驱。每一步都重新执行 Investigator 范围检查、时间窗/成本预算和管理审计，不自动递归展开；该能力不是完整关联图，也不推断缺失因果关系。

精确 ID 查询通过 typed ID 的时间局部性和索引桶缩小范围；trace_id 精确匹配 ClickHouse 现有 `FixedString(32)` 列，并继续受有界时间窗与扫描预算约束。首版不为每个事件在 PostgreSQL 建百万级重复 locator；按规模使用 ClickHouse 的次序、查询表/物化视图以及有界热目录。标明 ORDER BY 主要服务的查询路径并实测，而不是依赖一个 Bloom 索引解决所有检索。[S24]

## 14.3 自然语言检索

操作者可输入“找出这个版本上线后因 UI 来源缺失而拒绝的改密请求”。Agent 生成可展示的 QueryPlan：时间、站点、过滤、聚合、限制。QueryPlan 经 allowlist AST 校验、权限注入和成本预算后执行，不直接接受 Agent 任意 SQL。

所有调查工具读取权限不高于发起操作者，结果的字段级脱敏不可被 prompt 关闭。需要敏感内容时新建显式审批，不让 Agent 因“分析需要”自行解锁。回答必须引用 request_id/event_id/artifact_id 和具体片段，区分观察事实、规则解释与推测。

## 14.4 四种回放

EVIDENCE_VIEW：展示当时保存的内容、规则、结果；不重新判定。

DETERMINISTIC_REPLAY：使用冻结的身份/资格快照、规则/适配版本、Clock 输入和原参数，在无网络环境重算硬规则。结果与原记录对比；依赖缺失则 incomplete，不声称复现。

MODEL_REEVALUATION：同一证据发送给指定模型/模板，形成新的 model_call_id/replay_id，比较概率和结果；不覆盖原结果。供应商版本不可固定时明确不可保证逐次一致。

SANDBOX_PROTOCOL_REPLAY：隔离测试源站验证协议转换；生产凭证被替代，目的域白名单，写操作需明确测试资源。生产请求重放不是默认功能，另需强审批与副作用检查。

## 14.5 调查包导出

包内容：case manifest、事件 JSONL、请求/响应各版本、转换关系、模型输入输出、规则/适配/构建引用、证据摘要及签名验证说明、脱敏与缺失清单。包默认加密，下载授权短时，记录操作者、目的、范围、批准者和字节数。

导出包不默认附带 live Cookie、API key 或生产连接串。导出有过期和次数限制，但已下载副本不能远程保证删除。证据对照可给安全文本视图或十六进制视图，绝不在后台同源执行被捕获 HTML/JS。

## 14.6 查询性能目标

待验证目标：已入热索引的单 request_id 元数据 P95 ≤ 1 秒；完整阶段树 ≤ 2 秒；大原文按大小单独度量。不是所有历史和冷对象都承诺秒开。索引延迟目标、冷存储恢复与并发配额分别在控制台显示。

必须测试跨租户 ID 探测、任意对象路径、复杂查询耗尽、恶意正则和日志中的提示注入。用户看到 request_id 不等于获得案件或原文访问权。
