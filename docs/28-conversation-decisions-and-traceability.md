# 28 对话决策汇总与需求追踪

## 28.1 最终决策，不回退到旧建议

| 讨论主题 | 最终采用 | 明确不采用 |
|---|---|---|
| 部署 | 前置代理、自动注入普通 JS、按站适配 | 强制业务引入前后端 SDK |
| 心跳和堆栈 | 关联与风险证据 | 在线、点击或堆栈即证明权限 |
| 加密 | 实际协议终止/替换后重建，双向可见 | 一份明文镜像证明另一份密文内容 |
| 适配失败 | 站点/端点受控 compatibility | 客户端声称 Hook 失败就自动放行 |
| 资格 | 当前身份绑定下的资源、操作、字段和视图 | ID 出现过就得到该对象全部权限 |
| 一天会话 | 服务端与 Cookie 双重到期，可配置 | 仅靠浏览器过期，或一天内换身份仍继承 |
| 直接 URL | 已有有效资格可复用，无资格拒绝 | 为无依据的书签、粘贴 ID 自动放宽 |
| 新浏览器与新资源 | 重新通过认可入口取得资格 | 自动迁移旧浏览器账本或猜测未展示资源 |
| 创建成功 | 原认证快照下提交资格，再返回响应 | 等异步日志稍后推导权限 |
| 分享 | 明确例外入口，限权发行，继续记录 | 分享路径下所有请求免检、所有 ID 授权 |
| 身份串用 | WAF Cookie 和有效业务凭证强绑定 | WAF_A 与 Session_B 混用或静默换绑 |
| 凭证更新 | 验证继承链；续期与换账号分别处理 | 看到任何新 Cookie 就继承全部账本 |
| 垂直/操作越权 | 对应界面操作来源 + 精确操作/目标约束 | 根据评论作者 ID 推导密码重置权限 |
| 用户有真实权限但无界面来源 | 严格模式仍然拒绝 | 为恢复隐藏 ACL 而无依据放行 |
| JEV | 有限候选语义匹配、风险信号、置信记录 | 全历史精确查 ID、直接任意发放资格 |
| AI 进化 | 适配候选、独立验证、受控发布 | 在线错误触发自动扩权、生产副作用测试 |
| 日志 | 每请求、每层、AI 与转换内容均可关联 | 普通 log 一把打印所有秘密，或采样安全审计 |
| 主语言 | Rust 主干；TS、必要模型/浏览器运行时边界 | 为语言统一重新发明密码学/模型引擎 |

这份记录整理的是本会话确定的产品选择，而非声称这些机制已运行。历史 v1/v2 文件哈希保存在 reference/input-provenance.json；不将旧稿复制为并列有效规格。

## 28.3 边界接受记录

用户主动接受“未走认可流程就拒绝”的可用性取舍。设计保留安全恢复入口，但它只是重新取得资格，不是绕过资格。

仍需验证的边界：站点是否错误地通过正常界面提供敏感操作；原认证是否有可信验证来源；加密是否可适配；端点覆盖是否完整；隐式撤权是否可及时观察；长流和大包如何保证捕获；模型是否达到本站误匹配预算。不能通过日志或更大上下文消除这些信息与一致性缺口。

## 28.4 阅读和维护规则

产品改变先更新本章与 RQ/INV，再通过 ADR 记录原因，随后改 Schema/配置/测试。文档、模板、演示默认值必须一致。源站更新只允许修复映射，不得把未批准的管理入口自动加入 root。最终评审应检查“原来要拦的路径，是否因兼容处理被重新打开”。
