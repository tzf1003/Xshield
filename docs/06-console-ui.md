# 06 控制台界面设计

版本 4.2｜2026-11-02｜状态：设计稿，待实现。数据结构、接口和前端架构见 [07 技术方案](07-console-architecture.md)；可点击原型在 [design/console-v4](../design/console-v4/README.md)，直接用浏览器打开 `index.html` 即可。本章与原型不一致时以本章为准。

## 6.1 设计目标与原则

### 6.1.1 四项要求落到界面上

| 要求 | 界面上的做法 |
|---|---|
| 保留高级配置 | 站点的每个字段都能在表单里改；表单和 YAML/JSON 编辑器编辑同一份草稿，随时切换；“高级判定参数”分组列出 Jev 超时、调用上限、放行缓存、追加脱敏词、同义词，每项显示默认值、本站点的值和最近 24 小时的证据；每次保存产生版本，任意两个版本可比较、可回滚；不可配置的运行参数在“系统”页只读展示；请求列表支持条件语法，详情页能看到完整原始记录 |
| 兼顾便捷性 | 一个搜索框（⌘K）粘贴请求 ID、会话标签、路径或站点名直达；列表单击即在右侧预览，`j`/`k` 逐条浏览；每条记录顶部一句话说明结论和原因；从请求直接“登记为入口 / 加入绕过 / 调整 Jev 超时”，保存前自动给出影响预估；观察模式下自动汇总调优建议；批量粘贴测试套件导出的请求 ID 对照结论 |
| 每个请求都可追溯 | 网关处理的每个请求（包括绕过、413、未知站点）都能按请求 ID 打开；记录里出现的每个请求 ID 都可点击：值的来源请求、缓存复用的 Jev 放行、Jev 看到的最近访问、签发会话的登录请求、判定时的配置版本；查不到时说明可能的原因；日志写入有缺口时如实提示 |
| Jev 调用可查看详细上下文 | 每次调用显示两个问题的完整概率、结论、模型与线路、耗时与所用超时、裁剪级别、请求大小；`state` 有结构化、JSON、原文三种视图，外加指令全文和原始响应；结构化视图里每个值、每条最近访问都链接到对应的请求；失败的调用说明失败码和随后的处理 |

### 6.1.2 原则

1. **结论先行，逐层展开**。每一层先回答“发生了什么”：列表行（结论标签）→ 预览面板（一句话解释、关键值）→ 详情页（判定过程、请求值、Jev 上下文）→ 原始记录（JSON）。不需要的人不必往下看。
2. **请求 ID 是一等公民**。凡是出现请求 ID 的地方都可点击、可复制，悬停显示该请求的摘要（方法、路径、判定路径、时间）。
3. **颜色只表达结论**。拦截、本应拦截、未经判定用状态色，并且总是配图标和文字；放行不着色。判定路径用图标和文字区分，不另配颜色（图表除外，见 6.5.4）。
4. **用业务话，代码名随手可查**。界面写“快速放行”“本应拦截”，代码名（`fast_allow`、`would_block`）出现在悬停说明、条件语法和原始记录里，方便高级用户对照日志和代码。
5. **记录里的内容一律当作不可信文本**。判定日志里到处是攻击载荷，界面只渲染文本节点；值里的控制字符、零宽字符、双向控制字符显示成带底色的转义（如 `\u202e`），避免肉眼被欺骗。
6. **密度优先，留出呼吸**。表格默认紧凑行高 32 px，可在用户菜单切到 40 px；卡片、分组之间留足间距；一屏放得下的信息不做成弹窗。
7. **所有状态都能分享**。筛选、标签页、视图模式都在 URL 里，复制链接给自己或别人能还原到同一个画面。

## 6.2 信息架构

### 6.2.1 导航

左侧导航六项，顺序按使用频率：

| 导航 | 回答的问题 | 主要内容 |
|---|---|---|
| 总览 | 现在正常吗？有什么要处理？ | 需要处理的一行摘要（列表在顶栏的铃铛里）、关键指标、判定路径趋势、各站点状态、最近的拦截 |
| 请求追溯 | 某个请求为什么是这个结论？ | 请求列表、快捷筛选、条件语法、预览面板、实时模式、批量对照、导出 |
| 会话 | 这个用户之前做了什么？ | 会话列表、会话时间线（每步学到了什么、经过了哪些入口） |
| Jev 调用 | Jev 健康吗？判得准吗？ | 健康状态、耗时与置信度分布、调用列表、失败统计 |
| 站点 | 怎么改配置？改了会怎样？ | 站点列表、接入向导、站点详情（概览、配置、对象表、调优建议、变更历史） |
| 系统 | 网关在线吗？日志完整吗？ | 网关实例、日志存储、运行参数、导入判定日志 |

导航底部常驻：观察模式和拦截模式的站点数（点击进入站点列表）、快捷键帮助、退出登录。

### 6.2.2 路由

所有页面状态放在 URL 查询参数里（[07.10.3](07-console-architecture.md#7103-路由与-url-状态)）。其中两项是全局的，在各页之间保持：

- `site`：站点范围，缺省为全部站点。
- `range`：时间范围，取 `15m`、`1h`、`6h`、`24h`、`7d` 或 `custom`，缺省 `24h`。`range=custom` 时再用 `since`、`until` 给出起止（Unix 毫秒，最长 7 天）。打开某个具体时间段的链接（日志缺口的“查看缺口”、趋势图上的一段）写成 `range=custom&since=…&until=…`；选回预设范围，或在时间窗提示条上点“清除”，就是把 `range` 写回 `24h` 等预设值，`since`、`until` 随之丢掉。

范围只存在于 URL 里。页内链接、导航按钮、命令面板和快捷键跳到没有写明范围的地址时，把当前的 `site` 和 `range`（`custom` 时连同 `since`、`until`）带过去，目标自己写明的不改。所以浏览器后退会回到原来页面的范围，地址里没有 `site` 就是全部站点，不会因为“上次选过”而变。

| 路由 | 页面 | 页面自己的查询参数 |
|---|---|---|
| `/login` | 登录 | `next`：登录后返回的地址（只接受以 `/` 开头的站内路径） |
| `/` | 总览 | — |
| `/requests` | 请求追溯 | `q`（条件语法）、`chip`（快捷筛选）、`scope=all`（含绕过和未知站点的请求）、`peek`（预览面板打开的请求 ID）、`live=1` |
| `/requests/$requestId` | 请求详情 | `tab=pipeline｜values｜jev｜session｜raw`、`jev_view=structured｜json｜raw｜prompt`、`jev_doc=state｜body｜response`（JSON、原文视图看哪一份）、`hl`（高亮的值序号） |
| `/sessions` | 会话列表 | `flag=blocked｜jev`、`q`（会话标签前缀） |
| `/sessions/$label` | 会话时间线 | `only=judged｜jev｜blocks`、`at`（滚动定位到的请求 ID） |
| `/jev` | Jev 调用 | `q`（同请求追溯的条件语法，限定为 Jev 记录）、`chip` |
| `/sites` | 站点列表 | — |
| `/sites/new` | 接入向导 | `step=1..4`、`from=yaml`（直接粘贴配置创建） |
| `/sites/$name` | 站点详情 | `tab=overview｜config｜objects｜insights｜history`、`edit=form｜yaml`、`group=basic｜session｜routes｜entries｜bypass｜mode｜advanced`、`diff=a..b`（变更历史里比较的两个版本）；`tab=objects` 时另有 `state`（计数标签）、`q`（搜索）、`view=class｜slot`（按类别、按位置）、`class`（选中的类别）、`slot`（打开的位置抽屉），见 6.4.10 |
| `/system` | 系统 | `tab=edges｜storage｜params｜import` |

不存在的请求 ID、会话标签、站点名都显示该页面的“找不到”状态（6.7.2），不跳回首页。

- 左侧导航展开宽 216 px，可折叠为 56 px 的图标栏（折叠状态记在 `localStorage`）。顶栏高 52 px，页面内容区最大宽度不限，表格占满。
- 页面标题区：左侧标题和副标题（例如“请求追溯 · juice · 最近 24 小时”），右侧放本页操作（导出、批量对照、新建站点等）。

### 6.3.2 顶栏

| 元素 | 行为 |
|---|---|
| 站点范围 | 下拉列出全部站点（名称、模式、Host），选择后写入 URL 的 `site`（替换当前历史项，不新增，后退不会停在选择之前的同一页）；选了单个站点时，各页表格隐藏“站点”列 |
| 全局搜索框 | 点击或按 ⌘K / Ctrl+K 打开命令面板（6.3.3）；粘贴时直接识别内容 |
| 时间范围 | 预设：15 分钟、1 小时、6 小时、24 小时（默认）、7 天；底部“自定义…”选起止时间。最长 7 天（保留期），早于保留期的部分不可选 |
| 网关状态灯 | 读 `/api/status`（每 15 秒，[07.9.13](07-console-architecture.md#7913-状态灯与配置生效)）。文字写在线实例数：“网关 2/3 在线”。绿：有在线实例且没有问题；琥珀：有问题，包括站点加载失败、新版本保存超过 30 秒仍有在线实例没加载、有实例离线（24 小时内发过心跳、现在不在线）、最近 15 分钟有日志缺口、发送队列超过 80%、分区不足、心跳延迟；红：没有在线实例。点击弹出问题列表，每条带链接（打开配置、查看系统、查看缺口期间的请求）。灯只回答“现在有没有问题”：一天前的日志缺口不会让灯一直是琥珀色，它留在系统页的缺口列表里 |
| Jev 状态灯 | 读同一个接口的 `jev.health`：正常（绿）、空闲（灰，最近 5 分钟没有调用）、降级（琥珀）、不可用（红）。点击弹出最近 5 分钟调用数、失败分布、p50/p95 和“查看 Jev 调用” |
| 需要处理铃铛 | 灯后面的铃铛，每页都有，点击弹出“需要处理”列表（6.4.2 的每一条，带原来的操作链接）。徽标分两种：严重和警告是需要处理的事项，有严重时为红底、标记 ■，只有警告时为琥珀底、标记 ▲；提示单独计数，蓝底、圈着的 i，不计入需要处理。没有事项时没有徽标，面板写“一切正常”和最后检查时间。点链接后面板关闭并进入那一页；按 Esc 关闭并把焦点还给铃铛。某个读取失败时，面板里写明哪一类事项没有列出，并可重试 |
| 用户菜单 | 主题（跟随系统、浅色、深色）、行高（紧凑、舒适）、退出登录 |

状态灯的颜色总是配文字（“网关 正常”“Jev 降级”），折叠到窄屏时保留图标和悬停说明。

### 6.3.3 命令面板

⌘K / Ctrl+K 打开，居中浮层，宽 640 px。输入或粘贴后按以下顺序识别，结果分组列出，回车执行第一项，⌘/Ctrl+回车在新标签页打开：

| 输入 | 识别方式 | 给出的操作 |
|---|---|---|
| 含 1 个请求 ID | 任意文本中匹配 `req_` + 32 位十六进制 | 打开请求详情；副标题显示从 ID 解出的时间 |
| 含 2 个以上请求 ID | 同上，去重保序 | “批量对照 N 个请求 ID”，打开 6.4.3 的批量对照并带入粘贴内容 |
| 16 位十六进制 | 会话标签 | 打开会话时间线 |
| 以 `/` 开头 | 路径 | “筛选路径 /rest/basket/6”“筛选路径前缀 /rest/basket/*”；若命中某站点的入口或绕过，另列“在 juice 中命中入口 /rest/user/login” |
| `GET /path` 形式 | 方法加路径 | 按方法和路径筛选 |
| 站点名 | 与站点列表匹配 | 打开站点、打开站点配置、打开调优建议 |
| 含 `:` | 条件语法（6.4.3） | 按条件打开请求追溯；语法有误时在结果里指出错误位置 |
| 其他文字 | 匹配命令名 | 新建站点、导入判定日志、切换主题、复制当前页链接、查看快捷键 |

输入为空时列出最近打开的 10 个请求、会话和站点（`localStorage`，只存 ID 和标题）。

### 6.3.4 键盘快捷键

焦点在输入框、编辑器里时只有 ⌘K、Esc、⌘S 生效。

| 键 | 作用 | 范围 |
|---|---|---|
| ⌘K / Ctrl+K | 命令面板 | 全局 |
| `/` | 聚焦本页的筛选输入框 | 列表页 |
| `g` 然后 `o` `r` `s` `j` `c` `y` | 跳到 总览、请求追溯、会话、Jev 调用、站点、系统 | 全局 |

| 回车 | 打开选中行的详情 | 列表 |
| Esc | 关闭预览面板、对话框；详情页返回列表并保持滚动位置 | 全局 |
| `[` / `]` | 同一会话的上一个 / 下一个请求 | 请求详情 |

| `l` | 实时模式开关 | 请求追溯 |
| ⌘S / Ctrl+S | 打开保存对话框 | 站点配置 |

## 6.4 页面

### 6.4.1 登录

- 居中卡片：产品名、一个口令输入框、“登录”按钮。不提供用户名（单管理员）。
- 错误：口令错误（“口令不正确”）；同一来源 10 分钟内失败 10 次（“尝试次数过多，请 10 分钟后再试”）。
- `window.isSecureContext` 为假时，在卡片上方显示：“控制台需要经 HTTPS 或 localhost 访问，否则浏览器不会保存登录状态。可以用 SSH 隧道把控制台端口转发到本机。”
- 登录成功后跳到 `next`，没有则到总览。会话 12 小时过期；过期后任何请求返回 401 时，弹出登录对话框（不离开当前页，未保存的配置草稿保留）。

“需要处理”由前端根据 `/api/status`、`/api/sites`、`/api/system/models`，以及需要时各站点的 `/api/sites/{name}`、`/insights` 和 `/evidence` 生成，按级别排序。列表放在顶栏的铃铛里（6.3.2），每页都能打开；总览只用一行写明有几项，没有事项时写“一切正常”和最后检查时间。

| 条件 | 级别 | 文案示例 | 操作 |
|---|---|---|---|
| 没有在线网关 | 严重 | “没有在线的网关：最后一次心跳在 3 分钟前（edge-1）” | 查看系统 |
| 站点加载失败 | 严重 | “网关拒绝加载 shop：源站地址格式不正确” | 打开配置 |
| 新版本超过 30 秒仍有在线网关没加载 | 严重 | “emr v13 保存 2 分钟后仍有 1/2 个网关没加载（edge-2 停在 v12）” | 查看系统 |
| 时间范围内有日志缺口 | 严重 | “edge-1 有 37 条判定记录未写入（队列满），这段时间的请求可能查不到” | 查看缺口 |
| 队列压力下丢弃了绕过记录 | 提示 | “edge-1 在队列压力下丢弃了 1,204 条绕过记录（静态资源），判定记录不受影响” | 查看系统 |
| Jev 不可用 / 降级 | 严重 / 警告 | “Jev 最近 5 分钟失败 9 次（超时 7、模型服务限流 2）” | 查看 Jev |
| 观察模式站点有本应拦截 | 警告 | “juice 观察中 6 天：本应拦截 14 条（Jev 拒绝 11、无会话 3）” | 查看、就绪检查 |
| `on_jev_unavailable: allow` 且有未经判定 | 警告 | “shop 有 5 个请求未经判定就放行了” | 查看 |
| 有待处理的调优建议 | 提示 | “juice 有 2 条调优建议：登记入口 1、加入绕过 1” | 查看建议 |
| 某个判定参数的证据异常（超时占比 ≥ 1%、触发调用上限） | 提示 | “emr Jev 超时 3 次 / 412 次调用（p95 1.8 s，超时 3 s）” | 查看证据 |

- 指标卡：数值、与上一个同长时段的变化（可省略）、12 点迷你趋势。点击跳到按该条件筛选的请求追溯。“已判定请求”不含绕过、未知站点。
- 趋势图：每小时（时间范围 ≤ 6 小时时每 5 分钟）一根堆叠柱，三组：免调用放行（快速放行、缓存放行）、Jev 判定（Jev 通过、Jev 拒绝、Jev 不可用）、无会话。悬停显示该时段每个判定路径的计数；点击某一段跳到请求追溯并带上该时段和判定路径。右上角“以表格查看”切换为同样数据的表格。
- 站点卡：模式（观察模式显示已观察天数）、当前版本和生效状态、24 小时请求数和拦截或本应拦截数、待处理建议数。

**快捷筛选标签**。一行标签，每个带计数（`/api/requests/counts`，与当前其他条件联动）：已判定（默认，不含绕过和未知站点）、需要关注（拦截 + 本应拦截 + 未经判定）、拦截、本应拦截、未经判定、Jev 调用、无会话、绕过。标签互斥，选中的标签写入 URL `chip`，和条件语法同时生效。

**绕过和未知站点默认隐藏**。绕过请求通常占流量的大半（静态资源）；公网网关还会收到扫描器发来的任意 Host（未知站点）。它们都不是对某个站点的一次判定，默认不在列表里，计数也不含它们（API 的 `scope=judged`）。“□含绕过请求”打开后显示全部（`scope=all`）；“绕过”标签只看绕过；标签行末尾有一句小字“另有 N 条未知站点请求 · 查看”，点开按 `decision:unknown_site` 筛选。按请求 ID、会话标签或精确路径查找时自动包含，并在筛选栏提示“已包含绕过请求”，避免第四轮试跑那种“查不到”的情况（[04.5.4](04-deployment-testing.md#454-第四轮548-条记录)）。

**条件语法**。筛选框接受空格分隔的条件，同一键内用逗号表示“或”，不同键之间是“且”。输入时下拉提示键名和取值（取值来自 `ui/vocab.ts`）；“＋条件”按钮用菜单逐项添加，不需要记语法。语法错误的词加红色下划线并说明原因，修正前不发请求。

| 条件 | 例子 | 对应接口参数 |
|---|---|---|
| `outcome:` 结论 | `outcome:blocked,would_block` | `outcome` |
| `decision:` 判定路径 | `decision:jev_deny,no_session` | `decision_path` |
| `path:` 路径，`*` 结尾为前缀，匹配逻辑路径 | `path:/rest/basket/*`、`path:/weixin/*` | `path` |
| `api:` 接口名，子串匹配（区分大小写）；`unknown` 查取不到接口名的请求 | `api:saveBuriedPointList`、`api:unknown` | `api`、`api_unknown` |
| `object:` 类别：请求值里有这一类对象的请求 | `object:doctor` | `object` |
| `method:` | `method:POST` | `method` |
| `status:` 状态码或类别 | `status:4xx`、`status:413` | `status` |
| `session:` 会话标签 | `session:7c1e9a40d2b35f61` | `session` |
| `client:` 客户端 IP | `client:192.168.1.20` | `client` |
| `id:` 请求 ID | `id:req_01a19741107477ff9224781077354552` | `request_id` |
| `access:` / `attack:` Jev 回答 | `access:DENY`、`attack:ATTACK` | `jev_access` / `jev_attack` |
| `failure:` Jev 失败码 | `failure:JEV_TIMEOUT` | `jev_failure` |

| `site:` | `site:juice` | `site`（与顶栏站点范围同步） |
| 不带键的词 | `/rest/basket/6`、`req_…`、`7c1e9a40d2b35f61`、`GET` | 按形状识别为路径、请求 ID、会话或方法 |

`path:` 匹配的是逻辑路径。没有接口名规则的站点与现在完全相同；逻辑路径以真实路径开头，所以前缀筛选照常可用。`api:` 只看接口名，`object:` 只看请求值的类别（6.4.4 的“类别”列）。

`filter-dsl.ts` 负责解析和序列化，二者往返一致（[07.10.8](07-console-architecture.md#7108-测试)）。

**列表列**。默认列：时间、站点（选了单个站点时隐藏）、方法、路径、状态、判定、结论、Jev、耗时、请求 ID。列选择器可加：会话、上下文类型、客户端、Host、配置版本、查询串、网关实例。列设置记在 `localStorage`。

- 时间：本地时区 `HH:mm:ss.SSS`，时间范围超过 24 小时时加日期；悬停显示本地和 UTC 的完整时间。
- 路径：等宽字体，过长时中间省略（保留开头和结尾），查询串以浅色跟在后面；悬停显示完整路径和脱敏后的查询串。站点有接口名规则（6.4.9）时，这一列显示逻辑路径：规则取到的接口名接在真实路径后面，接口名前面用 `›` 分隔，并用次要文字色，例如 `/weixin/…/gateway › bus.buriedPointService/saveBuriedPointList`；悬停说明接口名来自哪里（“接口名来自请求头 X-Service-Id、X-Service-Method”）。取不到接口名的写 `/weixin/…/gateway › 未知接口`。
- 判定：图标 + 简称（6.6.1）；结论：状态标签（6.5.3）。
- Jev：有调用时显示结论方向和置信度（`jev_confidence`，两个回答最高概率中较小的一个）：“越权 86%”“攻击 88%”“放行 97%”“不确定 55%”；置信度低于 70% 的后面加“低”标记；失败时显示失败简称（“超时”“达到上限”）。
- 请求 ID：显示末 8 位（前 12 位是时间戳，同一时段的请求前缀相同，末尾才好区分），悬停显示全文和复制按钮。

**行的交互**。单击选中并打开预览面板；双击或回车打开详情；鼠标悬停 150 ms 预取详情；行末“⋯”菜单和右键菜单：复制请求 ID、复制详情链接、打开会话时间线、只看这个会话、只看这个路径、登记为入口（无会话的行）、加入绕过（像静态资源的行和 413 的行）。菜单里的点击只作用于菜单项；点在菜单空白处、或按下与抬起分在两项上，都不选中背后的行，也不打开预览或详情。

**预览面板**。右侧 400 px（窄屏为覆盖式抽屉），内容来自详情接口：请求行、结论和判定路径、一句话解释（6.4.4）、需核验的值（最多 5 个，带来源链接）、会话（标签、已存在时长）、耗时分解；Jev 记录另有两个问题的概率条。底部：打开详情、会话时间线、复制 ID。`j`/`k` 切换行时预览跟随，面板顶部有“固定”按钮可在浏览时保留当前记录作对比。

**实时模式**。“⟳实时”打开后时间范围变为“最近 10 分钟并持续更新”，每 2 秒重新拉取最近的行（回看 60 秒，按请求 ID 去重，原因见 [07.9.3](07-console-architecture.md#793-请求列表)），新行插到顶部并高亮 2 秒后淡出。用户已向下滚动或选中了某行时不跳动，顶部出现“↑ 12 条新请求”，点击回到顶部。每 2 秒返回满 200 行时提示“新请求太多，实时模式只显示最新 200 条，请增加筛选条件”。10 分钟无操作自动暂停，提示“实时模式已暂停（10 分钟无操作）· 继续”。新行到达通过 `aria-live="polite"` 播报数量。慢响应的记录要等响应结束才写入，所以可能晚几秒出现，行内的时间是请求到达的时间。

**分页**。按时间倒序，滚动到底自动加载下一页（游标分页）；列表最多保留 2000 行，超过时提示“已显示 2000 条，请缩小时间范围或增加条件”。

**日志缺口提示**。当前时间范围内网关报告过丢失记录时，列表上方显示琥珀色提示条：“21:02–21:05 edge-1 有 37 条记录未写入（队列满），这段时间的请求可能查不到 · 查看系统”。数据来自网关心跳里的缺口历史（[07.7.4](07-console-architecture.md#774-日志发送)）。条数是队列满时丢弃的与写入失败丢失的之和（`dropped + write_errors`），括号里写原因：“队列满”“写入失败”，两者都有时写“队列满、写入失败”。只丢了绕过记录（队列压力下主动丢弃）时提示条是灰色的：“edge-1 在 21:02–21:05 丢弃了 1,204 条绕过记录，判定记录不受影响”。网关重启会清空缺口历史，所以重启之前的缺口看不到；提示条下方的小字写明这一点。

**批量对照**。页面右上角“批量对照”或在命令面板粘贴多个 ID 时打开，全屏对话框：

**头部**：请求行（方法、路径；查询串另起一行，脱敏处显示为带斜纹底的 `已脱敏 · 12 字符`）、路径有接口名规则时的“接口”行（见下）、结论标签和判定路径、一句话解释、时间（本地与 UTC）、状态码、耗时分解、配置版本（链接到变更历史里的该版本）、网关实例、会话（链接到时间线并定位到本请求）、客户端。`[` / `]` 在同一会话里前后移动。

“接口”行写出接口名和来源，例如“接口 bus.buriedPointService/saveBuriedPointList · 来自请求头”；取不到时写原因，例如“未知接口：X-Service-Method 出现了 2 次，按未知接口处理（不算入口、不走绕过）”。

**一句话解释**（`explain.ts`，纯函数）由“原因”和“处理”两部分拼成。原因按判定路径选模板，值、字段、请求用记录里的内容填充（值超过 24 个字符时截断）：

| 判定路径 | 原因模板 |
|---|---|
| `bypass` | 命中绕过规则 `{bypass}`，没有判定，直接转发。 |
| `unknown_site` | Host `{host}` 不属于任何站点。 |
| `body_not_inspectable` | 请求体超过 48 KiB 判定上限或没有 Content-Length，无法判定。需要上传大文件的接口可以加入绕过，但绕过后不做越权判定。 |
| `no_session` | 请求没有会话凭证（{Cookie / 请求头} `{name}`），路径也不是入口。 |
| `fast_allow` | {N} 个需核验的值都已核验，没有调用 Jev。（没有需核验的值时：请求里没有需要核验的值，没有调用 Jev。） |
| `fast_allow`，用到对象表 | {N} 个需核验的值都已核验（按对象表：{类别}），没有调用 Jev。 |
| `cached_allow` | 同一会话 {M} 分钟前的相同请求已由 Jev 放行（{来源请求}），在缓存时长 {T} 分钟内直接复用。 |
| `jev_allow` | {N} 个值未核验（{值列表}），Jev 判定访问有依据（ALLOW {p}%）、内容无攻击（BENIGN {p}%）。 |
| `jev_deny`，access 为 DENY | Jev 判定越权（DENY {p}%）：{位置}里的 {值} 在这个会话里{从未出现过 / 没有以同类对象出现过，只以 {字段} 出现在 {请求} 的响应里}。 |
| `jev_deny`，access 为 DENY，两边类别不同 | Jev 判定越权（DENY {p}%）：{位置}里的 {值} 在这个会话里只以{文档}出现过，现在用作{医生}。 |
| `jev_deny`，attack 为 ATTACK | Jev 判定为攻击（ATTACK {p}%）：{位置} 的值含 `{值}`。 |
| `jev_unavailable` | 按失败码：Jev 调用超时（{timeout_ms} ms，{站点设置 / 默认值}）；本{会话 / 地址}每分钟 Jev 调用已达上限 {n} 次，没有调用 Jev；Jev 答不上来（UNKNOWN {p}%）；模型服务返回 {http_status}；Jev 响应格式不符合约定；上下文裁剪后仍超过 8 KiB，没有调用 Jev。 |

处理部分按结论和模式追加：拦截“返回 {status}。”；本应拦截“站点处于观察模式，请求照常转发。”；未经判定“站点设置为 Jev 不可用时放行，这个请求没有经过判定。”；放行不追加。源站出错时再加“源站{连接被拒绝 / 连接超时 / 读取超时 / TLS 握手失败}，网关返回 {status}。”。旧格式记录（`trace.v == 0`）只说结论，并在头部显示“旧格式记录：没有判定依据”。

**标签 1：判定过程**。顶部一条**耗时瀑布条**，下面按 [01.4](01-request-flow.md#14-判定步骤) 的步骤画成竖向步骤条。

- 来源标签末尾加上来源位置的类别。两边类别不同时，在这个值的那一行用 `!` 写“类别不同：文档 ≠ 医生”，这正是 Jev 判越权的依据。
- 用作接口名的值，类别显示为“接口名”，不参与核验，归入折叠的惰性值一行。
- 复合值（一个值里装了几段）的父行写出拆法，每段一行（`位置#段号`），各段分别核验；拆法见 6.4.10 的“格式”。

- 惰性值默认折叠为一行“另有 12 个惰性值（路由词、分页参数）· 显示”，展开后置灰显示。
- 需核验而未核验的值左侧加琥珀色竖条，这些就是交给 Jev 的值；“只看需核验的值”开关。
- 来源：最多 3 个来源标签，格式“`quantity` · GET /rest/basket/1”，点击打开来源请求，悬停显示来源请求的摘要（来自详情接口的 `sources`）。没有请求 ID 的来源（只出现在导入的旧格式记录和测试数据里，网关重启会清空上下文）标签不可点，悬停说明“这条来源没有记录请求 ID”；来源请求已过保留期的显示“已过保留期”。同一字段、同一请求再次返回同一个值时不更新来源，所以标签表示“首次学到”（[07.7.1](07-console-architecture.md#771-会话上下文增加请求-id)）。
- 值的展示：等宽字体；超过 256 字符的截断值标“已截断 · 原长 1,024”；脱敏值显示带斜纹底的 `已脱敏 · 12 字符`，悬停说明命中的词（“字段名含 password（内置）”或“字段名含 ssn（本站点追加）”）。

**值的标注**（W5）。值来自公共响应、而请求位置不接受公共来源时，这个值的那一行标“尝试越权”，说明它是交给 Jev 判定的尝试，而不是普通的放行；观察模式下请求照常转发，只记录这一标记。值的来源标签末尾附上来源位置的归属与可靠性。

**标签 3：Jev 上下文**。见 6.4.5。没有调用 Jev 时标签显示“未调用”并说明原因（快速放行、缓存、无会话等），限额用尽、上下文过大时说明“这次没有发出调用”。

**标签 4：会话上下文**。判定时会话的摘要（源站声明了会话身份时另有一行“会话身份”，列出用户、机构与角色的标签，用户与机构只存键控哈希）：已存在时长、已见值数量、经过的入口（每条带首次经过的请求链接）、最近访问（Jev 记录才有，最多 10 条，每条链接到请求）。非 Jev 记录写明“最近访问只在调用 Jev 的记录里保存；完整顺序见会话时间线”。底部“打开会话时间线（定位到本请求）”。

**标签 5：原始记录**。完整记录的 JSON 树（`summary`、`trace`、`jev`），可折叠、可搜索、可复制某个节点的路径和值；“复制 JSON”复制整条记录。

**右侧“相关”栏**：

- 值的来源：所有来源请求（去重），每条显示方法、路径、判定路径。
- 缓存来源（缓存放行时）、签发的会话（登录请求）、签发本会话的登录请求。
- 同一会话：前一个、后一个请求。
- 同路径 24 小时：按结论计数，点击跳到按该路径筛选的请求追溯。
- 操作，按记录类型出现：登记为入口…（无会话）、加入绕过…（静态资源、413）、调整 Jev 超时…（`JEV_TIMEOUT`）、调整调用上限…（`JEV_CALL_LIMIT`）、加为脱敏词…（值的字段名像敏感个人信息）、把这个字段归类…（值未核验，且来源字段名与路径的类别不同）、为这条路径写接口名规则…（路径是某条规则的前缀，或命中“可能是统一网关”的建议）、在配置中打开、复制链接。前五项打开 6.4.11 的快捷规则对话框；“把这个字段归类…”打开声明字段归类对话框（6.4.10）；“为这条路径写接口名规则…”打开 6.4.9 的接口名规则，路径预填为这条路径。

**回答区**。每个问题一根分段条（高 28 px，6.5.4）：三段依次是“通过”选项（ALLOW / BENIGN）、“不通过”选项（DENY / ATTACK）、UNKNOWN，宽度按概率；放得下时在段内写百分比，放不下的只在悬停和表格视图里显示。条右侧写出该问题的结论（“→ 越权”）。下面一行写 Jev 的最终结论（按 [02.3](02-jev.md#23-结论规则)：拒绝、通过、无法判定）和置信度，置信度低于 70% 时加“置信度低”提示；同一行右侧写**这个结论在网关那里变成了什么**（“已拦截，返回 403”“本站点在观察模式：本应拦截，请求已照常转发”“Jev 不可用，按站点设置放行”）。“Jev 拒绝”是 Jev 的回答，“拦截”“本应拦截”是网关的动作，两者要分开写，否则观察模式下会误以为请求被拦了。概率显示为整数百分比，悬停显示原始值（0.8612）。

**元信息**（回答区下面两行）：模型、线路（经 AI Gateway / 直连 TypeSafe / 自定义地址）、指令版本（点击进入指令视图）、`usage` 里的 token 数；**耗时条**：本次耗时占所用超时的比例，注明超时来自站点设置还是默认值，接近超时（≥ 80%）时条变琥珀色；**state 体积条**：已用字节占 8 KiB 的比例，裁剪级别非 0 时写明“为满足 8 KiB 上限，最近访问从 10 条减到 3 条”这类说明（[07.5.3](07-console-architecture.md#753-裁剪级别)）。完整请求体字节数在悬停里。

**失败的调用**。回答区换成失败卡片：失败码的中文名和说明（6.6.4）、HTTP 状态、这次的处理（服务故障按 `on_jev_unavailable`；`JEV_CALL_LIMIT` 回 429，`JEV_STATE_TOO_LARGE` 回 403，都不论 `on_jev_unavailable`）；有原始响应时显示前 8 KiB。`JEV_CALL_LIMIT`、`JEV_STATE_TOO_LARGE` 没有发出调用，卡片写明原因并链接到站点的高级判定参数，下面的视图区不显示。

**四种视图**（`v` 键循环切换，选择写入 URL `jev_view`）：

**值的判读提示**。结构化视图里每个值按 `trace.values[]` 给出一条提示，用来替人快速找到“缺少佐证”的值。提示是网关根据自己的记录判读的，**不是 Jev 的推理**：Jev 只给出概率，界面不编造理由。

| 提示 | 条件 | 标记与颜色 |
|---|---|---|
| 已核验 | `verified` 为真：网关已用响应核验过这是同类对象 | ✓ 绿 |
| 输入内容，不需要见过 | `kind == input` 且未核验 | – 灰 |
| 路由词 | `kind == route` | – 灰 |
| 只以别的类别出现过（写成“值只以文档出现过，现在用作医生”） | `kind == reference`，`seen` 为真，未核验，两边类别都能取到且不同 | ! 琥珀 |
| 见过，但不是同类对象 | `kind == reference`，`seen` 为真，未核验 | ! 琥珀 |
| 从未见过 | `kind == reference`，`seen` 为假 | ✕ 红 |

没有核验或缺少佐证的值卡片左侧带竖条并默认展开，其余值折叠成一行；值超过 8 个时，已核验和输入类合并为“另有 14 个值无异常 · 展开”。

- 搜索框在当前视图里高亮匹配（只切分文本节点），回车跳到下一处，显示“3 / 7”。
- 从“请求值”标签点 Jev 序号进来时，对应值滚动到视野内并高亮 2 秒；结构化视图里悬停一个值，同时显示它在 `trace.values` 里的位置和来源。
- “复制 state”复制原文；“复制完整请求体”复制还原后的请求体（不含密钥和请求头）。每个值卡片和每个来源标签都有单独的复制按钮。
- `state` 每批最大 8 KiB；请求分成几批送判时，Jev 视图上方写明“第 k 批，共 N 批”，本批的值与追溯信息不对应，来源链接不可用（[7.5.2](07-console-architecture.md#752-state-与追溯信息的对齐)）。超过 16 批的上限、有值或片段没有送判时，另写“攻击判定不完整：有 N 个值或片段没有送判”（[02](02-jev.md) 2.5）。四种视图都一次性渲染（JSON 树至多几百个节点），不做虚拟滚动；切换视图只切换显示，不重新请求。

### 6.4.8 站点列表与接入向导

**站点列表**：每个站点一行：名称、Host、源站、模式（观察模式显示“观察 6 天”）、版本和生效进度（“● v12 · 2/2 个网关已生效”“◌ v13 · 1/2 个网关已生效”“✕ 加载失败：源站地址格式不正确”“没有在线的网关”，进度来自 [07.9.13](07-console-architecture.md#7913-状态灯与配置生效) 的 `rollout`）、24 小时请求数、拦截或本应拦截数、Jev 调用数、待处理建议数。右上角“新建站点”。

**新建站点**（`/sites/new`）。P0 是单页：左边表单（基本信息、会话凭证、入口、绕过，与 6.4.9 的编辑器相同），右边实时生成的 YAML，另有“从 YAML 创建”直接粘贴；高级判定参数创建后再调。表单创建的站点一律从观察模式开始；从 YAML 创建时 `mode` 取 YAML 里的值（缺省 `observe`），写成 `enforce` 时创建后提示“新站点没有观察期，入口和绕过设错会直接拦截正常请求”，不阻止。**接入向导**（P1）是同样字段的分步版本，四步，右侧始终显示实时生成的 YAML：

| 步骤 | 内容 | 校验与提示 |
|---|---|---|
| 1 基本信息 | 站点名（小写字母、数字、`-`、`_`，最长 64）、Host（标签输入，最多 16 个）、源站地址（`http(s)://主机[:端口]`） | Host 被其他站点占用时立即提示（`SITE_HOST_TAKEN`，调用校验接口） |
| 2 会话凭证 | Cookie 或请求头，二选一，加名称；常用名称做成可点的标签：`JSESSIONID`、`SESSIONID`、`connect.sid`、`token`、`Authorization` | 说明“登录后浏览器每次都带给源站的那个凭证” |

第 1 步另有“粘贴已有配置”：粘贴 YAML 或 JSON，校验后直接跳到第 4 步。创建后进入站点详情，顶部提示“已创建 v1 · ● 已生效”和下一步：“把 Host 解析到网关”“用浏览器走一遍正常流程，再回来看请求追溯”。

**规则测试**（`RouteRuleTester`）：粘贴的请求只在浏览器里解析，不上传，也不存进草稿。解析前先隐藏 `Cookie`、`Authorization` 和名字里含 token 的头的值，结果底部写明隐藏了几个凭证值。逻辑路径的计算与网关共用测试用例（同 `lib/site-validate.ts` 的做法，见 6.6.5）。

提示与警告：

- **单位置提示**（`!`，中性符号）：每一段都只写了一个位置时显示上面的提示，可以点“我确认源站只认这里”关掉，记在草稿里。
- **入口不再命中**：规则生效后，这条路径下的请求按逻辑路径匹配入口和绕过。现有的 `/weixin/…/gateway` 这类精确入口不会再命中任何请求，提示“改写为逻辑路径”，并给出按接口名补全的候选（来自最近的记录）。
- **预估的局限**：过去的判定记录没有保存请求头，来源是请求头的规则无法按历史预估接口拆分，提示“保存后开始按接口统计”；来源是查询参数或正文字段的规则可以按历史预估。

- **入口、绕过**（`PatternListEditor`）：每行一条规则，显示 24 小时命中数和最近命中时间（打开配置时用当前配置调用一次影响预估接口取 `patterns`）；0 命中的规则标“24 小时未命中”。规则本地即时校验（6.6.5）；`/*`、`/api/*` 这类很宽的入口提示“前缀入口会放大无会话可达的范围”；绕过规则命中过已判定的接口时提示“这条绕过会让 N 个原本判定的请求不再判定，其中本应拦截 M 个”。入口和绕过的编辑器在有接口名规则的路径下输入时，按最近记录补全逻辑路径，例如输入 `/weixin/…/gateway/` 后列出 `bus.buriedPointService/saveBuriedPointList · 24 小时 8,016 次`。
- **规则测试器**（`PatternTester`）：输入一个路径，或粘贴一个完整的 HTTP 请求（只在浏览器里解析，不上传）。只有路径时用 URL 路径；粘贴完整请求时先算出逻辑路径再匹配。按草稿显示结果：命中哪条入口或绕过、或“需要会话”；路径含 `;`、`//`、`%2e`、`%2f` 等时说明“网关不会把这种写法的路径匹配到任何入口或绕过”（与 `PathPattern` 规则一致，共用测试用例）。
- **模式与 Jev 不可用**：模式只读显示，旁边“切换…”按钮进入 6.4.11 的流程；`on_jev_unavailable` 单选：拒绝（推荐）/ 放行；选放行时提示“Jev 不可用时请求不经判定直接放行，记录标为‘未经判定’；调用次数达到上限的请求仍然拒绝（429）”。

- 每项旁边有“?”，展开 [07.6.1](07-console-architecture.md#761-字段) 表里“调整的代价”的文字（来自 `ui/vocab.ts`）。
- 改动后 600 ms 内调用影响预估接口，结果写在该项下方（“改为 1000 ms：过去 24 小时有 31 次调用会超时”）；保存对话框里汇总所有改动的影响。
- 证据在展开分组时才请求（`/api/sites/{name}/evidence`），没有数据时写“最近 24 小时没有 Jev 调用”。
- 同义词每组旁有“改写成字段归类…”（6.4.10）。同义词里的词也出现在站点路径里（例如 `/api/docs`）时，组标题旁显示“会让路径里的 docs 也算成 doctor”。

**YAML 编辑**。CodeMirror 编辑器（懒加载），带行号、语法高亮、错误标记；顶部切换 YAML / JSON；提示“YAML 只是编辑格式，保存的是 JSON，注释不会保留”。从 YAML 切回表单前必须能解析且通过本地校验，否则提示“YAML 第 12 行有错误，修好后才能切回表单”。未知字段（例如拼错的键）按错误处理，指出行号；字段类型不对也一样：Host、入口、绕过要写成文本列表，名称、源站、模式要写成文本，写成数字、嵌套列表、单个文本（`hosts: a.example.com`）或写了键却留空（`hosts:`）都报错并指出行号，纯数字的值要加引号，缺少必填字段也报到该字段上。只有 `advanced` 和它下面的参数可以留空。`routes`（接口名规则）和 `objects`（对象表，含学习设置）两段可以不写：不写时分别是没有接口名规则、没有对象表，学习设置取默认值。整段粘贴可以替换全部内容。新增的两段与其他段沿用同样的保存、校验和版本流程。

**保存对话框**（⌘S 或“预估影响并保存”）：

```text
┌ 保存 juice 的配置 ─────────────────────────────────────────────────────────────────────┐
│ 改动  入口 ＋1：/rest/admin/application-configuration                                  │
│       Jev 超时  默认 → 3000 ms                                                         │
│       差异 ▾（YAML 逐行差异，并排 / 合并切换）                                          │
│ 影响（按最近 24 小时 548 条记录估算）                                                   │
│   ▸ 312 个无会话请求改为按入口判定        GET /rest/admin/application-configuration 312 │
│   ▸ 3 次超时的 Jev 调用可能不再超时                                                     │
│   ▲ 同义词改变无法预估                                                                  │
│ 备注（可选）[ 从请求 req_…0c41d2e9 登记入口                                     ]       │
│                                                       取消      保存为 v8              │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

1. 本地校验，有错误时定位到出错的字段，不打开对话框。
2. 服务端校验（`POST /api/sites/validate`），返回的错误码映射为 6.6.5 的文案。
3. 改动摘要（语义级：哪个字段从什么变成什么）和 YAML 逐行差异（只生成文本节点）。
4. 影响预估（[07.9.10](07-console-architecture.md#7910-影响预估)）：每类变化一张卡片，写数量和最多 3 个路径，点击展开示例请求；警告单列。统计不完整时写“按前 N 条记录计算”。
5. 备注（最多 500 字），从请求发起的快捷操作会预填来源请求 ID。
6. “保存为 v8”。返回 409 `VERSION_CONFLICT` 时提示“配置已被修改（当前 v9）”，提供“查看 v9 的改动”和“在 v9 基础上重新应用我的改动”（把草稿的语义改动重放到新版本上，冲突的字段让用户选）。

影响预估的类型见下表。

| 影响 | 写法 | 可否从历史预估 |
|---|---|---|
| 按接口拆分（`api_split`） | “这条路径下 9,812 个请求将按 37 个接口分别判定” | 来源是查询参数、正文字段时可以；来源是请求头时写“保存后开始统计” |
| 入口不再命中（`entry_unreachable`） | “入口 /weixin/…/gateway 将不再命中任何请求（N 个原本放行的无会话请求将需要会话）” | 可以 |
| 新增快速放行（`new_fast_allow`） | “158 次 Jev 调用会变成快速放行”，附示例请求 | 可以，按记录里的来源近似估算 |
| 改回 Jev（`back_to_jev`） | “14 次快速放行会改回调用 Jev”，附示例请求，并说明“这些请求原本靠名字把医生编号当成了文档编号” | 可以 |
| 缓存按接口区分（`cache_by_api`） | “同一会话里参数相同的不同接口不再共用放行结论” | 只提示，不计数 |

统计不完整时沿用“按前 N 条记录计算”。近似估算的影响旁注明“来源只记录了前 3 个，结果是近似值”。按接口拆分（`api_split`）、入口不再命中（`entry_unreachable`）和缓存按接口区分（`cache_by_api`）的数字同样是估算，后端对它们标注 `approximate`（`detail.approximate: true`），控制台旁注同一句。接口名没有在历史里核对过时，影响预估还会带上警示码 `INTERFACE_UNVERIFIED`，提示“接口名没有在历史里核对过，按接口和前缀入口的数字可能不完整”。

**保存后的生效状态**。顶部提示“已保存 v8 · 等待网关加载…”，每秒轮询 `rollout`：加载中显示“1/2 个网关已加载 v8”，全部在线网关加载后变为“● v8 已生效（2/2 个网关，2.1 秒）”。30 秒内未全部生效时变为琥珀色“edge-2 还没有加载 v8（停在 v7）”并链接到系统页；网关报告加载失败时显示该实例的错误码文案；没有在线网关时写“没有在线的网关，配置已保存，网关上线后加载”。离线实例不计入进度，另注“edge-3 离线”。

**调优建议**（P1）。按类型分组的建议卡片（[07.9.11](07-console-architecture.md#7911-调优建议与就绪检查)）：

```text
┌ 登记入口 /rest/admin/application-configuration ───────────────────── 312 次 · 最近 21:16 ┐
│ 未登录时前端就会请求这个接口，目前全部按“无会话”记为本应拦截。                            │
│ 改动：entries ＋ /rest/admin/application-configuration                                  │
│ 示例请求 …0c41d2e9                                          忽略    加入草稿    应用…     │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- “应用…”直接打开保存对话框（带该改动和影响预估），确认即保存；“加入草稿”把改动加进当前草稿，适合一次处理多条；“忽略”只记在浏览器里，可在列表底部“已忽略 3 条 · 显示”找回。
- 前缀类建议（同一父路径下 3 个以上）同时给出精确路径和前缀两个选项，并提示前缀的代价；`upload_candidate` 提示“绕过后该接口不做越权判定”；`hot_would_block` 只有“查看请求”。
- 观察模式的站点在顶部显示就绪检查摘要（6.4.11）。

两类新建议（代码名见 6.6.4）：

| 类型 | 卡片内容 | 操作 |
|---|---|---|
| 对象表待确认（`object_proposals`） | “对象表有 7 条待确认，确认后预计每天少调用 Jev 1,240 次”，列出影响最大的 3 条；完整队列在对象表（6.4.10） | 前往对象表；单条可直接“确认…” |
| 可能是统一网关（`route_rule_candidate`） | “/weixin/…/gateway 占本站点 92% 的请求，正文字段 `method` 有 37 种取值”。来源是请求头时，网关要先记录请求头名（数据要求见 [07](07-console-architecture.md)），之前只覆盖查询参数和正文字段来源 | 写接口名规则…（预填路径和来源） |

**变更历史**：

- 版本列表：版本号、时间、类型（创建、修改、回滚、删除、导入、自动收紧、自动暂停）、备注、自动摘要（“入口 ＋1，Jev 超时 默认 → 3000 ms”）、是否为当前生效版本。
- **自动收紧**、**自动暂停**：学习任务写入的版本，作者显示为“学习任务”。摘要写明改了什么，例如“自动收紧：响应 GET /api/records/{id} attachments[].doc_id 从医生改为文档”。这两类版本多一个操作“撤销…”，走回滚对话框，备注预填原因。
- 选两个版本比较差异（URL `diff=5..8`）；每个版本可“查看全文”“以此版本回滚…”“查看用此版本判定的请求”（跳到请求追溯，条件 `version:5`）。“查看全文”在该版本的行下方展开一行，占满表格宽度，YAML 逐行显示、不换行，过长时横向滚动；行内只放摘要，三个操作各占固定的列，同一操作在各行对齐。
- 回滚对话框与保存对话框相同：差异（当前 → 目标）、影响预估、备注，按钮写“回滚，生成 v9（内容同 v5）”。

### 6.4.10 站点详情 · 对象表

对象表是站点详情的第三个标签（`tab=objects`，`ObjectsTab`）。它回答两件事：站点里每个位置的值属于哪一类对象（医生、文档、患者……），以及哪些位置还在等人确认。“位置”“类别”等词的说明见 6.6.7。背景：接口名规则、字段归类和对象表的判定思路见设计笔记 header-routes-design、field-kinds-design、object-map-design（不在本仓库里）。

```text
 概览   配置   对象表 7   调优建议 3   变更历史                                           学习设置 ⚙
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ ▲ 1 个位置已自动暂停：GET /doctor/{id} 的 path[1]                                                │
│    快速放行后源站 404 比例从 1% 升到 18% · 查看                                                  │
│ 学习任务 14:00 自动收紧了 2 个位置 · 查看 · 撤销                                                 │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 类别 12 │ 已确认 86 │ 待确认 7 │ 有歧义 3 │ 已暂停 1 │ 学习中 41          ⌕ 搜索类别、字段、路径 │
│ 视图  ● 按类别  ○ 按位置                                         ＋ 声明字段归类   从同义词改写… │
├──────────────────────────┬───────────────────────────────────────────────────────────────────────┤
│ 医生 doctor     14 位置  │ 医生  doctor                                   改名 · 合并到… · 拆分… │

│ 患者 patient    21 位置  │ 常见字段  name · title · department                                   │
│ 预约 appointment 8 位置  │ 相关路由  /doctor/{id} · /api/doctors/{id}/files/{id}（path[2]）      │
│ ……                       │                                                                       │
│                          │ 位置                           状态   来源   依据            最近     │
│                          │ 响应 GET /api/doctors [].id    已确认 规则   名字明确        21:16    │
│                          │ 响应 GET /api/appointments     待确认 规则   流向 87%        21:15    │
│                          │   [].doc_id                                                           │
│                          │ 请求 GET /doctor/{id} path[1]  已暂停 管理员 404 比例异常    21:10    │
└──────────────────────────┴───────────────────────────────────────────────────────────────────────┘
```

- 顶部横幅只放需要人处理的事：自动暂停（▲，警告色）、自动收紧（中性，可撤销）。没有时不显示。
- 计数标签互斥，选中写入 URL `state`，与搜索框同时生效。“类别”标签的数字是类别数，其余标签的数字是位置数。视图、选中的类别和打开的位置也都在 URL 里（6.2.2）。
- **按类别**（`ObjectClassList`、`ObjectClassCard`）：左侧类别列表（名称、id、位置数、24 小时使用次数），右侧类别卡片和它的位置表。类别 id 创建后不变，改名只改名称。
- **按位置**（`SlotTable`）：一张表，列为位置（一侧的标记、逻辑路径、字段路径或参数）、类别与状态、来源（管理员声明 / 规则 / agent）、依据摘要、最近出现。单击行在右侧打开位置抽屉，`j`/`k` 逐条浏览，与请求追溯的预览面板一致。

**判断**（W5）。位置行的类别与状态列下多一行小字，写明它的判断，例如“归属 公共 · 可靠性 高”、“身份 用户”或“不接受公共来源 · 可靠性 高”。对象表上方的**判断提议**卡片列出学习提出、还在等确认的判断，每条写明位置、判断与依据（票数、会话数与公共票占比；或单位数、不同值数与一致份额）。“确认…”打开确认框，确认后站点保存一个新版本，判定开始使用它；草稿里有未保存的改动时“确认”暂不可用，先保存或放弃。“驳回”让同一判断不再提议，除非规则转到另一个判断。

位置抽屉里的“判断”一节可直接编辑：响应位置选身份（用户、机构、角色）或归属（自身、机构、管理、公共），请求位置选是否接受公共来源；可靠性只在有归属或接受公共来源时可选，有身份的位置不带归属。“应用到草稿…”把改动记入草稿，保存对话框列为“判断 无 → 归属 公共 · 可靠性 高”这样的一行。暂停中的位置保留判断但不使用。

**位置抽屉**（`SlotDrawer`）。单击位置打开抽屉，内容是这个位置的全部证据：

```text
┌ 响应 GET /api/appointments  [].doc_id ────────────────────────────────────────── 待确认 · 规则 ┐
│ 提议：医生 doctor                                                                              │
│ 依据  这个位置的值之后用在：                                                                   │
│   GET /doctor/{id} path[1]          87%   140 次   23 个会话   Jev 通过 140 · 拒绝 0           │
│   GET /api/schedule query.doc       11%    18 次    6 个会话   Jev 通过 18 · 拒绝 0            │
│   示例请求 …77354552 · …e3a1b2c4 · …0c41d2e9                                                   │
│ 响应结构（不含值）  [].id:number  [].doc_id:number  [].doc_name:string  [].slot:string         │
│ 影响  过去 7 天 158 次 Jev 调用会变成快速放行                                                  │
│       14 次快速放行会改回 Jev（/docs/{id}）                                                    │
│       改回 Jev 的这些请求原本把医生编号当成了文档编号 · 查看                                   │
│ 范围  仅 /api/appointments*（证据里的接口） · 放宽…                                            │
│ 历史  10-31 规则提议 · 11-01 证据更新                                                          │
│                                                      标为有歧义   改为其他类别…   忽略   确认… │
└────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 依据一节按位置的一侧显示“之后用在”（响应位置）或“之前出现在”（请求位置），每行可点，跳到按这个组合筛选的请求追溯（6.4.3）。
- 响应结构只显示字段路径和类型，从不显示值。
- agent 给出的提议多一节“agent 结论”：选择、置信度、引用的依据（`f1`、响应结构，点击高亮对应的行）、理由。理由是模型输出，按不可信文本只渲染文本节点。
- **复合值**（位置带格式时）多一节“格式”：值按分隔符拆成几段，每段是一个子位置，各有自己的类别。拆法在 6.4.4 的请求值表里逐行显示。

```text
 格式  按 # 拆成 3 段（98% 的值符合）
   第 1 段 字母 2–20 位    输入：姓名
   第 2 段 数字 11 位      输入：手机号（按身份信息查找）
   第 3 段 数字 1–6 位     患者 patient · 流向 92% · 已确认
   不符合格式的 2% 整体交给 Jev · 查看
```

- **按条件取类别**（位置带条件时）多一节“条件”：`由 query.by 决定：id 为患者；phone、name 为输入（按身份信息查找）`；按形状判断的写成 `按值的形状：短数字为患者，11 位数字为手机号`，形状重叠的部分标“有歧义，交给 Jev”。
- 操作：
  - **确认…**：打开保存对话框（6.4.9），改动写成“对象表 ＋ 响应 GET /api/appointments [].doc_id 归为医生（仅 /api/appointments*）”，影响按 6.4.9 的影响类型列出。站点处于拦截模式、并且会新增快速放行时，必须勾选“我已查看示例请求”才能保存。
  - **改为其他类别…**：选择已有类别或新建，同样走保存对话框。
  - **标为有歧义**：这个位置永久交给 Jev，学习不再提议。
  - **忽略**：记在服务端，学习任务不再提议同一结论；证据发生明显变化后重新提议。与调优建议的“忽略”不同，后者只存在浏览器里。
  - “标为有歧义”和“忽略”是学习状态，不生成新版本，变更历史里看不到。

**声明字段归类**（`DeclareKindDialog`）。“＋ 声明字段归类”和请求详情里的“把这个字段归类…”（6.4.4）打开同一个对话框：

```text
┌ 声明字段归类 ──────────────────────────────────────────────────────────────────────────────────┐
│ 字段   [ doc_id ]        忽略大小写和 _、-：doc_id、docId、DocID 是同一个                      │

│ 范围   ● 仅这些接口  [ /api/appointments* ] ＋                                                 │
│        ○ 全站（站点里同名字段指两种东西时会错放行）                                            │
│ 会匹配 响应 GET /api/appointments [].doc_id · 请求 GET /api/schedule query.doc_id              │
│        另有 GET /api/records/{id} attachments[].doc_id 不在范围内（之后用在 /docs/{id}）       │
│                                                                   取消      预估影响并加入草稿 │
└────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 从请求详情发起时，范围默认填这次请求的接口；“会匹配”一栏按最近的记录列出命中和不命中的位置，不命中的同名字段用来提醒范围的意义。
- 选“全站”时，如果最近记录里同名字段流向两类以上的目标，选项旁显示警告，并列出这些目标。
- “预估影响并加入草稿”把声明放进草稿，影响在 6.4.9 的保存对话框里汇总。
- 声明写进 `advanced.field_kinds`（网关从 field-kinds 设计起读取的位置），不写进 `objects`。保存、YAML、比较和合并都按这个位置处理；高级判定参数的“全部恢复默认”只清掉判定参数，不清掉声明。

**从同义词改写**（`SynonymMigrateDialog`）。高级判定参数的同义词旁、以及对象表工具栏的“从同义词改写…”，打开同一个对话框：对每组同义词按最近记录列出它实际影响的位置，逐个选择“归为哪一类、限定在哪些接口”，生成字段归类声明，并删除这组同义词。

**学习设置**（`LearningSettings`）。“学习设置 ⚙”打开抽屉。设置属于站点配置，改动走保存对话框、产生版本（6.4.9）。学习设置存放在 `objects.learning`，取值等于默认值时不写入保存，所以不改学习设置的保存永远不会因为它被拒绝。网关接受 `objects.learning`（#124 合入之后）时，开关可以改，保存前检查范围：学习门槛 1 到 10000 次或会话，agent 每日上限 0 到 100000。`LEARNING_SAVE_READY` 为真；如果网关之后又拒绝这个键，把它改为假，抽屉会回到只读并显示说明。agent 开关在没有配置学习代理模型时不能打开（`AGENT_SAVE_READY` 为真；`agent_configured` 为假时开关置灰，写明“系统里还没有配置学习代理模型”并链接到模型配置）。已经打开的站点在模型之后被改坏时，开关保持打开、可以关掉，状态条和总览提示模型失败（`agent_health` 为 `failing`）。网关接受 `agent.enabled: true`；学习代理只由控制面的学习任务调用，控制面没有配置模型时位置等待，不会报错。学习设置里的“学习代理”一行按四种状态显示：没有模型、模型失败、有位置在等（可看发给它的内容）、已开启（每日上限与今天的用量）。对象表的学习状态条、运行记录抽屉、来源与代理筛选，以及位置抽屉里的“学习代理结论”，都在 `features/sites/objects` 里（设计第 3 节）。`objects` 段里网关的 `classes` 和 `slots` 原样保留，控制台不编辑它们。

| 项 | 控件 | 说明 |
|---|---|---|
| 自动学习 | 开 / 关 | 关闭后只用手工声明，已确认的位置照常生效 |
| 自动收紧 | 开 / 关（默认关） | 只会让快速放行变少的改动是否自动生效；关闭时不拆分类别 |
| agent | 开 / 关 + 每日调用上限 | 规则判不了的位置是否交给 agent；没有配置模型时置灰并说明 |
| 学习门槛 | 至少 N 次使用、M 个会话（默认 20、5） | 调低会更快学到，也更容易被少数会话影响 |
| 自动暂停 | 开（推荐）/ 关 | 已确认位置出现异常时自动暂停 |

**冷启动**（`ColdStartPanel`）。对象表为空时不显示空表格，而是下面的面板。候选来自最近 24 小时的请求；确认后它们作为学习的起点，其余位置照常判定。确认的每个位置都按位置键写进对象表（`objects.slots`，如 `GET /api/doctors [].id`），不写成字段归类；字段归类只由“高级”里手工声明。

```text
┌ 还没有对象表 ──────────────────────────────────────────────────────────────────────────────────┐
│ 从最近 24 小时的请求里识别出 9 个名字明确的类别。                                              │
│ 确认后它们作为学习的起点，其余位置照常判定。                                                   │
│  ☑ 医生 doctor     GET /api/doctors [].id · GET /doctor/{id} path[1]                           │
│  ☑ 患者 patient    GET /api/patients [].id · GET /api/patients/{id} path[2]                    │
│  ☐ 文档 doc        GET /api/docs [].id     ! 名字是缩写，建议改名为“文档 document”             │
│  ……                                                                                            │
│                                                                   稍后再说      确认 8 个类别… │
└────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- “稍后再说”关闭面板，对象表保持为空。
- “确认 8 个类别…”这类按钮打开保存对话框（6.4.9）。
- 接入向导的最后一步也放同样的列表，可以跳过（6.4.8）。
- 类别从名字来，数组名是父对象：`GET /api/patients/{id} prescriptions[].id` 的类别是处方，`GET /api/patients patients[].id` 是患者；顶层的 `[].id` 和对象顶层的 `id` 取接口名。`results`、`items`、`rows` 这类容器词下的 id 不取类别，它是哪一类要看流向，名字说不出。`query.q` 这类非标识符的查询词不取类别，`query.id`、`query.ids` 仍取路由词。路径里字面量的一段（如 `GET /share/SHR-9F2A path[1]`）只有一个值，不作候选。
- 核对用同一批请求的票：候选的类别与票里其他位置的类别相反，且相反的票超过可比较票的十分之一时，面板显示“与 X 冲突”，不预选，管理员可以改类别或不选。同一个数字分属两类（患者 3 与处方 3）时，只要票里有一个同类的来源，就不算冲突。
- 使用次数或会话数低于学习门槛（默认 20 次、5 个会话）的候选仍列出，标注“使用次数少，请确认”，不预选；名字较短的候选同时标注“名字较短”。

### 6.4.11 关键流程

**A 从一条请求登记入口**

1. 在无会话的记录上（列表行菜单、预览面板、详情页“相关”栏）点“登记为入口…”。
2. 快捷规则对话框给出候选规则：精确路径（默认选中；请求有接口名规则时是逻辑路径，见 6.4.9）、父路径前缀（如 `/rest/admin/*`，附“前缀入口会放大无会话可达的范围”）、自定义；每个候选显示 24 小时内匹配的无会话请求数。
3. 选中后对话框内直接显示改动、影响预估和预填的备注（“从请求 req_…0c41d2e9 登记”），点“保存为 v8”。
4. 生效状态在对话框内更新到“● 已生效”，然后提供“查看这个路径之后的请求”。

**B 加入绕过**：同 A，候选规则按目录合并（`/assets/*`）；413 的记录额外提示“绕过后该接口不做越权判定，只在确实需要上传大文件时使用”；影响里单列“其中本应拦截 N 个”。

**C 从 Jev 超时或限额记录调整参数**：在 `JEV_TIMEOUT` 记录上点“调整 Jev 超时…”，对话框显示本站点 24 小时耗时分布、当前超时和建议值（p99 × 1.5，向上取整到 500 ms），改值即出影响预估，保存流程同上。`JEV_CALL_LIMIT` 同理，并先展示触发上限的会话或地址、涉及的路径，提示登记入口或绕过可能更合适。

**D 切换到拦截模式**：

```text
┌ 把 juice 切换到拦截模式 ────────────────────────────────────────────────────────────────┐
│ 就绪检查（最近 24 小时）                                                                │
│  ✓ 已观察 6 天 4 小时（自 v3 起）                                                       │
│  ▲ 本应拦截 14 条：Jev 拒绝 11 · 无会话 3                               逐条查看 →      │
│  ▲ 待处理建议 1 条：登记入口 /rest/admin/application-configuration       查看 →         │
│  ✓ Jev 正常（p95 910 ms，超时 0.7%）                                                    │
│  ✓ Jev 不可用时：拒绝                                                                   │
│ 影响：过去 24 小时有 14 个请求会被拦截（返回 401 / 403）                                │
│ □ 我已查看这些请求，确认它们应当被拦截                                                  │
│                                                    取消     切换到拦截模式（生成 v8）    │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

- 检查项只陈述事实，不设硬性门槛；本应拦截数大于 0 时必须勾选确认才能切换。
- 切回观察模式只需确认：“切回观察后不再拦截任何请求，只记录本应拦截”。
- 两个方向都生成新版本并显示生效状态。

**E 回滚**：变更历史里选版本 → 回滚对话框（差异、影响、备注）→ 生成新版本 → 生效状态。

**F 排查“我被拦了”**：用户给出请求 ID（拦截响应体和响应头里都有）→ ⌘K 粘贴 → 详情页一句话解释 → 查看来源和 Jev 上下文 → 如果是误判，用“相关”栏的操作调整配置，或把记录链接发给判定方面的开发者。

**G 对照测试套件结果**：测试套件导出 TSV → 请求追溯“批量对照”→ 只看不一致 → 逐条打开详情。

### 6.5.3 结论与状态

状态色固定，不随主题变化，只用于图标、圆点和浅底色；文字始终用 `--ink`，状态从不只靠颜色表达。

| 含义 | 颜色 | 图标 | 标签样式 |
|---|---|---|---|
| 拦截、严重 | `#d03b3b` | ■ 实心方块 | 状态色 14% 不透明度的底色 + 图标 + 文字 |
| 本应拦截、警告 | `#fab219` | ▲ 三角 | 同上 |
| 未经判定 | `#ec835a` | ◆ 菱形 | 同上 |
| 正常 | `#0ca30c` | ● 圆点 | 只用于状态灯和就绪检查的对勾 |
| 放行 | 不着色 | ○ 空心圆 | 只有文字 |

判定路径的标签是中性描边加图标（6.6.1），不使用状态色，避免“Jev 拒绝”和“拦截”两个维度的颜色互相干扰。名称上也刻意区分：“Jev 通过 / Jev 拒绝”是 Jev 的回答，“放行 / 拦截 / 本应拦截”是网关的动作；观察模式下 Jev 拒绝的请求被转发，结论是“本应拦截”。

状态图形（■ ▲ ◆ ● ○）只表达结论和状态，不挪作他用。步骤条、值的判读提示、列表项目符号使用 ✓ – ! ✕ › · 等中性符号。

### 6.5.4 图表

- 系列颜色按固定顺序取用：1 `#2a78d6` / `#3987e5`（蓝），2 `#eb6834` / `#d95926`（橙），3 `#1baf7a` / `#199e70`（青绿）（浅色 / 深色）。这三色在两种主题下都通过了相邻配对的色盲区分检查；浅色主题下第 3 色与底色对比度只有 2.7:1，所以每张图都有图例和“以表格查看”。
- 同一张图最多 3 个系列，超过的合并（例如判定路径合并为免调用放行、Jev 判定、无会话三组）。系列颜色跟随系列本身，筛选掉一个系列不重新分配颜色。
- 柱宽不超过 24 px，柱顶 4 px 圆角、底部方角；堆叠段之间留 2 px 底色间隙；折线 2 px；网格线 1 px 实线、颜色比底色深一级。
- 单系列图（耗时直方图、置信度直方图、迷你趋势）用系列 1，不加图例，标题说明内容；阈值线（超时、70%）用 1 px `--ink-2` 实线加文字标注。
- Jev 回答的分段条：高 28 px，三段依次为通过选项（系列 1）、不通过选项（系列 2）、UNKNOWN（中性灰 `#a19f98` / `#6b6a65`），段间 2 px 间隙，段内百分比用白字，放不下时不写；图例只列名称。
- 悬停：柱、段各自显示提示框（数值在前、名称在后，系列用短色线标识）；折线用竖向十字线对齐最近的点。提示框内容也能通过键盘焦点和表格视图获得。
- 每张图右上角有“以表格查看”，切换为同样数据的表格。数据刷新时保留旧图并降低不透明度，不闪骨架屏。

### 6.5.5 组件细节

- 表格：紧凑行高 32 px / 舒适 40 px；悬停行用 `--surface-sunken`；选中行左侧 2 px `--accent` 竖条加浅色底。
- 请求 ID、会话标签：等宽字体、`--ink-2`，悬停显示全文和复制按钮；复制后按钮短暂变为“已复制”。
- 不可信文本：值里的控制字符、零宽字符（U+200B–U+200F、U+2060、U+FEFF）、双向控制字符（U+202A–U+202E、U+2066–U+2069）显示为带 `--surface-sunken` 底色的 `\u202e` 形式；超长值在中间省略，可展开。
- 焦点环：2 px `--accent`，偏移 2 px，所有可交互元素可见。
- 动效：120–200 ms 缓出；`prefers-reduced-motion` 时关闭高亮渐隐和面板滑入。

## 6.6 文案与词汇

所有文案集中在 `ui/vocab.ts`（[07.10.5](07-console-architecture.md#7105-共享词汇与解释)），组件不写死文字。代码名在悬停说明里同时显示。

### 6.6.1 判定路径

| 代码名 | 名称 | 图标 | 一句话说明 |
|---|---|---|---|
| `bypass` | 绕过 | → | 命中绕过规则，不判定，直接转发 |
| `fast_allow` | 快速放行 | » | 需核验的值都已核验，没有调用 Jev |
| `cached_allow` | 缓存放行 | ↺ | 复用缓存时长内 Jev 对同一请求的放行 |
| `jev_allow` | Jev 通过 | ✦ | Jev 判定访问有依据、内容无攻击 |
| `jev_deny` | Jev 拒绝 | ✦ | Jev 判定越权或攻击；观察模式下网关的结论是“本应拦截” |
| `jev_unavailable` | Jev 不可用 | ∅ | Jev 超时、出错或答不上来，按站点设置处理；调用达到上限回 429，上下文过大回 403，都不论站点设置 |
| `no_session` | 无会话 | ⊘ | 没有会话凭证，路径也不是入口 |
| `body_not_inspectable` | 请求体不可判定 | ⊟ | 请求体超过 48 KiB 或没有 Content-Length，返回 413 |
| `unknown_site` | 未知站点 | ⊗ | Host 不属于任何站点，返回 404 |

图标一律是文本字形，不用 emoji：emoji 外观因平台而异，彩色的还会和结论的颜色编码混淆；组件根节点设 `font-variant-emoji: text`。■ ▲ ◆ ● ○ 的用法见 6.5.3。

### 6.6.2 结论、上下文、值

| 代码名 | 名称 | 说明 |
|---|---|---|
| `allowed` | 放行 | 转发给源站 |
| `blocked` | 拦截 | 网关返回 401 / 403 / 404 / 413 / 429，没有转发 |
| `would_block` | 本应拦截 | 观察模式下本应拦截，照常转发 |
| `unjudged` | 未经判定 | Jev 不可用且站点设置为放行，没有判定就转发 |
| `session` / `address` | 会话 / 地址 | 上下文来自会话凭证 / 未登录请求按客户端地址 |
| `route` | 路由词 | 路径里的纯字母段，例如集合名 |
| `reference` | 引用 | 像对象引用的值：路径里的 ID，或字段名像 ID、所有者、文件 |
| `input` | 输入 | 其他值，例如表单内容 |
| 惰性（`inert`） | 惰性值 | 不可能是对象引用、也构不成攻击的值，不触发判定 |
| 已见（`seen`） | 见过 | 会话里出现过这个值 |
| 已核验（`verified`） | 已核验 | 以同类对象出现过，快速放行的依据 |

### 6.6.3 Jev 回答

| 问题 | 选项 | 名称 |
|---|---|---|
| `access`：访问有依据吗 | `ALLOW` / `DENY` / `UNKNOWN` | 有依据 / 越权 / 不确定 |
| `attack`：内容是攻击吗 | `BENIGN` / `ATTACK` / `UNKNOWN` | 无攻击 / 攻击 / 不确定 |
| Jev 结论 `conclusion` | `allow` / `deny` / `unknown` | 通过 / 拒绝 / 无法判定（这是 Jev 的回答；网关的动作用 6.6.2 的“放行 / 拦截 / 本应拦截”） |
| 线路 `route` | `gateway` / `direct` / `custom` | 经 AI Gateway / 直连 TypeSafe / 自定义地址 |

### 6.6.4 失败码与其他原因

| 代码 | 简称 | 说明 |
|---|---|---|
| `JEV_TIMEOUT` | 超时 | 超过所用超时（站点设置或默认值）仍未返回 |
| `JEV_RATE_LIMITED` | 服务限流 | 模型服务返回 429 |
| `JEV_TRANSPORT` | 连接失败 | 连接、TLS 或协议错误 |
| `JEV_HTTP_ERROR` | 服务出错 | 模型服务返回非 200 状态 |
| `JEV_RESPONSE_TOO_LARGE` | 响应过大 | 响应超过 64 KiB |
| `JEV_RESPONSE_INVALID` | 响应无效 | 响应结构不符合约定 |
| `JEV_UNKNOWN` | 答不上来 | 最高项是 UNKNOWN 或两项并列 |
| `JEV_STATE_TOO_LARGE` | 上下文过大 | 分批后仍装不下，没有调用，返回 403（正常不出现） |
| `JEV_CALL_LIMIT` | 达到上限 | 会话或地址每分钟调用次数用完，没有调用，返回 429 |
| 响应未观察：`status` / `content_type` / `compressed` / `too_large` / `head` / `not_forwarded` / `would_block` | — | 非 2xx / 类型不是 JSON 或 HTML / 响应被压缩 / 超过 1 MiB / HEAD 请求 / 请求没有转发 / 本应拦截（观察模式，响应不学习） |
| 源站错误：`connect_refused` / `connect_timeout` / `read_timeout` / `tls` / `other` | — | 连接被拒绝 / 连接超时 / 读取超时 / TLS 握手失败 / 其他错误 |

建议类型：`entry_candidate` 登记入口、`bypass_candidate` 加入绕过、`upload_candidate` 上传接口加入绕过、`raise_jev_timeout` 调大 Jev 超时、`raise_call_limit` 调大调用上限、`secret_field_candidate` 追加脱敏词、`hot_would_block` 本应拦截集中的路径、`object_proposals` 对象表待确认、`route_rule_candidate` 可能是统一网关。影响预估类型的名称直接用 [07.9.10](07-console-architecture.md#7910-影响预估) 表中的“含义”列，新增的五类见 6.4.9。

### 6.6.5 错误码文案

| 错误码 | 文案 |
|---|---|
| `UNAUTHENTICATED` | 登录已过期，请重新登录 |
| `INVALID_PASSWORD` | 口令不正确 |
| `LOGIN_RATE_LIMITED` | 尝试次数过多，请 10 分钟后再试 |
| `SITE_NOT_FOUND` | 站点不存在，可能已被删除 |
| `REQUEST_NOT_FOUND` | 找不到这个请求（原因见 6.7.2） |
| `SITE_EXISTS` | 已有同名站点 |
| `SITE_NAME_MISMATCH` | 配置里的站点名与地址中的不一致 |
| `SITE_HOST_TAKEN` | Host {field} 已属于其他站点 |
| `VERSION_CONFLICT` | 配置已被修改（当前 v{current_version}） |
| `ROLLBACK_TARGET_DELETED` | 目标版本是删除操作，不能回滚到它 |
| `SITE_CONFIG_MALFORMED` | 配置不是有效的 JSON 对象，或含有不认识的字段 |
| `SITE_CONFIG_NAME_INVALID` | 站点名只能用小写字母、数字、`-`、`_`，最长 64 个字符 |
| `SITE_CONFIG_HOSTS_INVALID` | Host 不能为空，最多 16 个，每个必须是有效的主机名 |
| `SITE_CONFIG_ORIGIN_INVALID` | 源站地址必须是 `http://主机[:端口]` 或 `https://主机[:端口]`，不带路径 |
| `SITE_CONFIG_SESSION_INVALID` | 会话凭证需要一个有效的 Cookie 名或请求头名 |
| `SITE_CONFIG_ENTRIES_INVALID` | 入口至少一条、最多 64 条；每条以 `/` 开头，`*` 只能在末尾，不能含查询串、`.` 或 `..` 段 |
| `SITE_CONFIG_BYPASS_INVALID` | 绕过最多 64 条，规则格式同入口 |
| `SITE_CONFIG_ADVANCED_INVALID` | 高级判定参数有误：{本地校验指出的具体项，例如“Jev 超时需在 100–30000 ms 之间”} |
| `SITE_CONFIG_OBJECTS_INVALID` | 对象表的配置有误，请检查对象表的各项；功能表的条目被拒绝时，指出具体的一项，例如“对象表第 3 个功能的档位只能是 admin”（见 7.9.18） |
| `INVALID_FILTER` | 筛选条件有误：{field} |
| `WINDOW_TOO_LARGE` | 时间范围最长 7 天 |
| `TOO_MANY_IDS` | 一次最多对照 1000 个请求 ID |
| `BODY_TOO_LARGE` | 内容过大（配置最大 64 KiB，导入文件最大 100 MiB） |
| `INTERNAL` | 控制面出错，请稍后重试；问题持续时查看控制面日志 |

服务端错误码不回显配置值，界面用本地校验补足“具体哪一项”（`lib/site-validate.ts` 与 Rust 规则共用测试用例）。

### 6.6.6 写作规则

- 说清“发生了什么、为什么、能做什么”，不用“非法”“异常”“失败”这类笼统词。
- 数字带单位和千分位：`1,204 次`、`512 ms`、`3.4 KiB`；概率用整数百分比。
- 时间默认本地时区，悬停显示 UTC；相对时间（“3 分钟前”）只用于状态和最近活动。
- 按钮写动作和结果：“保存为 v8”“切换到拦截模式（生成 v8）”“回滚，生成 v9”。

### 6.6.7 接口名与对象表

接口名规则和对象表新增的词。代码名同样在悬停说明里显示；一句话解释里为对象表加的两句见 6.4.4。

| 代码名 | 名称 | 说明 |
|---|---|---|
| `logical_path` | 逻辑路径 | 真实路径加上按规则取到的接口名，判定、入口、绕过、缓存都按它 |
| `api` | 接口名 | 接口名规则取到的名字 |
| `unknown_api` | 未知接口 | 有规则但取不到接口名，不算入口、不走绕过，交给 Jev |
| `object` | 类别 | 值指向的对象类别，例如医生、文档 |
| `slot` | 位置 | 值所在的地方：某个接口的某个字段，或某个路由的某个参数 |
| `pending` | 学习中 | 位置在攒学习证据 |
| `proposed` | 待确认 | 规则或 agent 给出了类别，还没有生效 |
| `confirmed` | 已确认 | 类别已生效 |
| `ambiguous` | 有歧义 | 确认有歧义，永久交给 Jev，学习不再提议 |
| `suspended` | 已暂停 | 已确认的位置出现异常后暂停 |
| `retired` | 已过期 | 长期未出现 |
| `admin` | 管理员声明 | 类别是管理员在对象表里手工声明的 |
| `rule` | 规则 | 类别由规则推出 |
| `agent` | agent | 类别由 agent 给出 |
| `composite` | 复合值 | 一个值里装了几段，按格式拆开，分别核验 |
| `identity_lookup` | 按身份信息查找 | 按手机号、姓名等查对象，不要求展示过，由 Jev 判断是否合理 |

## 6.7 加载、空状态与错误

### 6.7.1 加载

- 首次加载用骨架行（表格）和骨架块（详情头部、卡片）；之后的刷新保留旧内容并降低不透明度，不闪烁。
- 详情页在列表悬停时已预取，通常不出现加载态。
- 统计接口返回 `complete: false` 时，在图表或预估下方写“按前 200 万条记录计算”。

### 6.7.2 空状态与找不到

| 场景 | 内容 |
|---|---|
| 还没有站点 | “还没有站点。新建一个站点，把它的 Host 解析到网关，就能开始观察。”· 新建站点 |
| 对象表为空 | 冷启动面板（6.4.10）：列出最近 24 小时里名字明确的类别，确认后作为学习的起点 · 稍后再说 |
| 时间范围内没有请求 | “最近 24 小时没有请求。”· 查看网关状态 · 扩大到 7 天 |
| 筛选后没有结果 | 列出可以放宽的条件：清除某个条件、扩大时间范围、包含绕过请求 |
| 请求 ID 查不到 | 用 ID 里的时间戳给出原因：生成时间早于保留期（“生成于 10 月 20 日 21:16，已超过 7 天保留期”）；生成时间在未来或早于网关上线（“ID 时间异常，可能不是本系统生成的”）；时间在保留期内但当时有日志缺口（“当时 edge-1 丢失了 37 条记录（队列满）”，条数与原因的算法同日志缺口提示）；以上都不是时提示“可能来自其他环境的网关” |
| 会话查不到 | “这个会话在当前时间范围内没有记录；会话在 24 小时无活动后过期，网关重启后也会清空” |
| 没有 Jev 调用 | “最近 24 小时所有请求都快速放行或命中缓存，没有调用 Jev” |
| 没有调优建议 | “暂时没有建议。观察模式下积累更多请求后再来看” |

### 6.7.3 错误

- 接口错误在所在区域显示错误条：文案（6.6.5）、错误码、重试按钮，不弹窗打断。
- 401 时弹出登录对话框，登录后重放原请求，配置草稿不丢失。
- 控制面不可达时顶部显示“无法连接控制面，正在重试…”，恢复后自动消失并刷新数据。

## 6.8 响应式与可访问性

### 6.8.1 断点

| 宽度 | 布局 |
|---|---|
| ≥ 1200 px | 完整布局：预览面板（400 px）与列表并排 |
| 1024–1199 px | 预览面板改为覆盖式抽屉；详情页右侧“相关”栏移到标签页下方；Jev 查看器的两栏改为单栏 |
| 768–1023 px | 同上；导航折叠为图标栏，时间范围标签隐藏 |
| < 768 px | 只读为主：详情页单栏，顶栏换行；配置编辑仍可用，但提示“建议在桌面端修改配置” |

请求表格按**自身容器宽度**（CSS 容器查询，不是视口宽度）逐级折叠次要列，所以预览面板并排、列表变窄时同样可读：容器宽度 ≤ 1080 px，站点、耗时、请求 ID 移到路径下方的第二行；≤ 900 px，方法并到路径前面，状态也移到第二行；≤ 680 px，Jev 结论也移到第二行，只剩时间、路径、判定、结论四列。第二行用浅色等宽字，信息不丢，只是挪位置。

### 6.8.2 可访问性

- 目标 WCAG 2.2 AA：文字对比度 ≥ 4.5:1（6.5.2 的令牌均满足），图表等图形 ≥ 3:1 或有文字和表格替代。
- 颜色从不单独表达含义：状态有图标和文字，判定路径有图标和文字，图表有图例和表格视图。
- 全部功能可用键盘完成；表格使用 grid 语义和 `aria-selected`；对话框锁定焦点、关闭后焦点回到触发处；Toast 和实时模式的新行用 `aria-live="polite"` 播报。
- 每个页面在浅色、深色两种主题下跑 axe，零违规（[07.10.8](07-console-architecture.md#7108-测试)）。
- 首版只有中文界面，文案集中管理，以后可以加英文。

## 6.9 原型说明

可点击原型在 [design/console-v4](../design/console-v4/README.md)：纯 HTML、CSS、JavaScript，不需要构建，直接打开 `index.html`。它用于确认布局、文案和交互，不是实现代码。

- 数据：`data.js` 按 [07.9](07-console-architecture.md#79-控制面-api) 的接口形状写死两个站点（`emr` 拦截模式、`juice` 观察模式，各带版本历史）、20 条样例记录、3 个会话和系统状态。记录里的 `state`、请求体、响应与网关实际发给 Jev 的形状一致（紧凑 JSON、键按字母序），追溯信息与 `state` 逐项对得上，所以结构化视图的判读提示和来源链接是真实可点的。Jev 指令全文取自网关源码。
- 已画出：状态灯与问题弹层（含配置落后、实例离线、日志缺口）、请求追溯（条件语法、预览面板、实时模式、批量对照）、请求详情全部 5 个标签、Jev 查看器的四种视图和上下文内搜索、会话时间线、站点配置草稿（表单与 YAML 同源）、保存前的影响预估、生效进度模拟、模式切换的就绪检查、快速加规则、调整参数、变更历史与回滚、系统页、命令面板、快捷键、深浅主题。
- 交互：保存、回滚、切换模式、登记入口只改内存中的数据，并模拟“等待网关加载 → 已生效”；保存对话框里可勾选让某个网关卡住，演示琥珀色告警。刷新页面恢复初始数据。
- 路由：用 `#` 地址模拟 6.2.2 的路由，对照表见原型的 README。
- 不包含：真实接口和登录、虚拟滚动、CodeMirror（YAML 用普通文本框）、接入向导的多步表单、导出文件下载、Jev 调用对比视图（P1）、时间范围选择器（原型固定最近 24 小时）；接口名规则、对象表，以及请求追溯和请求详情里新增的接口名与类别（6.4.3 至 6.4.5、6.4.9、6.4.10）。总览的数字是示意，与只有 20 条的样例列表不对应。
- 开发线程以本章为规格、以原型为视觉参考；实现与原型不同的地方在 PR 里说明。
