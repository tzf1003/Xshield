# Xshield v4 控制台可点击原型

用于确认 [06 控制台界面设计](../../docs/06-console-ui.md) 的布局、文案和交互，不是实现代码。数据结构和接口以 [07 技术方案](../../docs/07-console-architecture.md) 为准；原型与 06 不一致时以 06 为准。

## 打开方式

纯 HTML、CSS、JavaScript，不需要构建，也不访问网络：直接用浏览器打开 `index.html`。刷新页面恢复初始数据；登录页接受任意口令。

| 文件 | 内容 |
|---|---|
| `index.html` | 页面框架：左侧导航、顶栏、脚本加载顺序 |
| `styles.css` | 06.5 的颜色令牌（浅色、深色两套）和全部组件样式；请求表格用 CSS 容器查询按自身宽度折叠列 |
| `prompts.js` | Jev 两个问题的指令全文，取自网关 `state.rs` 的 `instructions` 与 `criteria` |
| `data.js` | 按 07.9 接口形状写死的样例数据：2 个站点（各含版本历史）、20 条记录、3 个会话、系统状态、调优建议、证据直方图 |
| `core.js` | 共用工具和外壳逻辑：词汇表、状态灯与弹层、配置生效进度模拟、对话框与弹出层、路由、一句话解释、YAML 解析、差异视图、图表 |
| `pages-trace.js` | 总览、请求追溯（条件语法、预览面板、实时模式、批量对照、导出）、请求详情（5 个标签）、会话列表与时间线 |
| `jev.js` | Jev 调用页，以及详情页里的 Jev 查看器（回答区、结构化 / JSON / 原文 / 指令四种视图、上下文内搜索） |
| `pages-config.js` | 站点列表、新建站点、站点详情（概览、配置、调优建议、变更历史）、草稿与保存、模式切换、快速加规则、调整参数、回滚、系统页 |
| `boot.js` | 站点选择、主题、登录页、快捷键帮助、命令面板、全局按键、启动 |

## 样例数据

- `emr`：拦截模式，自定义了 Jev 超时 3000 ms 和追加脱敏词 `idcard`、`ssn`，版本 v12；`edge-3` 离线，停在 v11。
- `juice`：观察模式 6 天，全部用默认值，版本 v7，有 2 条调优建议。
- 列表里只放了 20 条样例记录，覆盖快速放行、缓存放行、Jev 通过、Jev 拒绝（越权、攻击）、Jev 超时、达到调用上限、无会话、绕过、请求体不可判定。**总览里的数字按生产流量量级编写，与列表不对应**；Jev 调用页上方的分布图同样是示意数据。
- 记录里的 `state`、请求体和响应与网关实际发给 Jev 的形状一致：`state` 是紧凑 JSON（键按字母序），`seen_as` 来源标签和追溯信息逐项对得上，所以结构化视图里的判读提示和来源链接都是真的。其中一条用的是旧版指令，可在“指令”视图里看与当前版本的差异。
- 请求值里的攻击载荷用简短的示意文本代替。
- 时间固定为 2026-11-01 21:17:04（UTC+8）起算；列表里“21:04 前后 edge-1 有 37 条记录未写入”这个缺口对应 `edge-1` 的心跳，缺口期间的请求（例如 21:04:04 的一条）在列表里查不到，请求 ID 查询会给出原因。

## 路由

原型用 `#` 地址模拟 06.2.2 的路由，地址形状与正式控制台相同：

| 原型地址 | 正式路由 | 页面 |
|---|---|---|
| `#/` | `/` | 总览（需要处理、汇总、每小时请求、站点） |
| `#/requests?chip=would&q=…&peek=req_…&scope=all` | `/requests` | 请求追溯（快捷标签、条件语法、预览面板） |
| `#/requests/req_…?tab=jev&jev_view=structured` | `/requests/$requestId` | 请求详情（5 个标签；Jev 上下文有 structured / json / raw / prompt 四种视图） |
| `#/sessions`、`#/sessions/7c1e9a40d2b35f61?only=blocks` | `/sessions`、`/sessions/$label` | 会话列表、时间线 |
| `#/jev` | `/jev` | Jev 调用 |
| `#/sites`、`#/sites/new` | `/sites`、`/sites/new` | 站点列表、新建站点 |
| `#/sites/emr?tab=config&group=advanced`、`…&edit=yaml` | `/sites/$name` | 站点详情：概览、配置（表单分组 / YAML）、调优建议（`tab=insights`）、变更历史（`tab=history&diff=6..7`） |
| `#/system?tab=edges|storage|params|import` | `/system` | 系统（网关、日志存储、运行参数、导入） |

全局参数 `site`（站点范围）只存在于地址里，地址里没有 `site` 就是全部站点；链接和按钮跳转时把当前范围带到目标地址，所以浏览器后退会回到原来页面的范围；顶栏的下拉框读写它（替换当前历史项）。例如 `#/requests?site=juice&chip=would` 只看 juice 的本应拦截。自定义时间窗写成 `range=custom&since=…&until=…`（Unix 毫秒，日志缺口的“查看缺口”用它），和站点一样随链接、按钮带到别的页，点提示条上的“清除”写回 `range=24h`；原型只在请求追溯页读取它，时间范围选择器本身没有做。

在 claude.ai 上预览时，`#/…` 形式的地址只在页面内部生效，不会同步到浏览器地址栏。

## 建议的演示路线

1. **总览**：“需要处理”里有日志缺口、`edge-3` 离线、juice 的就绪检查；点顶栏的网关灯和 Jev 灯看问题列表。
2. **追溯一个请求**：按 ⌘K（Windows 为 Ctrl+K），粘贴 `req_01a19741107477ff9224781077354552`，打开这条本应拦截的请求。读一句话解释；“判定过程”看耗时条和步骤；“请求值”里点来源标签跳到 `GET /rest/basket/1`。
3. **看 Jev 的上下文**：“Jev 上下文”标签先读回答区（两根概率条、结论、网关怎么处理的），再在结构化视图里看每个值有没有佐证；切到 JSON 点键名复制路径，切到原文看逐字节的 `state`，在搜索框里搜 `quantity`，按 `v` 循环四种视图。
4. **请求追溯**：单击行打开右侧预览，`j`/`k` 浏览，回车打开详情；试试条件 `decision:jev_deny conf<0.9`；点“批量对照”用示例粘贴；点“实时”看新行进入；把窗口缩窄到 1100 px 以下看预览变成抽屉、列逐级折叠。
5. **会话时间线**：从详情页的“同一会话”进入，看签发会话的登录请求排在第一行、学到的值逐步增长、日志缺口提示。
6. **改配置**：站点 emr → 配置 → 高级判定参数：改 Jev 超时，看右侧证据直方图和影响预估，点“采用”套用建议值；顶部出现草稿条，点“预估影响并保存”；保存对话框勾选“演示：让 edge-2 不加载新版本”，看生效进度从“等待网关加载”变成琥珀色，状态灯同步变化。
7. **模式切换与调优**：站点 juice → 概览或调优建议里的“切换到拦截模式…”看就绪检查；“调优建议”里“应用…”；“变更历史”里勾选两个版本看差异、“以此回滚…”。
8. **YAML**：配置 → YAML，把 `mode: observe` 改成别的值看逐项报错；把 `hosts` 写成数字、嵌套列表、单个文本（`hosts: a.example.com`）或留空（`hosts:`），会报到那一行；改回来后切回表单，草稿保留。
9. 主题按钮循环跟随系统 / 浅色 / 深色；`?` 看全部快捷键。

## 原型的取舍与限制

- 没有真实接口和登录、虚拟滚动、CodeMirror（YAML 用普通文本框，解析器只支持配置用到的子集）、导出文件下载、接入向导的多步表单（新建站点是一页表单加 YAML 预览）、Jev 调用对比视图（P1）。调优建议和旧版指令差异在 06 里也是 P1，原型已经画出来，方便提前确认。这些按 06 和 07 在开发线程里实现。
- 时间范围固定为最近 24 小时（顶栏的标签不可点），06.3.2 的时间范围选择器没有做。
- 状态灯的问题列表由样例的系统数据现场计算（每 15 秒刷新）；“配置落后”的告警阈值文档写 30 秒，原型缩短为 6 秒，方便演示。
- 实时模式的新行是随机生成的快速放行记录，只在内存里。
- 保存、回滚、切换模式、登记入口、调整参数、新建站点只改内存中的数据，并模拟“等待网关加载 → 已生效”。
