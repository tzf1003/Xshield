# Xshield v4 控制台可点击原型

用于确认 [06 控制台界面设计](../../docs/06-console-ui.md) 的布局、文案和交互，不是实现代码。数据结构和接口以 [07 技术方案](../../docs/07-console-architecture.md) 为准；原型与 06 不一致时以 06 为准。

## 打开方式

纯 HTML、CSS、JavaScript，不需要构建，也不访问网络：直接用浏览器打开 `index.html`。刷新页面恢复初始数据。

| 文件 | 内容 |
|---|---|
| `index.html` | 页面框架：左侧导航、顶栏 |
| `styles.css` | 06.5 的颜色令牌（浅色、深色两套）和组件样式 |
| `data.js` | 按 07.9 接口形状写死的样例数据 |
| `app.js` | 路由、各页面渲染、对话框、命令面板、快捷键 |

## 样例数据

- `emr`：拦截模式，自定义了 Jev 超时 3000 ms 和追加脱敏词 `idcard`、`ssn`。
- `juice`：观察模式 6 天，全部用默认值，有 2 条调优建议。
- 列表里只放了 8 条样例记录，覆盖快速放行、Jev 通过、Jev 拒绝（越权、攻击）、Jev 超时、无会话、绕过。列表计数与总览的汇总数字（按生产流量量级编写）不对应。
- 请求值里的攻击载荷用简短的示意文本代替。

## 路由

原型用 `#` 地址模拟 06.2.2 的路由，地址形状与正式控制台相同：

| 原型地址 | 正式路由 | 页面 |
|---|---|---|
| `#/` | `/` | 总览 |
| `#/requests?chip=would&peek=req_…` | `/requests` | 请求追溯（快捷筛选、预览面板） |
| `#/requests/req_…?tab=jev&jev_view=structured` | `/requests/$requestId` | 请求详情（5 个标签，Jev 上下文 4 种视图） |
| `#/sessions`、`#/sessions/7c1e9a40d2b35f61` | `/sessions`、`/sessions/$label` | 会话列表、时间线 |
| `#/jev` | `/jev` | Jev 调用 |
| `#/sites`、`#/sites/emr?tab=config&group=advanced` | `/sites`、`/sites/$name` | 站点列表、站点详情（概览、配置、调优建议、变更历史） |
| `#/system?tab=storage` | `/system` | 系统（网关、日志存储、运行参数、导入） |

在 claude.ai 上预览时，`#/…` 形式的地址只在页面内部生效，不会同步到浏览器地址栏。

## 建议的演示路线

1. 总览：看“需要处理”，点 juice 的“就绪检查”，体验切换到拦截模式前的检查和勾选确认。
2. 按 ⌘K（Windows 为 Ctrl+K），粘贴 `req_01a19741107477ff9224781077354552`，打开这条本应拦截的请求。
3. 详情页：读一句话解释；看“判定过程”的步骤条；“请求值”里点来源标签跳到 `GET /rest/basket/1`；“Jev 上下文”里切换结构化、JSON、原文、指令。
4. 请求追溯：单击行打开右侧预览，双击进入详情；点“批量对照”粘贴几个请求 ID。
5. 无会话的那条记录（`/rest/admin/application-configuration`）详情页右侧“登记为入口…”，看候选规则、影响和“保存为 v8”后的生效提示。
6. 站点 emr → 配置 → 高级判定参数：默认值和自定义值、最近 24 小时证据、内置脱敏词带锁不可删。
7. 站点 juice → 调优建议 → “应用…”，以及变更历史里的回滚。

## 没有包含的部分

真实接口与登录、虚拟滚动、实时轮询、CodeMirror（YAML 用只读文本代替）、接入向导的四步表单、导出文件下载、Jev 调用对比视图（P1）。这些按 06 和 07 在开发线程里实现。
